## 1. 使用方式

准备 `basic`、`auditor`、`standard`、`admin` 四个启用账号。每项既要检查页面按钮和提示，也要使用浏览器开发者工具或接口客户端直接调用一次对应 REST/RPC；前端隐藏、禁用按钮不能作为权限成立的证据。

测试账号、Token、频道凭据、数据源密码和生产报告不得写入本清单、截图、控制台输出或 Git。

## 2. 角色边界

| 能力 | basic | auditor | standard | admin |
|---|---|---|---|---|
| 登录、个人会话读取、普通状态读取 | 允许 | 允许 | 允许 | 允许 |
| 审计日志 | 拒绝 | 允许 | 拒绝 | 允许 |
| 工作台新建/发送/继续/删除会话 | 拒绝 | 拒绝 | 允许 | 允许 |
| 数据源、GAIOP 服务、告警接入、频道、敏感配置、报告存储 | 只读/页面不提供管理入口 | 只读/页面不提供管理入口 | 只读/页面不提供管理入口 | 管理 |
| 系统升级、用户管理、删除报告 | 拒绝 | 拒绝 | 拒绝 | 管理 |
| 报告列表与下载 | 仅本人正式归档 | 仅本人正式归档 | 仅本人正式归档 | 全部；删除仅管理员 |
| 告警列表与当前页导出 | 允许 | 允许 | 允许 | 允许 |
| Gateway RPC 写操作 | 拒绝 | 拒绝 | 仅显式白名单 | 允许 |

“仅本人正式归档”依赖报告审计 JSON 中的 `sourceUserId`；缺失归属的历史报告不能被非管理员作为可见数据处理。

管理员角色内部不新增角色：初始管理员可管理其他管理员；普通管理员只能管理基础、审计和标准用户。初始管理员不能删除、停用、降级或由他人重置密码。

## 3. 必测直接接口

| 验证项 | 非管理员预期 | 管理员预期 |
|---|---|---|
| `POST/PUT/DELETE /api/data-sources/*` | 403 | 可按校验规则执行 |
| `PUT /api/system-config/alert-ingestion` | 403 | 仅保存启用状态；不回显敏感值 |
| `PUT /api/channels/config` | 403 | 保存掩码外的新凭据，不回显明文 |
| `/api/system-upgrade/*` 的校验、执行、回滚、删除备份 | 403 | 需要确认口令；服务未部署时返回可识别不可用状态 |
| `DELETE /api/reports/:id` | 403 | 删除 DOCX 与配对审计 JSON 并记录审计 |
| `GET /api/reports`、下载、预览 | 只能看到/读取本人 | 可读取全部 |
| `/api/rpc` 的 `config.set`、`logs.tail` | 403 | 依 Gateway 实际能力执行 |
| `/api/rpc` 的 `chat.send` | basic/auditor 403；standard 允许 | 允许 |
| 普通管理员直接创建/提升/编辑/重置/删除管理员 | 不适用 | 403；仅初始管理员允许管理其他管理员 |
| 临时密码登录后访问普通REST或 `/api/rpc` | 所有角色均为403 `PASSWORD_CHANGE_REQUIRED` | 所有角色均为403 `PASSWORD_CHANGE_REQUIRED` |

## 4. 本地自动化基线

- `server/lib/permissions.test.js`：四角色 RPC 决策、敏感读取拒绝、真实 HTTP 中间件 403/200 边界。
- `server/lib/account-security.test.js`：密码规则、大小写不敏感失败计数、5次锁定5分钟、成功清空、幂等SQLite迁移和初始管理员唯一标记。
- `server/routes/auth-users.test.js`：登录锁定、同一外部错误、普通/初始管理员边界、直接REST拒绝、重置后仅允许改密、RPC拒绝、改密后重新登录和审计脱敏。
- `src/utils/password-policy.test.ts`：前端密码规则与服务端规则一致。
- 报告路由测试：正式归档审计文件配对与跨用户隔离。
- 告警、频道、告警接入、系统升级路由测试：输入校验、管理员写入、脱敏和不可用状态。
- 生产构建与 Node 接口测试通过，只说明当前源码可构建；不代表目标服务器服务已启动或外部频道已生效。

## 5. ISO/目标环境追加验收

1. 注入首次管理员与密钥后，逐角色重复第 2、3 节；确认直接访问也不能绕过页面权限。
2. 重启后检查管理员账号、接收器启用状态、报告读取、频道配置掩码和审计日志。
3. 验证 443、SSE、报告目录、SQLite、告警目录、运行时桥接及 `/etc/gaiop/*.env` 的服务账户权限。
4. 以一条新的 NAPM Syslog 事件和一份测试报告完成端到端验收；测试数据按约定清理或保留。
5. 记录通过/失败、ISO 发布编号、两端源码版本和验收人；不得记录凭据。

## 6. 登录与账号安全专项

1. 新建、本人改密和管理员重置分别验证少于8位、缺少英文字母、缺少数字均拒绝，合法密码通过。
2. 使用测试账号连续失败4次、第五次触发锁定；锁定期正确密码仍拒绝，5分钟后自动恢复；成功登录后失败计数清空。
3. 管理员重置测试账号，确认旧Token立即失效；临时密码登录只能进入改密页，直接访问工作台、管理REST和Gateway RPC均拒绝。
4. 改密成功后确认当前Token失效，必须以新密码重新登录。
5. 普通管理员可管理非管理员，但创建/提升/编辑/停用/降级/重置/删除管理员均拒绝；初始管理员可管理其他管理员。
6. 初始管理员的删除、停用、降级、他人重置均拒绝；自身只能正常改密。继续验证不能删除自己和不能移除最后一个有效管理员。
7. SQLite迁移前后比较用户总数、按角色计数、按状态计数和密码哈希摘要，确认迁移只增加安全字段。不得输出密码或哈希内容。
8. 审计中应出现登录失败、锁定、创建、角色状态修改、重置和改密结果，不得出现密码、临时密码、Token或哈希。

本清单只约束验收和证据，不替代部署变更审批、客户侧平台权限或 NAPM 发送端配置。
