# 开发文档完整性检查清单

| 属性 | 内容 |

模块进入“已实现”前，应完成以下检查。

## 产品与页面

- [ ] 目标用户、业务价值和不包含的范围明确。
- [ ] 页面入口、路由、按钮和跳转关系与代码一致。
- [ ] 空状态、加载状态、失败状态和无权限状态明确。
- [ ] 用户可见文案只使用 NetInside / 观枢 GAIOP 品牌。

## 权限与安全

- [ ] 四类角色的查看、新增、修改、删除、执行权限明确。
- [ ] 后端实施强制权限校验，前端禁用不作为安全边界。
- [ ] 密码、Token、API Key、证书私钥不明文返回或写入审计。
- [ ] 文件路径、URL、IP、分页、长度和枚举字段完成服务端校验。

## 数据与接口

- [ ] 数据来源、持久化位置、字段和关联关系明确。
- [ ] 接口请求、响应、错误码和权限与实际代码一致。
- [ ] 写操作是否即时生效、需重启、仅保存策略或会触发外部系统已说明。
- [ ] 部分失败、重复提交、并发修改和恢复方式已说明。

## 测试与交付

- [ ] 前端构建通过。
- [ ] 服务端语法或自动化测试通过。
- [ ] 管理员、标准、审计、基础用户关键权限已验证。
- [ ] 正常、无权限、非法输入、依赖不可用和敏感值场景已验证。
- [ ] 已知限制和下一步清晰，不将规划写成现状。
