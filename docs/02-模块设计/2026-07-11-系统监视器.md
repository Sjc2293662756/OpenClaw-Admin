## 1. 目标与数据含义

展示 GAIOP 管理服务所在主机的 CPU、内存、磁盘、网络、运行时长和基础系统信息。当前本地运行时显示开发电脑资源；部署到麒麟后才显示麒麟服务器资源。它不是 NAPM 监控数据，也不代表远端 NAPM 主机资源。

## 2. 当前功能

- 每 5 秒自动刷新和手动刷新。
- CPU 使用率/核心数、内存使用量、磁盘使用量。
- 网络收发字节和连接数。
- 运行时长、平台、主机名和在线实例数量。
- 依据 CPU、内存、磁盘阈值显示绿色、黄色、红色状态。
- 受管存储水位 one-shot 成功执行后，展示按真实文件系统设备归并的当前状态、使用率、受管标签和最近一次受限告警时间；该提示不提供趋势、预测、模拟清理或清理按钮。

## 3. 权限和边界

基础用户由服务端工作台边界拒绝；标准、审计和管理员可只读查看。页面不执行系统命令、不修改主机，也不调用任何留存清理器。数据仅用于管理诊断，不替代 NAPM 的网络、应用和业务性能分析。

## 4. 异常与验收

- 指标接口失败时保留上次刷新时间并标识数据失效，不显示伪造的 0。
- Windows、麒麟和 Ubuntu 的磁盘/网络统计差异应有兼容处理。
- 页面明确显示所监测主机名，避免被理解成 NAPM 服务器。
- 认证过期应引导重新登录。

### 4.1 受管存储水位（2026-08-17 功能分支基线）

- 独立 one-shot 仅对配置中逐项登记的根目录执行 `stat` 和 `statfs`，不遍历、不统计文件、不读取业务文件内容；目录不存在、无权限或 `statfs` 失败时直接报告失败，不回退父目录或 `/`。
- 使用 `stat.dev` 识别设备并生成不可逆的稳定文件系统标识。同一设备上的多个受管标签合并为一个状态，不同设备分别判断。
- 使用与 Linux `df -P` 一致的 `used = blocks - bfree`、`percent = used / (used + bavail)` 口径；阈值比较采用原始整数交叉乘法，不使用展示值或四舍五入值。
- 状态固定为 `<75% normal`、`75%-<80% warning`、`80%-<90% cleanup_required`、`>=90% emergency`。状态保存在 Admin SQLite，只有首次异常、状态升降/恢复、检测失败/恢复和持续异常提醒周期到达时记录事件。
- 状态接口不返回受管路径。事件仅含策略版本、文件系统标识、状态、使用率、阈值、UTC 时间、检测成功标志和原因码。
- 本批不实现 80% 清理到 70%、90% 应急清理到 80%、业务写入阻断或任意清理器调用。详见[实现基线](../05-部署运维/2026-08-17-GAIOP磁盘水位监测与告警实现基线.md)。

## 5. 后续

### 5.1 已确认的指标口径与待改造项（2026-07-22）

当前 `/api/system/metrics` 在 Admin BFF 进程内采集。237 当前采用 `gaiop-admin.service` 直接运行 Node，因此页面在该环境展示的是 **237 Admin 主机** 的资源；本地开发时则展示开发电脑资源。它不采集浏览器电脑、NAPM 238、远端数据源或其他独立主机的资源。

| 页面项 | 当前实际口径 | 现状与改造要求 |
|---|---|---|
| CPU | `os.cpus()` 返回的自开机累计 CPU 时间计算出的平均忙碌比例 | **待修正**：不能称为 5 秒实时 CPU 使用率；应保存前后两次采样，以差值计算采样周期内使用率 |
| 内存 | BFF 所在运行环境的 `os.totalmem()` / `os.freemem()` | 当前可用；页面需明确监测对象为 Admin 主机 |
| 磁盘 | Windows 为系统盘、Linux 为根目录 `/` 的容量 | 当前可用但范围有限；后续增加 GAIOP 数据、报告、告警和备份目录所在挂载点的容量/可用空间 |
| 网络 RX/TX | 所有非回环网卡自开机以来的累计收发字节 | **待修正**：页面必须标注“累计”；后续按两次采样差值展示实时速率，并明确这不是 GAIOP 专属流量 |
| 运行时间 | Gateway 已连接时优先使用 Gateway health 的 uptime，失败时回退到主机开机时长 | **待拆分**：分别展示服务器开机时长与 Gateway 进程运行时长，不能共用一个模糊标签 |
| 在线实例 | Gateway `system-presence` 返回项数 | 当前仅代表 Gateway 在线实例，不代表操作系统进程数、TCP 连接数或频道在线数 |

此次只完成本地代码与部署模板核对，未连接 237 读取实时数值。后续改造前须先确认数据展示是否应包含 Gateway、Syslog 接收器、报告目录、告警目录及备份目录的组件级健康状态。

### 5.2 后续验收标准

- 连续两次采样间隔明确，CPU 使用率和网络速率可由原始累计值复算。
- 页面显式展示监测对象（例如“237 Admin 主机”），避免与 NAPM、浏览器或数据源混淆。
- 主机开机时长、Gateway 进程运行时长和组件在线状态独立显示。
- 磁盘指标至少覆盖根目录和承载 GAIOP 持久化数据的挂载点；采集失败不能伪造为 0。
- 补充 Windows、麒麟/Ubuntu，以及 Gateway 不可达时的接口和页面验收用例。
