## 1. 范围

告警通知页面只展示 NAPM 经 Syslog 写入 Ubuntu OpenClaw 服务器的告警记录，支持严重级别、类别、关键字筛选与详情查看。

页面严重级别固定为 NAPM 已确认的三档：`轻微`、`重大`、`紧急`。接收器以 Syslog 正文中 `...Alerts severity=<级别>` 的业务级别为准，Admin 仅按这三档展示和筛选，不额外补充“一般”级别，也不依据 Syslog 协议头的 `severity` 推断业务级别。

不提供告警规则编辑、NAPM 写入、Syslog 配置、OpenClaw 配置、服务启停或任意远程命令执行。

## 2. 数据链路

```text
NAPM → rsyslog → GAIOP Syslog 接收器 → 规范化事件持久化
     → 正式接收器接口 → GAIOP-Admin BFF → 管理页面
```

BFF 固定调用受控的接收器查询接口，浏览器不能传入服务器地址、日志路径或内部认证信息。原始 Syslog 只在 GAIOP 接收器内解析，接口不返回原始行、SSH 地址、日志路径、账号、密码或私钥。

### 2.1 当前持久化边界与后续决策

当前 GAIOP 接收器将解析后的脱敏告警逐行追加到受控数据目录的 `alerts.jsonl`，启用状态单独保存在 `receiver-settings.json`；原始 Syslog 仍由 rsyslog 管理，两类文件不能混为同一保留策略。接收器启动时和运行时的可查询窗口均为最近 3000 条，页面/BFF 的最大读取上限也是 3000；该条数是查询窗口，不是“保存 3000 条后自动删除”的保留策略。当前 `alerts.jsonl` 没有自动压缩、按时间清理或容量清理，文件会持续追加。

后续集中规划时再决定告警应保存多久、容量上限、备份与清理任务、去重键/状态流转，以及继续使用受控 JSONL 还是迁移到 SQLite 等事件数据库。未完成该决策前，页面和部署说明不得标注固定保留天数或宣称已自动清理。

## 3. 解析契约

复用 GAIOP `openclaw-napm-syslog-watcher` 已验证的 Syslog 格式：时间、来源、类别、严重级别、告警名称、规则 ID、事件 ID、告警描述、分组、开始/结束时间和指标列表。告警类型权威映射来自 GAIOP `openclaw-napm-alert-query/services/AlertConstants.js`：网络性能、网络异常、应用性能、业务故障、用户体验、安全事件、智能分析。页面筛选固定展示全部七类，即使当前日志中没有对应类型。GAIOP 本次未修改；若其 Syslog 解析契约或分类常量变化，需同步更新 Admin 的解析器与测试。

## 4. 权限与审计

- 标准、审计和管理员可只读查看告警；基础用户受工作台专用边界限制，不能访问告警列表、告警实时事件或流状态。
- 每次成功列表读取写入 Admin 审计，记录返回数量，不记录原始内容或 SSH 配置。
- 页面无写操作，因此没有远端变更权限。

## 5. 运行时配置

部署环境通过 `GAIOP_ALERT_RECEIVER_URL` 和可选的 `GAIOP_ALERT_RECEIVER_TOKEN` 配置 BFF 到正式接收器的内部连接。本地开发默认经 `127.0.0.1:3004` 受控隧道访问 237 回环接收器。

内部认证值不得写入代码、Git、文档、接口响应或审计日志；生产通过部署侧安全存储提供。

## 6. 接口

`GET /api/alerts` 需要登录认证，支持 `severity`、`category`、`keyword`、`startAt`、`endAt`、`page`、`pageSize` 与 `maxResults`。`locateId` 是仅供 `/alerts?focusAlert=` 深链使用的一次性精确业务 ID 参数：它在 BFF 既有受权限保护的 3000 条接收器窗口中定位目标，并按原时间排序返回目标所在页；该值不会传给 Receiver 的普通 `keyword`，也不会改变名称、来源 IP、事件 ID 的关键词契约。`GET /api/alerts/time` 返回 BFF 当前时间，供页面生成和展示筛选区间，避免依赖浏览器电脑时钟。默认范围为最近 1 小时；快捷范围包括今日、昨日、最近 7 日、最近 30 日和本月，点击后立即查询；自定义范围需要在日历面板中确认或取消。BFF 只返回当前页，默认每页 10 条；页面可选择 10/20/50/100 条每页，并可设置 `TOP 50/100/200/500/1000` 或自定义上限（最大 3000）。关键字只检索告警名称、来源 IP 与事件 ID，不检索告警描述。`POST /api/alerts/export` 仅接收当前页六个展示字段，生成带冻结表头和筛选器的 `.xlsx` 文件；复制和导出均不额外读取告警源。BFF 从正式接收器读取最多 3000 条持久化事件，完成映射、时间筛选、TOP 和分页；接收器不可用时明确返回 `503 ALERT_SOURCE_UNAVAILABLE`，不会回退到 SSH 读日志。

## 7. 告警详情分析交接

页面只在 Receiver/BFF 已提供权威 `alertNumber` 时生成 `分析告警 <告警编号>` 指令，并通过一次性路由交接值移交到 GAIOP-Admin 新对话输入框；工作台读取后立即清除该值。编号缺失时明确显示未记录并安全禁用，不从内部业务 ID、`eventId`、开始/结束时间或触发指标猜测、生成或回退编号。

**当前状态（2026-08-29）：未启用。** 已发布 Receiver SSE v1 契约和实际 Receiver 运行文件均未提供 `alertNumber`/`GJ-` 字段，因此当前告警详情会显示“未记录权威告警编号，暂时无法生成分析指令”。这不是 Admin 前端或 BFF 漏映射：BFF 已仅透明投影上游字段。等待 GAIOP 后端正式确定该字段的来源、格式和生命周期后，再由上游解析/持久化并经 `/alerts`、内部 SSE 输出；Admin 只做同名透明适配并补充契约测试，不建立第二套编号映射。

## 8. 2026-07-15 实现补充与当前边界

### 8.1 页面与查询体验

- 默认按 BFF 当前时间查询最近 1 小时，避免浏览器本机时间不准导致查询窗口偏移；筛选器上方始终展示已生效的起止时间。
- 快捷范围包括最近 1 小时、今日、昨日、最近 7 日、最近 30 日和本月；点击非“自定义”范围后立即查询。自定义范围展开双日历与时间输入，必须点击确认才生效，取消则保留原范围。
- 列表是服务端分页而不是一次性加载全部记录：默认每页 10 条，可选 10/20/50/100 条；读取上限为 `TOP 50/100/200/500/1000` 或自定义值，后者最大 3000。搜索范围为告警名称、来源 IP、事件 ID，不检索告警描述。
- 级别、类型筛选始终含有明确的“全部”选项，避免空白选择框。页面提供复制当前页内容和导出当前页 Excel；导出由 BFF 根据当前已展示的脱敏字段生成，不再次读取 Syslog。

### 8.2 正式数据源性能与降级

- BFF 每次从正式接收器读取的事件数受 `TOP` 上限约束，最大 3000；接收器按最新事件优先返回，BFF 保持页面既有排序语义。
- 接收器不可用、返回格式无效或内部连接超时时，BFF 返回 `503 ALERT_SOURCE_UNAVAILABLE`；不读取 SSH 日志作为回退。
- 已验证 237 接收器的健康、持久化查询以及经本地 3004 隧道的 BFF 映射；不代表 NAPM 发送端配置或完整产品部署已经验收。

### 8.3 详情与对话交接

- 详情展示原始触发条件和触发指标；缺失字段显示“未记录”，不根据级别反向伪造条件。
- 页面只在 Receiver/BFF 已提供权威 `alertNumber` 时生成 `分析告警 <告警编号>` 指令；缺少该字段时安全禁用，不从内部 ID、事件 ID、时间窗口或指标推导编号。
- 当前操作名称为“分析告警”。仅在权威 `alertNumber` 存在时进入新的工作台欢迎态并将指令移交给输入框；不写入 URL、审计详情或远端日志。父级工作台读取一次路由交接值后立即移除查询参数，再通过页面属性传给输入区；会话存储仅作兼容回退。
- 创建新会话时会先清空前一个会话的本地消息预览，避免先显示旧会话、数秒后才切换为新会话的割裂体验。
- 从告警详情进入的工作台会话在页头显示单向“返回告警通知”。返回时恢复本次进入前的时间范围、级别、类型、来源关键字、分页、每页条数与 TOP 上限；返回后立即清除这份浏览器会话状态，普通工作台和普通告警页面不会显示该按钮或误用旧筛选。

### 8.4 本地验证与待联调项

已完成：告警解析单元测试、Excel 导出测试、前端构建、真实只读 Syslog 冒烟、告警详情到工作台输入框的浏览器手工验证。

待集中部署阶段：目标环境下的长时间 Syslog 性能、告警数据保留期/容量/清理策略及是否迁移事件数据库、GAIOP Skill 实际执行分析后的结果回写和多用户审计验收。本模块仍不修改 GAIOP 代码；若 GAIOP 的 Syslog 解析或告警分类契约调整，必须同时更新解析器、接口测试和本文件。

## 9. 2026-08-26 实时通知阶段三

Receiver 已提供冻结的 `gaiop.alert-event.v1` 内部 SSE。Admin BFF 以进程级唯一连接消费，不随浏览器数量创建上游连接；首次连接先持久化 `: connected cursor=N` 基线，正常事件完成契约校验、`mapGAIOPAlertEvent()` 投影和浏览器广播后才推进 SQLite 游标。断线使用 `Last-Event-ID` 恢复，网络失败按有上限的退避无限重连。

浏览器继续复用 Bearer 认证的 `GET /api/events`。标准、审计、管理员可收到 `type: alert` 和非敏感 `type: alertStreamState`；基础用户禁止接收。`ALERT_CURSOR_EXPIRED` 会保留未解决断档并要求阶段四刷新 `GET /api/alerts`，历史刷新不等于实时缺失区间已补齐。本阶段没有修改前端 Store、弹窗、告警页面或详情分析交接。

完整接口、SQLite 字段、故障状态和阶段四消费规则见《[GAIOP 告警实时 SSE BFF 接口](../03-接口设计/2026-08-26-GAIOP告警实时SSE-BFF接口.md)》。

## 10. 变更记录

## 11. 2026-08-27 实时通知 UI（阶段五）

- 应用根节点在 Naive UI `NNotificationProvider` 内永久挂载一个通知控制器；它只消费阶段四的同一条浏览器 Bearer SSE 和补偿 Store，路由切换、两个工作台头部以及告警通知抽屉都不会另建连接。
- 标准、审计和管理员在管理工作台与对话工作台均可见同一个告警铃铛；基础用户不渲染该入口，服务端实时和补偿权限继续是最终裁决。
- 仅本次浏览器会话中新到的 `triggered` 实时事件进入弹窗队列，每个 cursor 最多一次。首次无游标基线和补偿事件只进入告警通知；`recovered` 同样只作为告警通知的低干扰状态更新，避免恢复或批量追平造成弹窗风暴。
- 通知最多同时显示 3 条：轻微自动关闭 5 秒，重大 12 秒，紧急保持到用户关闭。通知与消息中心均只显示级别、名称/分类、来源和时间等安全摘要，不展示原始 Syslog 全文或运行诊断。
- 告警通知是全局抽屉，最近内存事件上限 150，支持单条/当前严重级别筛选的全部已读、移除和清空，以及安全简要展开。阅读与提示队列均仅内存；浏览器持久化仍仅保留按账号隔离的游标。单条已读是幂等的，退出和账号切换清空正文与阅读状态。
- “查看详情”统一使用 `/alerts?focusAlert=<业务告警ID>` 深链；URL 不携带正文、时间范围或其他诊断字段。告警页优先在现有列表精确选择，否则通过 BFF 的一次性 `locateId` 精确业务 ID 定位目标所在页；该 ID 不进入名称、来源 IP、事件 ID 的普通关键词语义。不能定位或接口失败时保留当前页面并给出不泄密提示。查询参数保留在 URL，保证前进/后退及同一路由不同 ID 可解释。
- 流状态、`historyRefreshRequired` 和 gap 只在告警通知以轻量状态条呈现；后续 `connected` 不会清除未解决断档，也不会被提示为已经补齐。
