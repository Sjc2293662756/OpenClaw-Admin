## 1. 本期边界（已实现）

本期只实现“当前认证账户”的告警通知偏好，不改变告警记录、Syslog 接收、Receiver 持久化、Admin BFF 上游 SSE、游标推进、历史查询或企业微信等外部频道。

设置入口固定为“系统设置 → 告警通知设置”，不设置“高级配置”，不提供试听、铃声、音量、免打扰、持续时间、自定义级别等能力。标准、审计和管理员（即已具备告警读取权限的账户）可见和使用；基础账户不显示，服务端同样拒绝。

配置项和默认值均为开启，以保持发布前的现有行为：

| 配置项 | 默认值 |
|---|---:|
| 实时告警提醒总开关 | 开启 |
| 声音提醒 | 开启 |
| 轻微/重大/紧急：页面弹窗 | 全部开启 |
| 轻微/重大/紧急：告警通知 | 全部开启 |

页面使用明确的“保存设置”动作：加载、保存中、失败、安全默认及未修改时禁用保存均有可见反馈。总开关关闭时，子项仅视觉禁用，原有选择不会被改写；重新打开总开关后恢复原选择。中英文、明暗主题和窄屏以同一系统设置卡片适配。

## 2. 存储、接口和安全边界（已实现）

正式 Admin SQLite 新增 `alert_notification_preferences`：以 `user_id` 为唯一主键，保存八个布尔开关和 `updated_at`。不存在记录时，服务端返回全部开启的默认值；浏览器不以 localStorage 作为配置权威来源。

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/alerts/preferences` | 标准、审计、管理员 | 仅读取 `req.user.id` 的当前账户设置或默认值 |
| `PUT /api/alerts/preferences` | 标准、审计、管理员 | 只接受完整白名单布尔字段；仅保存 `req.user.id` 的当前账户设置 |

接口不接受或信任客户端 `userId`，字段未知、缺失或非布尔值统一拒绝。保存写入不含敏感值的审计记录。删除账户时，同一 SQLite 事务删除其偏好行；即使异常遗留也不可能通过当前账户接口读取。没有新增角色、跨账户读取/写入能力或第二套权限。

## 3. 实时运行语义（已实现）

1. 登录、刷新或账户切换时，应用先读取当前账户偏好，成功或明确失败后才启动既有的单条浏览器 SSE 消费。这样已关闭提醒的账户不会在正常加载窗口短暂收到错误浮层。
2. 配置读取真实失败时，使用所有开关开启的安全默认值继续消费告警，并给出可见提示；不静默丢失告警。异步请求按账户和代次隔离，退出/切换后的迟到响应不能污染新账户。
3. 总开关关闭时，新事件仍会推进该账户实时游标和去重状态，但不会进入通知抽屉、未读数、浮层或声音；重新开启后不会回放关闭期间的事件。
4. 某级别“告警通知”关闭后，该级别后续 `triggered`、`recovered`、`compensation` 都不进入该账户抽屉或未读数；已有条目不删除。
5. “页面弹窗”是同级“告警通知”的呈现细节：关闭告警通知后，页面弹窗同步显示为关闭并禁用；其原有选择保留，重新开启通知后恢复。某级别页面弹窗关闭时，该级别后续 live `triggered` 不显示浮层，但通知开启时仍进入抽屉。
6. `recovered` 和 `compensation` 永不产生页面弹窗或声音，只在相应“告警通知”开启时进入抽屉。
7. 声音只在总开关、声音开关、同级告警通知和页面弹窗均开启，且 Naive UI 浮层实际创建后播放。三个级别均无可用页面弹窗时，声音开关视觉禁用但保留原选择。现有浮层持续时间、最多三条及阅读详情时清空提示队列的策略保持不变。

这些偏好只影响保存成功以后到达的新事件；不追溯删除当前浏览器抽屉内容。告警历史列表、Receiver/JSONL 持久化、BFF SSE 进程游标、SSE 断档/补偿、历史读取与详情定位不受影响。

## 4. 后续离线收件箱（**规划，未实现**）

下列能力均未在本期实现，当前浏览器仍保留 `recentEvents` 150 条内存上限，阅读和清空状态仍仅限当前浏览器会话：

- 服务端账户告警收件箱；
- 跨浏览器已读/清空同步；
- 离线未读汇总或登录提示；
- 服务端分页的通知历史；
- 解除浏览器 `recentEvents` 150 条上限。

后续推荐数据模型为“告警正文只保存一份”：

```text
既有 Receiver 告警事件（唯一告警正文）
            ↑ alert_id
账户收件箱状态（account_id, alert_id, read_at, cleared_at, created_at ...）
账户配置（account_id, 各通知开关, updated_at）
```

不得为每个账户复制完整告警正文。账户收件箱只记录账户 ID、告警 ID 和已读/清空等账户状态；读取时按 `alert_id` 关联既有告警事件投影。具体 Receiver 告警事件的长期保留、唯一键与可关联性须先完成跨端契约评审，再实施此表。

未来仍应复用 Receiver 在持久化后立即向 Admin BFF 推送的现有 SSE 链路：BFF 将一份事件映射到具有对应账户偏好的收件箱状态，再向在线浏览器推送。该范围不需要 Kafka、RabbitMQ、Redis、轮询、第二条 SSE 或额外 WebSocket。离线统计、分页和跨浏览器状态需另行定义幂等键、清空语义、保留期、索引、审计和迁移/回滚方案后才可开发。
