## 1. 目标

集中展示 NAPM 通过 Syslog 送达的告警，并提供“进入新对话分析”的闭环。告警分析仍使用普通运维对话，不建立另一套聊天系统。

## 2. 目标流程

```text
NAPM → Syslog 接收/解析 → 告警持久化 → 告警通知列表
  ├─ 按频道转发企业微信等外部渠道
  └─ 点击分析 → 对话工作台新会话（携带告警上下文）
```

## 3. 当前实现

只有独立菜单、空状态、进入空白新对话按钮和禁用的告警配置入口。尚无 Syslog 监听、告警表、列表/详情、状态、筛选、转发或上下文传递。

## 4. 未来范围

- 告警 ID、发生时间、来源、级别、对象、摘要、原始内容、状态和更新时间。
- 去重、持久化、列表、筛选、详情、确认状态和分析会话关联。
- Syslog 来源、协议、端口、解析规则、转发频道和测试。
- 告警入库与转发解耦：转发失败不能导致告警丢失。

## 5. 权限建议

所有登录用户按数据范围查看；标准/管理员可发起分析；状态变更权限在开发时确认；接入、解析、转发和端口配置仅管理员。

## 6. 开发前确认与验收

需由 NAPM 提供真实样例后确认 UDP/TCP/TLS、字段格式、唯一标识、级别映射、去重窗口、状态同步和保留期。验收必须覆盖重复告警、乱序、解析失败、转发失败、重启恢复和携带准确上下文创建新对话。
