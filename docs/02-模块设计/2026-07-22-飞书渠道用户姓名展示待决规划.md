# 飞书渠道用户姓名展示待决规划

| 项目 | 内容 |
|---|---|
| 状态 | 待产品与客户管理员确认；未实现、未申请权限、未修改 237 |
| 关联模块 | 飞书频道插件、Gateway 会话元数据、Admin 会话管理与报告来源展示 |
| 触发原因 | 当前 Gateway 飞书会话仅提供 `ou_...` open_id，不提供姓名字段 |

## 1. 已确认事实

2026-07-22 的 237 只读核对表明，飞书会话元数据中有渠道标记和 `displayName=ou_...`，但没有 `senderName`、`userName`、`channelUserName` 或其他昵称字段。Admin 因此只能显示“飞书用户（open_id）”，不得将 ID 伪装成姓名，也不得按同名映射为 GAIOP 本地账户。

完整只读证据见[237 会话身份字段只读核对记录](../05-部署运维/2026-07-22-237会话身份字段只读核对记录.md)。

## 2. 候选方案

仅在消息到达飞书频道插件时，以该消息的 `open_id` 查询飞书通讯录用户基础信息，仅读取姓名；成功后由插件将姓名作为可信 `senderName` 或 `channelUserName` 交给 Gateway，再由 Admin 展示。

不在 Admin 会话列表加载时逐条查询，不复制飞书通讯录到 GAIOP SQLite，不把飞书用户自动绑定为 GAIOP 账户，也不改变平台侧机器人可用范围或 GAIOP 权限决策。

## 3. 前置决策

实施前必须由客户飞书管理员确认：

1. 是否同意为飞书应用授予最小的通讯录基本信息读取权限；
2. 应用的通讯录可见范围是否覆盖需要显示姓名的成员；
3. 是否只展示姓名，且不持久化部门、手机号、邮箱等额外信息；
4. 缓存保留时间、失效方式和“外部用户/无权限/接口失败”时显示 open_id 的降级规则。

## 4. 实施与验收边界（尚未执行）

若后续决定实施，应优先使用飞书插件支持的扩展点或受控适配层，不直接修改运行时 `node_modules`。验收至少覆盖：有权限成员、应用范围外成员、外部用户、接口超时/限流、缓存命中/失效、消息响应时间、会话列表、会话详情和报告来源展示。

任何飞书权限申请、插件改动、安装、升级、重启或 237 验证均须另行授权，并遵循频道插件全量备份、版本固定、跨频道校验和失败整体回滚要求。
