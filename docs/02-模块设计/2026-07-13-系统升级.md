## 1. 当前能力

- 查看升级服务健康、组件版本/状态、最近任务与备份；
- 管理员上传最大 500MB 的 ZIP，执行签名、清单、版本和兼容性校验；
- 校验通过后必须输入 EXECUTE 才能提交异步执行；
- 查看任务进度和步骤；运行中或自动回滚中每 3 秒只读轮询，终态自动停止；
- Skill 备份可输入 ROLLBACK 后创建可跟踪的回滚任务；
- 升级备份可输入 DELETE 后删除。

## 2. 安全与权限

仅管理员可访问。浏览器只访问 Admin BFF，不能得到升级服务地址、内部令牌、升级包路径、备份目录或安装目录。

BFF 以当前管理员身份调用升级服务；每次校验、执行、回滚、删除均记录 BFF 审计，升级服务也记录实际操作者。升级服务在物理删除或回滚前会验证备份目录位于受控 backupRoot 下。

**已确认产品决策（2026-07-20）：** Gateway 核心和频道插件只能由 GAIOP 系统升级模块升级。客户不能通过频道页面、命令行、插件安装器或单独升级包执行安装/升级；即使只升级一个频道插件，也必须在系统升级模块中按完整 Gateway/全部交付频道组合执行暂存、备份、验证和失败整体回滚。该决策定义未来能力边界，不表示当前版本已经具备该升级能力。

## 3. 已知范围

当前人工回滚仅支持 Skill。前端和 OpenClaw 已具有组件专用替换、重载、健康检查和失败自动恢复实现，但尚未完成真实签名升级包的破坏性实机演练，因此页面不开放人工回滚入口。

频道插件同样不属于当前可安全升级范围。2026-07-20 的企业微信故障证明，在共享 npm 运行目录中安装一个频道插件可能影响其他频道的依赖解析。未来系统升级模块处理 Gateway 或频道插件时，必须校验核心/插件兼容矩阵，在版本化临时目录安装，重启后检查全部交付插件和全部已启用频道，并在任一失败时自动恢复旧程序、插件目录和配置。详见[频道插件依赖隔离与升级保护规划](../05-部署运维/2026-07-20-频道插件依赖隔离与升级保护规划.md)。

普通 ZIP 使用磁盘暂存和流式转发；加密大包的遗留解密实现仍可能在解密阶段读取完整内容，ISO 发布前需要继续流式化。

## 4. 237 部署状态

2026-07-27 已完成：

- 独立 `gaiop-upgrade.service` 部署，只监听 `127.0.0.1:18900`；
- 生产环境缺少内部 Token 时拒绝启动；健康接口以外全部鉴权；
- Admin BFF 配置升级服务地址和内部 Token，浏览器仍只访问 BFF；
- 前端升级目标严格限制为 `/opt/gaiop/admin/dist`；
- OpenClaw 重载适配 `netinside` 用户级 `openclaw-gateway.service`；
- 组件目录按 `gaiop`/`netinside` 恢复所有权；
- ZIP 路径穿越、重复条目、组件名称与包布局校验；
- 旧数据库、组件路径和备份路径迁移；
- 受控部署前备份、失败自动回滚、部署后鉴权和健康验证。

完整过程见[237 系统升级模块适配与正式部署记录](../05-部署运维/2026-07-27-237系统升级模块适配与正式部署记录.md)。

## 7. 2026-08-09 数据留存第一批实现

- Admin 的上传中转目录固定为 `data/upgrade-upload-staging`，正常请求仍在 `finally` 即时删除；独立每日 one-shot 仅补偿删除物理修改时间超过 24 小时的严格 UUID v4 `.zip`，不递归进入 `data`，也不处理 `wizard.db`、`.bak` 或未知项。
- Upgrade 的成功任务包仍即时删除；独立 one-shot 补删残留成功包，并按数据库任务归属保留 `failed`、`rolled_back` 包 7 天。活动任务包永不删除，未知包只记录；staging 中仅处理超过 24 小时的严格 UUID v4 `.zip`。
- 回滚备份只有同时“超过 90 天”且“超出该组件最近 5 个经验证可用的物理备份组”时才可删除。共享目录必须全部引用都满足条件；物理目录删除成功后才删除数据库记录。根目录、越界路径、路径穿越与符号链接均拒绝。
- Admin 与 Upgrade 使用各自的 systemd timer、单实例锁、UTC 截止时间、最老优先和单批上限。生产自动删除总开关默认并保持关闭；开启前必须另行完成只读候选核查并取得确认。
