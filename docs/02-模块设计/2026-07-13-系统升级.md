## 1. 目标

未来受控升级 GAIOP 前端、管理服务、智能体服务、Skills 和相关配置。原数据备份源码的存在不等于升级能力，不能直接复用“上传并覆盖”的危险流程。

## 2. 当前实现

只有菜单、占位页和规划说明，没有上传、校验、解压、执行、重启或回滚动作。原数据备份菜单和路由已隐藏，遗留源码暂存。

## 3. 必须先确定的升级协议

- 升级包清单、组件版本、目标平台、依赖和升级顺序。
- SHA-256 及数字签名、公钥来源和密钥轮换。
- 预检：磁盘、权限、版本、服务状态、备份、兼容性。
- 执行：原子切换或明确停机窗口、进度、日志、失败状态。
- 回滚：代码、配置、数据库迁移和 Skills 的回滚边界。
- 麒麟与 Ubuntu、Docker 与原生服务的差异。

## 4. 权限与安全

只有管理员可以检查、上传、执行和回滚；实际文件处理和服务控制应由独立受限升级服务完成。浏览器和普通 Node 进程不直接覆盖生产目录。升级包不能从任意 URL 自动下载执行。

## 5. 验收入口条件

先完成命令行/服务端升级工具、签名验证、失败回滚和测试环境演练，再开放 Web 页面。验收包括篡改包拒绝、版本不兼容拒绝、预检失败无变更、升级成功健康检查和失败可回滚。
