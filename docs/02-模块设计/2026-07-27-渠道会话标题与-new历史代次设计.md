# 渠道会话标题与 `/new` 历史代次设计

| 属性 | 内容 |
|---|---|
| 创建日期 | 2026-07-27 |
| 最后更新 | 2026-07-30 |
| 状态 | 方案记录，整体留待团队决策；未实施 `/new` 历史代次 |
| 优先级 | BFF > GAIOP > OpenClaw |
| 当前产品行为 | 外部频道显示“渠道对话 · 渠道用户”；`/new` 后只展示当前上下文 |

## 1. 已确认事实

企业微信等外部频道使用稳定路由键，例如 `agent:main:wecom:direct:<user>`。执行 `/new` 后：

1. 路由键保持不变；
2. Gateway 生成新的运行时 `sessionId`；
3. 旧转录被保存为重置归档；
4. 标准历史接口通过稳定路由键只返回当前 `sessionId` 的转录。

因此，`/new` 清空模型上下文是正确行为，但当前 Admin 把稳定路由键直接当作唯一历史会话，导致旧代次虽然仍可能存在于运行时归档中，却无法在页面上作为独立历史会话访问。

## 2. 当前决策

本阶段不实现 `/new` 历史代次，不读取或解析 OpenClaw 私有 `.reset` 文件。

已经实施的低风险边界：

- 历史排序只采用真实交互时间，不采用通用 `updatedAt`。
- 外部频道会话稳定显示为“企业微信对话 · 用户”“飞书对话 · 用户”“钉钉对话 · 用户”。
- 当前对话窗口只处理精确匹配已选 `sessionKey` 的实时事件。
- WebChat 继续使用首条用户消息固定标题。

2026-07-30 确认继续保持以下边界：

- “稳定路由与历史代次分离”的正确模型、旧历史内容来源、代次级标题和报告代次关联属于同一个功能包，不拆分为独立小功能提前实施。
- 该功能工作量和运行链路影响均较大，继续放到团队决策后再排期。
- 外部频道服务于运维人员快速使用；渠道身份与其独立 GAIOP 管理员/普通用户账号并存，不自动建立身份映射或合并历史。

## 3. 目标模型

如后续确认实施，应把“稳定收发路由”和“可归档会话代次”分开：

```text
渠道路由 routeKey
├─ generation A：已结束，只读历史
├─ generation B：已结束，只读历史
└─ generation C：当前活动，可继续收发
```

建议新增 BFF 侧 `channel_conversation_generations`：

| 字段 | 说明 |
|---|---|
| `generationId` | Admin 生成的稳定代次标识 |
| `routeKey` | Gateway/频道固定收发路由键 |
| `runtimeSessionId` | 当前代次对应的 Gateway sessionId |
| `sourceChannel` | 企业微信、飞书、钉钉等规范化渠道 |
| `channelUserId/channelUserName` | 渠道身份 |
| `title/titleSource` | 稳定名称或首条消息固定标题 |
| `status` | `active`、`closed`、`archived`、`unavailable` |
| `startedAt/endedAt/lastInteractionAt` | 真实生命周期时间 |
| `historyRef` | 官方历史引用或 BFF 受控归档引用，不保存任意服务器路径 |

历史代次必须只读；继续发送始终使用当前 `routeKey`，不能向旧 `runtimeSessionId` 误发消息。

## 4. 代次检测优先级

1. **Gateway 官方生命周期/API**：优先使用能够返回 routeKey、sessionId 变化和历史读取的官方接口。
2. **BFF 事件与会话列表对账**：在确认事件完整性后，BFF 记录 routeKey 当前 sessionId；检测到 sessionId 变化时关闭上一代。
3. **GAIOP 适配层**：仅当官方契约不足时，由 GAIOP 插件输出稳定的会话代次事件。
4. **OpenClaw 私有重置文件**：仅作迁移/恢复兜底，不作为正式在线契约；文件名和 JSONL 结构可能随升级变化。

不得为该功能修改 OpenClaw 核心，也不得让页面直接读取运行时目录。

## 5. 历史内容来源待确认

需要在实施前从以下方案中选择：

- 官方 API 可以按 runtimeSessionId 读取历史：直接使用，风险最低。
- BFF 从每个渠道会话开始镜像完整消息：不依赖私有文件，但需证明事件无丢失、顺序可靠，并确定容量、加密、保留期和删除规则。
- 受控读取 `.reset` 归档：可恢复现有历史，但与 OpenClaw 内部格式耦合，只适合一次性迁移或应急恢复。

在没有可靠历史内容来源前，不应只创建空的“历史代次”列表项。

## 6. 渠道会话标题后续判断

当前稳定名称不需要模型：

```text
企业微信对话 · yangs
飞书对话 · <用户>
钉钉对话 · <用户>
```

若后续希望与 WebChat 一样使用首条消息标题，建议：

1. 每个 generation 只取第一条真实用户消息；
2. 去除 `/new`、`/status` 等控制命令；
3. 本地截断生成固定标题，不调用模型；
4. 标题异步写入 BFF，不阻塞频道回复；
5. 事件缺少可靠正文时保持稳定渠道名称，不猜测。

调用模型生成语义总结会增加 Token、延迟和不确定性，除非用户另行确认，否则不纳入默认方案。

代次级标题依赖可靠的 generation 生命周期和首条消息归属。在 `/new` 历史代次模型未实施前，不单独把当前稳定渠道会话改造成首条消息标题，避免同一稳定 `routeKey` 多次 `/new` 后标题含义不清。

## 7. 报告来源兼容

当前报告来源的 `sourceSessionId` 仍记录渠道稳定路由键。实施会话代次后，可新增可选 `sourceConversationGenerationId`，使同一企业微信用户多次 `/new` 产生的报告能够精确归属；不得改变现有四项来源字段或把代次信息发送给模型。

## 8. 实施前确认项

- 当前 Gateway 是否提供按 runtimeSessionId 读取历史的官方接口。
- 是否需要迁移现有 `.reset` 历史，还是只从启用功能后开始记录。
- BFF 镜像消息的保留期、容量、删除、导出和访问权限。
- `/new` 代次在历史列表中的名称、时间和只读提示。
- 报告来源是否同步增加 generationId。
- 企业微信之外的飞书、钉钉是否一次性采用同一契约。

以上方向确认前，本设计只作为后续决策入口，不授权部署历史代次功能。
