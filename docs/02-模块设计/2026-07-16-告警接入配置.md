## 1. 定位

本模块只管理 GAIOP 的 Syslog 告警接收目标状态和运行健康。它不承担频道、通知转发、Webhook、企业微信、rsyslog 下载或系统软件安装。

频道凭据和通知路由属于“频道管理”；rsyslog、系统服务、目录权限和防火墙属于 ISO 部署组件；NAPM 的 Syslog 目标地址属于发送端配置。

## 2. 页面与权限

- 仅管理员可读写。
- 固定展示 UDP Syslog、端口 `514`，不提供浏览器编辑监听端口或服务器路径。
- 唯一可保存策略为“启用/停用 Syslog 接收”；策略由接收器写入受控状态目录，接收器服务重启后恢复，不依赖浏览器会话。
- 显示 `pending/applied/failed/unknown`、接收器可达性、最近接收时间和最近错误码。
- 保存和读取均记录不含路径、Token 或原始 Syslog 的管理审计。

## 3. 运行边界

本地开发时，Admin BFF 通过受控 SSH 隧道的 `127.0.0.1:3004` 连接 237 回环接收器；部署时使用受控内部地址。浏览器不会直接连接接收器，连接参数和可选内部认证值不返回浏览器。隧道不可用时，页面显示接收器不可用，不会伪造成功。

当前本地标准链路为：`3002 前端 → 3000 Admin BFF → 3004 本地隧道 → 237:19090 接收器`。原有 `3003 → 237 Gateway` 隧道保持不变；根目录“启动GAIOP本地开发环境.cmd”会在同一条受控 SSH 连接上同时建立两个映射。2026-07-16 已验证接收器健康、启用/停用跨重启恢复和持久化分页查询；页面实际操作仍通过 BFF 权限接口完成。

页面不会安装 rsyslog、创建 systemd 服务、打开防火墙、写 NAPM 配置或管理 Webhook。最终以 237 系统镜像交付这些已验证的部署组件，不维护另一套安装器。

## 4. GAIOP 接收器

`GAIOP-latest/skills/openclaw-napm-syslog-receiver/` 复用既有 Syslog 行解析器，读取 rsyslog 管理的文件，规范化并持久化告警事件；其本地回环接口为：

- `GET /health`：健康、启用状态、最近接收时间和最近错误。
- `PUT /config`：仅接受 `{ enabled: boolean }`，并持久化启用状态供服务重启恢复。
- `GET /alerts`：为后续 Admin 正式查询替换保留的分页读取接口。

它不复用 Watcher 的企业微信推送配置，也不读取 Watcher 的敏感配置文件。

## 5. 237 兼容部署记录

237 已有 rsyslog UDP/514 接收规则，并将兼容格式日志写入受控文件。2026-07-16 新增了独立的用户级 `gaiop-syslog-receiver` 服务，读取同一文件并监听本机回环健康接口；现有 rsyslog 规则、端口、防火墙、Gateway、NAPM 发送端均未改变。

该服务健康检查已通过，且已出现新的 Syslog 接收时间；NAPM 发送端尚未作为本模块联调对象验证。ISO 正式交付以已验证的 237 系统镜像为基线，不再维护独立安装脚本。
