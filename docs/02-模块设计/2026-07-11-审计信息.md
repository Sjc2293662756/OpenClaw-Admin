## 1. 目标

记录谁在什么时间对什么对象执行了什么关键操作，为管理员和审计用户提供可追溯性。审计记录不能保存明文密码、Token、Cookie、私钥或完整敏感配置。

## 2. 当前页面

- SQLite `audit_logs` 持久化，不是纯前端展示。
- 审计信息默认查询“今日”，复用统一时间范围组件，仅提供今日、昨日、最近7日、最近30日和自定义。范围确认后向服务端发起查询，不在浏览器中截取最近 200 条再过滤。
- 可按关键词、用户名、用户角色、事件分类、结果、来源和错误码筛选；关键词仅在 Enter 或“查询”时请求。所有筛选、稳定时间倒序、分页、总数与五项汇总均由 `GET /api/audit-logs` 服务端完成。
- 默认每页20条，可切换20、50、100；筛选、时间范围和页大小变化均回到第一页，翻页重新向服务端查询。请求代次与 `AbortController` 防止旧响应覆盖新条件；失败时保留上次列表并展示错误。
- 当前范围汇总为总记录、成功、失败、已记录拒绝和历史未分类，并满足 `总记录 = 成功 + 失败 + 已记录拒绝 + 历史未分类`。拒绝使用“已记录拒绝”，不将经过限频的匿名401/410描述为公网原始请求总数。
- 点击记录可在只读详情抽屉查看完整结构化字段；空值统一显示“历史未记录”。请求编号可复制，来源地址只表示服务端安全取得的来源地址，不宣称一定是真实客户端 IP。
- 审计用户和管理员可查看；基础和标准用户被服务端拒绝。
- 页面读取不写入“查看审计”记录；不提供编辑、删除或清理操作。

## 3. 第一阶段审计底座

`audit_logs` 采用幂等 SQLite 迁移增加 `category`、`result`、`source`、REST 方法/规范化路径、RPC 方法、稳定错误码、服务器生成请求编号和服务端可确认来源地址。历史记录保留原值，新字段为 `NULL`，不推断回填。

- `result` 仅为 `success`、`failed` 或 `denied`；`source` 仅为 `auth`、`rest`、`rpc` 或 `system`。
- 统一写入器兼容原 `recordAudit(user, action, target, detail)` 调用；请求上下文可自动补充安全的 REST/RPC 元数据，不读取或保存请求体、查询原文或认证材料。
- 已登录 REST 403、RPC 权限拒绝（含管理员未登记方法）、会话/报告/媒体归属隐藏 404 会写入 `denied`。匿名 401 和退役入口 410 使用有界内存限频，避免扫描灌满 SQLite。
- 登录失败、临时锁定和首次改密强制拒绝继续记录为认证事件。普通仪表盘、会话列表、Usage、频道状态、SSE/心跳和 `GET /api/alerts` 刷新不写审计。

## 4. 页面字段与安全投影

主表显示时间、结果、操作用户、用户角色、分类、操作/说明、对象、来源、错误码和详情入口。长操作说明与对象会省略并可查看提示，完整值仅在详情抽屉展示。

详情抽屉显示完整时间、操作用户和用户 ID、当时角色、结果、分类、来源、操作、对象、完整说明、REST 方法、规范化 REST 路径、RPC 方法、错误码、请求编号和来源地址。只返回安全投影：不展示原始 Body、查询参数、Token、密码、Cookie、密钥、RPC 参数、聊天内容、报告正文或敏感配置。

分类映射为 `authentication`（身份认证）、`authorization`（权限校验）、`resource_access`（资源访问）、`operation`（业务操作）、`system`（系统事件）；来源映射为 `auth`（登录认证）、`rest`（REST接口）、`rpc`（Gateway RPC）、`system`（系统）；结果映射为 `success`（成功）、`failed`（失败）、`denied`（拒绝）。历史空字段显示“历史未记录”。

## 5. 异常与安全

- `limit` 范围 1–200；非法值回退默认 100。服务端查询已支持时间、用户名、角色、分类、结果、来源、错误码、关键词、分页、总数和结果汇总。
- 审计读取接口不可通过页面隐藏替代服务端权限。
- 审计数据暂不提供删除接口，避免管理员随意抹除记录。
- 数据库备份、文件权限和时间同步影响审计可信度，应纳入部署要求。

## 6. 验收标准

- 审计/管理员可以查看，其他角色接口返回 403。
- 已覆盖自建写操作成功事件，详情不含敏感值。
- 时间、用户名、角色、对象与实际操作一致，筛选、分页、汇总和详情均来自同一服务器查询范围。
- 快速连续查询不会被旧响应覆盖；接口失败与无记录状态有区分。

## 7. 已知限制

本阶段不包含动态策略、删除/留存、导出、WORM、防篡改签名、SIEM 或复杂数据库聚合限流；Gateway 正常写操作仍沿用既有业务审计，不重写全部业务模块。后续留存、导出和防篡改治理仍未实施。
