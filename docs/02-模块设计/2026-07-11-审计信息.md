## 1. 目标

记录谁在什么时间对什么对象执行了什么关键操作，为管理员和审计用户提供可追溯性。审计记录不能保存明文密码、Token、Cookie、私钥或完整敏感配置。

## 2. 当前页面

- SQLite `audit_logs` 持久化，不是纯前端展示。
- 审计信息默认查询“今日”，复用统一时间范围组件，仅提供今日、昨日、最近7日、最近30日和自定义。范围确认后向服务端发起查询，不在浏览器中截取最近 200 条再过滤。
- 可按关键词、系统用户单选、用户角色、事件分类、结果、来源和错误码筛选；用户下拉复用安全的 `/api/users` 只读清单，包含 `system（系统事件）` 虚拟选项。关键词仅在 Enter 或“查询”时请求，用于操作、对象、说明及已删除/历史用户检索。所有筛选、稳定时间倒序、分页、总数与五项汇总均由 `GET /api/audit-logs` 服务端完成。
- 默认每页20条，可切换10、20、50、100；默认 TOP 200，可选择 TOP 50、100、200、500、1000 或最高3000的自定义TOP。TOP 在服务端执行，真实 `total` 和五项汇总不受TOP截断影响，实际可浏览数为 `min(total, maxResults)`。筛选、时间范围、页大小和TOP变化均回到第一页，翻页重新向服务端查询。
- 当真实结果超过TOP时，页面提示“当前筛选结果超过 TOP N，可提高 TOP 值继续查看。”，底部显示真实匹配数和当前 TOP。请求代次与 `AbortController` 防止旧响应覆盖新条件；失败时保留上次列表并展示错误。
- 当前范围汇总为总记录、成功、失败、已记录拒绝和历史未结构化，并满足 `总记录 = 成功 + 失败 + 已记录拒绝 + 历史未结构化`。历史未结构化提示“早期审计记录没有结果分类字段，不代表操作失败。”；拒绝使用“已记录拒绝”，不将经过限频的匿名401/410描述为公网原始请求总数。
- 点击记录可在只读详情抽屉查看完整结构化字段；空值统一显示“历史未记录”。请求编号可复制，来源地址只表示服务端安全取得的来源地址，不宣称一定是真实客户端 IP。
- 审计用户和管理员可将当前已应用的时间范围与全部筛选条件导出为 Excel；导出覆盖当前 TOP 范围的全部匹配记录，不受当前页限制，最大3000条。导出按钮位于每页/TOP控件附近，使用独立加载状态，不阻塞列表查询；无记录时不可导出。
- 工作簿仅使用既有安全投影：时间、结果、操作用户/ID/角色、分类、操作、说明、对象、来源、REST/RPC字段、错误码、请求编号和来源地址。空值为“历史未记录”，所有以 `=`、`+`、`-`、`@` 开头的文本会进行 Excel 公式注入防护；不包含请求Body、查询原文、Token、Cookie、密码、聊天内容或敏感配置。
- 导出完成后才写入“导出审计信息”结构化审计，成功/失败仅记录时间范围、TOP和实际条数等安全摘要，因此生成文件不会包含本次导出行为自身。
- 审计用户和管理员可查看和导出；基础和标准用户由服务端拒绝。
- 页面读取不写入“查看审计”记录；不提供编辑、删除或清理操作。重置会恢复业务筛选条件与今日范围，并保留每页条数和TOP展示设置。

## 3. 第一阶段审计底座

`audit_logs` 采用幂等 SQLite 迁移增加 `category`、`result`、`source`、REST 方法/规范化路径、RPC 方法、稳定错误码、服务器生成请求编号和服务端可确认来源地址。历史记录保留原值，新字段为 `NULL`，不推断回填。

- `result` 仅为 `success`、`failed` 或 `denied`；`source` 仅为 `auth`、`rest`、`rpc` 或 `system`。
- 统一写入器兼容原 `recordAudit(user, action, target, detail)` 调用；请求上下文可自动补充安全的 REST/RPC 元数据，不读取或保存请求体、查询原文或认证材料。
- 已登录 REST 403、RPC 权限拒绝（含管理员未登记方法）、会话/报告/媒体归属隐藏 404 会写入 `denied`。匿名 401 和退役入口 410 使用有界内存限频，避免扫描灌满 SQLite。
- 登录失败、临时锁定和首次改密强制拒绝继续记录为认证事件。普通仪表盘、会话列表、Usage、频道状态、SSE/心跳和 `GET /api/alerts` 刷新不写审计。

## 4. 页面字段与安全投影

主表显示时间、结果、操作用户、用户角色、分类、操作/说明、对象、来源、错误码和详情入口。空说明、对象、来源和错误码在表格中紧凑显示“—”；空说明只显示操作名称，不产生第二行“历史未记录”。详情抽屉仍以“历史未记录”明确提示缺失字段。长操作说明与对象会省略并可查看提示，完整值仅在详情抽屉展示。

详情抽屉显示完整时间、操作用户和用户 ID、当时角色、结果、分类、来源、操作、对象、完整说明、REST 方法、规范化 REST 路径、RPC 方法、错误码、请求编号和来源地址。只返回安全投影：不展示原始 Body、查询参数、Token、密码、Cookie、密钥、RPC 参数、聊天内容、报告正文或敏感配置。

分类映射为 `authentication`（身份认证）、`authorization`（权限校验）、`resource_access`（资源访问）、`operation`（业务操作）、`system`（系统事件）；来源映射为 `auth`（登录认证）、`rest`（REST接口）、`rpc`（Gateway RPC）、`system`（系统）；结果映射为 `success`（成功）、`failed`（失败）、`denied`（拒绝）。历史空字段显示“历史未记录”。

## 5. 异常与安全

- `limit` 范围 1–200；非法值回退默认 100。`maxResults` 缺失或非法时服务端使用默认 TOP 200，最大3000且不小于当前 `pageSize`；服务端不会信任浏览器截取结果。查询支持时间、用户名、角色、分类、结果、来源、错误码、关键词、分页、真实总数、TOP浏览边界和结果汇总。导出复用同一筛选解析与安全投影，始终在服务端按TOP上限读取，不接受浏览器传入的记录内容。
- 审计读取接口不可通过页面隐藏替代服务端权限。
- 审计数据暂不提供删除接口，避免管理员随意抹除记录。
- 数据库备份、文件权限和时间同步影响审计可信度，应纳入部署要求。

## 6. 验收标准

- 审计/管理员可以查看，其他角色接口返回 403。
- 已覆盖自建写操作成功事件，详情不含敏感值。
- 时间、用户名、角色、对象与实际操作一致，筛选、分页、汇总和详情均来自同一服务器查询范围。
- 快速连续查询不会被旧响应覆盖；接口失败与无记录状态有区分。
- 导出覆盖当前筛选的TOP范围、不受当前页限制、最大3000条；工作簿无敏感字段并防护公式注入，导出成功/失败审计不影响已生成文件内容。

## 7. 已知限制

本阶段不包含动态策略、删除/留存、WORM、防篡改签名、SIEM 或复杂数据库聚合限流；Gateway 正常写操作仍沿用既有业务审计，不重写全部业务模块。后续留存和防篡改治理仍未实施。
