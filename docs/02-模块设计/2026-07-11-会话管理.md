## 1. 目标

提供比对话工作台历史列表更完整的会话检索、详情和管理能力。会话数据权威来源为 GAIOP Gateway。

## 2. 功能

- 总会话、24 小时活跃、消息量和频道数量统计。
- 按智能体、频道、对端、模型、标签搜索，按频道/模型筛选和排序。
- 展示会话标识、消息数、模型、Token 和最后活动时间。
- 查看详情、新建/重置、删除和批量删除；支持新建会话表单。

## 3. 权限

- 基础用户：仅查看、搜索和删除本人有效 WebChat 会话；不能创建、发送、续聊或重置。
- 审计用户：只读查看全部 Gateway 会话，包括外部频道会话；不能删除、发送、续聊或重置。
- 标准用户：查看、搜索、续聊和删除本人有效 WebChat 会话；不能查看他人或外部频道会话。
- 管理员：查看和管理全部会话。

会话列表、详情、历史、使用量、删除和事件流均由 BFF 按同一归属规则裁决；页面按钮只是体验层，直接 RPC 不能绕过。

## 4. 数据与异常

- 列表和详情来自 `sessions.*`、`session.*` 等 Gateway RPC。
- 会话删除、重置必须以 Gateway 返回成功为准并刷新列表。
- 会话不存在、Gateway 离线、方法版本不兼容需要独立错误提示。
- Admin BFF 已对其签发并登记的 `webchat-*` 工作台会话执行用户归属隔离；外部渠道和未登记的历史会话仍没有被归属到普通用户，非管理员不可读取，管理员保留排障查看能力。

## 5. 验收标准

- 搜索、筛选、排序与列表字段一致。
- 只读角色无法通过直接 RPC 删除或重置。
- 单个和批量操作均有确认、成功/失败反馈。
- 对话工作台和会话管理打开同一会话时使用一致标识。

## 6. 会话与附件留存

### 6.1 状态机

- 标准会话严格早于 180 天截止线后才进入 `pending_delete`；恰好 180 天仍保护。
- `delete_after` 固定为自动标记时间加 7 天。管理员可在会话列表看到“7 天待删除”，并在期限内取消；同一活动快照不会被重复标记，发生新的真实活动后才重新计算。
- `long_term` 会话始终恢复为 active，自动标记和最终删除均跳过；取消长期保留后恢复标准 180 天规则。
- 自动标记和最终删除由 `GAIOP_SESSION_RETENTION_AUTO_MARK`、`GAIOP_SESSION_RETENTION_AUTO_DELETE` 两个独立开关控制，默认均为 `false`。

### 6.2 真实活动与归属

自动留存只接受 Gateway 会话上的 `lastInteractionAt`、`lastMessageAt`、`lastUserMessageAt`、`lastAssistantMessageAt`、`lastActivity`，或 BFF 附带同等来源证据的 `conversationLastActivity`。`updatedAt`、`createdAt` 和 `sessionStartedAt` 只可用于兼容展示，不能作为自动删除证据；缺少可靠时间即保护。

WebChat 归属只信任 active `workspace_sessions.owner_user_id`。外部频道只在 Gateway 明确给出单一 source channel 和稳定 peer 时登记为 `channel_peer`；归属不明、默认共享会话、多渠道共享、运行中、流式中、有队列消息、待处理任务或待交付结果的会话全部保护，最终删除前重新核查。

### 6.3 删除和附件

最终删除只调用 Gateway 正式 `sessions.delete`，参数为 `{ key, deleteTranscript: true }`。只有 Gateway 成功响应后，Admin 才在同一 SQLite 事务中软删除 `workspace_sessions` 并更新留存记录；Gateway 失败时会话、Admin 会话记录和附件记录不变。

附件必须先显式登记到 `session_retention_attachments`。`follow_session` 跟随会话状态；`temporary` 的 `expires_at` 不晚于登记基准后 7 天。当前正式 Gateway 集合没有附件或媒体删除 API，也没有证明 `sessions.delete` 会原子删除登记附件的契约，因此：

- 有任何登记附件的会话都阻止最终删除；
- 已到期临时附件只报告 `attachment_delete_api_unavailable`；
- 归属无法证明的附件报告 `attachment_ownership_unverified`；
- 不直接删除媒体文件，也不删除会话 JSONL、索引或转录文件。

项目 memory、智能体 memory、正式报告、Skill/频道配置、设备身份和数据源不进入本留存服务。会话删除成功/失败和策略操作写入 `audit_logs` 的 `session_retention` 类别，不记录聊天正文、附件内容或附件路径；当前核心审计没有自动清理，按不少于 3 年保护。

## 7. 后续

外部频道身份目前不映射为 GAIOP 登录用户，因此不会作为基础/标准用户的“本人会话”；审计只读、管理员管理。后续如引入身份映射，必须独立设计并迁移，不能按名称猜测。附件实际清理必须等 Gateway 提供正式、可验证的附件删除契约后另行实现；在此之前两个生产自动开关不得启用。
