## 1. 目标

明确已从正式产品隐藏但仍保留源码的能力、服务端可达性和清理条件，防止把“菜单不可见”误认为“代码与接口已安全移除”。

## 2. 范围

| 遗留能力 | 正式前端 | 服务端现状 | 处理原则 |
|---|---|---|---|
| Hermes 全部模式 | 无正式路由/菜单 | `/api/hermes*` 入口返回功能停用，仍有大量内部源码 | 保留到兼容确认后分阶段删除 |
| 远程终端 | 无正式路由/菜单 | 遗留管理员接口和进程管理代码仍在 | 不作为 GAIOP 产品能力，优先收缩接口面 |
| 远程桌面 | 无正式路由/菜单 | 遗留管理员接口和会话代码仍在 | 同上 |
| 虚拟公司 | 无正式路由/菜单 | 场景/办公室相关代码部分仍被工坊使用 | 区分工坊所需代码后再清理 |
| 数据备份 | 无正式路由/菜单 | 遗留接口、任务代码和 `backup_records` 表仍在 | 系统升级不得直接复用；先确认无依赖 |
| 全局文件浏览器 | 正式页面已改为报告管理 | `/api/files/*` 返回 410，遗留实现仍可能在入口文件中 | 保留受控报告 API，删除任意文件接口 |
| 旧 Web 环境配置 | 无页面 | `/api/config` 返回 410 | 使用专用配置接口替代 |
| 顶级访问控制/IP 管理 | 无正式入口 | 无正式业务闭环 | 不建设 IP 白名单；会话设置已归系统设置 |

## 3. 安全原则

隐藏菜单不等于删除能力。服务端遗留接口必须是停用、未注册或管理员强制保护状态；不能因为前端没有入口就认为公网不可调用。每次清理前应搜索路由注册、WebSocket、子进程、文件写入和依赖引用。

## 4. 清理顺序

1. 建立路由清单和自动化不可达测试。
2. 确认 GAIOP 正式页面、工坊、报告和系统监视器没有复用遗留服务。
3. 先删除路由注册和启动副作用，再删除服务和前端源码。
4. 移除不再使用的依赖、环境变量、数据库表和构建资源。
5. 执行完整构建、四角色接口回归和生产启动验证。

## 5. 验收标准

- 用户无法通过菜单或已知旧前端路由进入遗留页面。
- Hermes 等明确停用接口返回稳定的 `FEATURE_DISABLED` 或 404。
- 终端、桌面、备份、任意文件写入不应作为正式公网 API 可用。
- 删除源码后入口、对话、智能体管理、报告和系统配置功能不回归。
