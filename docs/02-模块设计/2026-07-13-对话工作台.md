## 1. 目标与非目标

对话工作台是登录后的默认业务空间，用统一对话完成性能分析、告警研判、数据包分析、巡检和报告生成。它不提供普通社交聊天，也不为每种 Skill 建立独立聊天模式。

## 2. 页面结构与流程

- 左侧：品牌、开始新对话、最近 50 条历史会话、用户菜单。
- 右侧：工作空间切换、欢迎态、消息流、工具结果、输入区。
- 点击“开始新对话”只取消当前会话选择；发送第一条消息时由 Admin BFF 创建并登记不可预测的会话标识，避免出现无业务意义的系统消息。
- 历史会话按最后活动时间排序；可打开和二次确认删除。
- 当前会话被删除后返回欢迎态。

## 3. 会话标识与上下文

工作台新会话使用 Admin BFF 签发的独立 `webchat-*` 会话标识。BFF 在 SQLite `workspace_sessions` 中记录 `session_key`、当前登录用户稳定 ID、状态和时间；浏览器不自行构造会话标识，也不传入 Gateway 来源路由字段。外部企业微信等渠道使用可配置的空闲重置；Web 工作台的渠道级超长空闲窗口待 BFF 完整参数适配与真实 Gateway 联调验证。用户可通过历史列表继续旧分析，也可主动开始新对话。

## 4. 权限矩阵

| 操作 | 基础 | 审计 | 标准 | 管理员 |
|---|---:|---:|---:|---:|
| 查看本人已登记的工作台历史 | 是 | 是 | 是 | 是 |
| 打开本人已登记的工作台会话 | 是 | 是 | 是 | 是 |
| 发送、停止生成 | 否 | 否 | 是 | 是 |
| 删除会话 | 否 | 否 | 是 | 是 |
| 查看未登记遗留会话/他人会话 | 否 | 否 | 否 | 管理员排障可见 |

服务端 `/api/rpc` 除角色限制外，还会对工作台会话读、写、删除和列表 RPC 执行归属校验；SSE 中无会话标识或不属于当前用户的 Gateway 事件不会下发。管理员保留既有 Gateway 历史的排障能力。该规则只覆盖 BFF 登记的 Web 工作台会话，不把外部渠道会话伪装为某个 Admin 用户所有。

## 5. 依赖与异常

- 依赖管理服务认证、Gateway WebSocket 和对话 RPC。
- Gateway 未连接时显示服务不可用，不清空输入和历史。
- 流式中断应保留已接收内容并允许重新发送。
- 删除失败不得先从本地永久移除；应刷新实际会话状态。
- 复制、语音播放和工具结果是展示能力，不改变会话数据。

## 6. 验收标准

- 首次进入和点击新对话均显示欢迎态，不显示 `New session started`。
- 标准用户/管理员可以发送；基础/审计用户被前端提示且后端拒绝。
- 打开旧会话能看到历史并继续；外部渠道空闲策略不强制切换 Web 页面。
- 删除需要确认，成功后列表刷新；失败时显示明确原因。
- 不同标准用户不能通过列表、历史、发送、删除或 SSE 取得对方已登记的工作台会话；未登记的旧会话对非管理员返回“不存在或无权访问”。

## 7. 已知限制与后续

WebChat 会话在首条成功的真实用户请求后生成固定标题：去除 Gateway 时间信封与多余空白，忽略 `/status`、`/new` 等控制命令，截取前 24 个字符，超长追加省略号。标题不调用模型，不增加 Token 或延迟，后续消息不会覆盖已有的正常标题。

标题写入同时覆盖 Gateway 的 `chat.send` 和带 `sessionKey` 的 `agent` 兼容回退；无会话标识的普通 `agent` 调用不参与 WebChat 归属或标题处理。历史回填只补空标题或纠正控制命令占位标题，不覆盖已有正常标题，也不猜测历史用户归属。

### 7.1 对话数据面与管理控制面分离（2026-07-27）

WebChat 发给 Gateway/模型的数据面只包含当前 Gateway 接受的标准对话参数，例如 `sessionKey`、`message` 和幂等键。登录用户、报告来源渠道、来源用户、来源会话和活动数据源属于 Admin/GAIOP 管理控制面，不再作为 `chat.send.metadata` 发送给 Gateway，也不会进入模型上下文。

BFF 在转发对话前按 `sessionKey` 写入带 HMAC 的服务器端报告来源快照；GAIOP 报告工具在真正生成报告时按当前会话或工具调用标识读取并验签该快照。会话归属和会话标题仍由 BFF/SQLite 独立维护。Gateway 的 `agent` 兼容回退继续保留，但仅用于 RPC 版本兼容，不承担来源数据传输。

该边界避免管理字段改变 Gateway 参数校验、模型判断或提示词，同时不改变报告文件管理的审计字段、会话权限、标题生成、外部频道链路和 OpenClaw 核心。

### 7.2 多渠道会话展示与实时隔离（2026-07-27）

- 历史会话排序使用最后一次真实用户/助手交互时间。Gateway 的通用 `updatedAt` 可能因交付重试、压缩、缓存统计或后台维护而变化，不得再参与对话排序。
- WebChat 保留首条真实用户请求生成的固定标题；外部频道当前采用稳定名称“渠道对话 · 渠道用户”，例如“企业微信对话 · yangs”。外部频道首条消息标题留待 `/new` 历史代次功能一起确认，不调用模型生成标题。
- 管理员可以在历史列表中看到多个渠道，但当前聊天窗口只接受 `event.sessionKey` 与已选会话键完全相同的实时内容。企业微信事件只能更新企业微信会话，不能进入已打开的 WebChat 或历史默认会话。
- `main`/`agent:main:main` 等旧默认记录显示为“历史默认会话”，不再冒充普通 GAIOP Web Chat；其后台交付重试不能造成置顶。

### 7.3 当前体验优先级确认（2026-07-30）

- 输入区当前展示完整内部会话键，虽然不属于最终产品文案，但现阶段有助于快速定位具体 `sessionKey`、核对 Gateway 历史和排查串话/加载问题，暂时保留；待会话链路和性能稳定后再做最终界面收口。
- 会话管理列表打开慢已经确认是需要优化的问题。
- 从会话管理点击“继续对话”后，工作台长时间不能显示历史消息的问题更加明显，列为当前会话体验的首要性能问题。
- 性能优化必须先分别测量列表 RPC、归属补充、`chat.history`、页面挂载、SSE 订阅和重复刷新耗时；不得以跳过权限过滤、减少历史完整性或重置原会话换取速度。
- 外部频道 `/new` 历史代次、代次级标题和旧历史读取属于同一功能包，继续留待团队决策，不在本轮拆分实施。
- 外部频道是运维人员便捷使用的渠道入口；渠道平台身份与其 GAIOP 管理员/普通用户账号暂时并存，不自动映射或合并。

## 8. 2026-07-15 告警分析交接与 Gateway 兼容修正

告警详情会生成受控的“分析告警数据包”文本。页面使用一次性路由交接值进入工作台，工作台容器立即读取并清除该值，再把文本传给输入区；浏览器会话存储只保留为兼容回退。该方式不会把告警内容长期留在 URL，也不会把它写入审计详情。新建工作台会话时会同步清理旧会话的本地预览，避免旧消息短暂闪现。

由告警详情打开的工作台额外显示单向“返回告警通知”按钮。它仅把用户带回原告警页面，并恢复本次进入前的筛选和分页状态；告警页面不提供回到会话的反向入口，返回状态在使用后即删除。

此前浏览器在 `chat.send` 中附带了单独的 `originatingChannel: webchat`。当前 Gateway 要求一旦使用来源路由字段，就必须提供完整且兼容的来源/目的地组合；单独字段会导致 `originatingTo is required when using originating route fields`，从而阻止正常对话。已移除浏览器侧的该字段及相关半截字段，当前工作台重新使用 Gateway 的默认会话路由。

因此，`resetByChannel.webchat` 仍仅是已保存的管理策略，不能宣称已经对当前 Web 工作台实际生效。后续若恢复渠道级超长空闲窗口，必须由 Admin BFF 根据已验证的 Gateway 版本生成完整来源路由参数、做版本兼容和权限审计；浏览器不得自行传入来源字段。该兼容修正不改变工作台会话归属、用户隔离、告警交接或报告来源信封的边界。
