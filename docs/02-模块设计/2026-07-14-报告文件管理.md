# 报告文件管理模块设计

| 属性 | 内容 |
|---|---|
| 创建日期 | 2026-07-14 |
| 最后更新 | 2026-07-16 |
| 状态 | Admin 本地过渡导入版本可用；正式共享目录、可信来源归属与真实 Gateway/Web 联调待验证 |

## 1. 目标与非目标

只管理 GAIOP 报告生成 Skill 产生的受控报告。不得浏览、上传、编辑、重命名或删除任意服务器文件。旧 `/api/files/*` 已返回 `410 LEGACY_FILE_BROWSER_DISABLED`。

## 2. 存储和自动登记

- 报告根目录默认 `GAIOP-Admin/data/reports`，生产由 `GAIOP_REPORTS_DIR` 指定。
- 管理服务与报告 Skill 必须使用同一绝对目录或容器共享卷。
- Skill 写入报告文件和配套审计 JSON。
- 列表读取时扫描根目录中的 JSON，只接受带 `reportId` 和安全文件名的记录，并写入 `report_files` 表。
- 不扫描其他目录，不接受路径片段或符号式越界路径。

## 3. 功能与权限

| 操作 | 基础 | 审计 | 标准 | 管理员 |
|---|---:|---:|---:|---:|
| 列表、下载 | 是 | 是 | 是 | 是 |
| 删除报告及配套 JSON | 否 | 否 | 否 | 是 |

当前页面不提供在线预览，只保留下载；Admin BFF 的受控预览接口因兼容原因暂不移除，但不作为页面功能入口。删除成功后同时删除文件、审计 JSON 和元数据，并记录操作审计。

## 4. 数据字段

报告元数据包括 ID、原始名称、存储名称、类型、来源会话、来源用户、数据源、MIME、大小、状态、创建和更新时间。浏览器不获得服务器真实路径和存储名称。

### 4.1 来源字段与筛选（2026-07-15）

- 报告审计 JSON、`report_files` 与 `GET /api/reports` 使用同一组跨目录字段：`sourceUserId`、`sourceSessionId`、`dataSourceId`。
- Admin 列表展示来源用户、来源会话和来源数据源；任一字段缺失时固定显示“未记录”，不根据文件名、当前登录用户或其它猜测补造来源。
- `GET /api/reports` 仍支持三个可组合的精确筛选参数：`sourceUserId`、`sourceSessionId`、`dataSourceId`。当前报告页暂不展示这三个输入框，页面筛选只保留报告类型和生成时间，避免把未记录的历史来源字段做成无效操作入口。
- GAIOP 报告导出从 Gateway 注入的会话键记录 `sourceSessionId`；报告 Skill 在没有显式历史来源时，从当前激活运行时数据源记录 `dataSourceId`。历史报告或缺少上下文的导出仍可为空。

`sourceUserId` 不能从 Gateway 上下文的 `accountId` 推断，后者仅是通道账号语义。对 Web `chat.send`，Admin BFF 可在开启 `GAIOP_REPORT_PROVENANCE_ENABLED=true` 且配置至少 32 字符 `GAIOP_REPORT_PROVENANCE_SIGNING_KEY` 时，附加含用户 ID、会话 ID、签发时间的 HMAC 签名来源信封；GAIOP 仅在签名、时效和当前会话均验证通过时写入 `sourceUserId/sourceSessionId`。浏览器不能提交或替换该来源用户字段，签名及密钥不得写入日志、审计或接口响应。

Gateway 是否将该元数据原样传到插件上下文尚未完成真实 Gateway/Web 联调验证，因此该开关默认关闭；关闭或验证失败时不会伪造 `sourceUserId`。

## 5. 异常与安全

- 元数据不存在：`REPORT_NOT_FOUND`。
- 实体文件缺失：标记 `missing` 并返回 `REPORT_FILE_MISSING`。
- 不支持预览：`415 REPORT_PREVIEW_UNSUPPORTED`。
- 删除或流读取失败应保留可诊断错误，不泄露路径。
- 文件名使用 `basename` 和根目录解析双重限制，目录权限只授予服务账号。

## 6. 验收标准

- 任意 `../`、绝对路径或非登记文件不能访问。
- 合法报告可列表、下载；非管理员不能删除。
- 管理员可读取全部报告；非管理员只能列表和下载 `sourceUserId` 与本人登录 ID 完全相同的报告。来源用户缺失的旧报告只对管理员可见，避免将历史未知归属错误授权给任意用户。
- 下载复用读取范围校验并记录操作审计，不能用报告 ID 绕过列表隔离。
- 删除同时移除配套元数据并写审计。
- 管理服务和 Skill 指向同目录时，新报告能自动登记。

### 6.1 真实联调前置检查（2026-07-15）

- 本机检测到 GAIOP-Admin 服务在 `3000` 端口运行；在用户明确提供测试后台凭据后已成功登录工作台，未尝试读取账号、密码、Token 或进程环境来绕过认证。
- 本地 Admin `.env` 尚未配置报告来源签名开关和密钥，GAIOP 工作区未发现本地 `.env`；因此当前未向 Gateway 发送来源信封。
- 已通过受控 SSH 隧道只读确认测试服务器的 Docker 与原生 Gateway 均在运行，本地映射 `8080/8081` 的 WebSocket 握手均成功；服务器 Admin 测试端口也在响应。隧道不暴露服务器端口到公网。
- 登录后已确认报告管理页的来源三字段和筛选控件可用；当前本地数据库没有已登记报告。
- 默认 Docker Gateway 当前加载的 GAIOP 插件未包含报告来源签名处理；原生 Gateway 的服务账户和工作目录已确认，但旧的预期插件位置不存在实际插件文件。两套运行时均尚未验证可消费来源信封，不能宣称真实链路已生效。
- 真实报告联调仍需要明确的签名配置来源、目标 Gateway 部署匹配的 GAIOP 插件代码及 metadata 透传验证。后续经授权完成部署和配置后，必须完成 Web 生成报告、审计 JSON 入库、跨用户拒绝下载三项验收，才可开启签名配置。

## 7. 已知限制

来源会话和数据源已进入报告调用链；Web 报告来源用户的签名传递、GAIOP 验签和 Admin 读取隔离已实现，但必须在目标 Gateway 版本确认元数据透传后才可开启并宣称端到端生效。它只隔离报告文件，不代表 Gateway 会话历史已经完成所有者隔离。保留期、容量和自动清理未实现。

## 8. OpenClaw 历史报告过渡导入（2026-07-16）

为先完成 Admin 侧报告管理页面，当前只从默认 Docker OpenClaw 实例**一次性只读复制**已有的报告文件及配套审计 JSON 到 `GAIOP-Admin/data/reports`。未复制原生实例，避免重复报告混入；未修改 OpenClaw、NAPM、GAIOP 或服务器配置。

- 这不是远程目录挂载、定时同步或实时读取。后续新生成的报告不会自动出现在本地，除非再次进行受控导入，或完成正式后端适配。
- 已导入历史审计实际只包含报告标识、文件名/文件引用、报告类型和生成时间；没有 `sourceUserId`、`sourceSessionId`、`dataSourceId`。页面必须显示“未记录”，不得由文件名、当前登录用户或其它上下文推断。
- 已只读核对 GAIOP `ReportGenerationService` 的正式 `reportType` 白名单。报告类型下拉始终展示：快速（`quick_report`）、故障分析（`diagnostic_report`）、对比（`comparative_report`）、运维（`operation_report`）、巡检（`inspection_report`）、综述（`summary_report`）；不再仅依据当前已导入文件动态生成。故障分析的 B/S 故障、页面性能、C/S 故障是 `diagnostic_report` 下的不同模板，不是额外报告类型。历史或未来出现的未知类型仍以“历史类型”保留为可筛选项，避免隐藏既有记录。
- 报告页采用与告警通知一致的时间选择器：默认最近 30 日，支持最近 1 小时、今日、昨日、最近 7 日、最近 30 日、本月和确认后生效的自定义时间；同时提供报告类型、每页 10/20/50/100 条、TOP 50/100/200/500/1000 或自定义最高 3000 条。
- 过渡阶段为避免改动 BFF，时间、类型、TOP 与分页由页面在已获取的受控报告元数据中执行；正式报告量增长后，应将等价筛选与分页参数下沉到 `GET /api/reports`，保持页面交互不变。
- 当前页面仅提供下载和管理员删除；过渡导入阶段的删除只影响 `GAIOP-Admin/data/reports` 中的本地副本及其元数据，不会删除远端原始文件。

### 8.1 后续正式对接清单

1. 在 GAIOP 部署配置中指定正式共享报告根目录（`GAIOP_REPORTS_DIR`），使报告 Skill 和 Admin BFF 读取同一受控目录或容器共享卷。
2. 由 GAIOP 报告生成链在审计 JSON 中写入已验证的 `sourceUserId`、`sourceSessionId`、`dataSourceId`，再由 Admin 扫描入库并执行读取隔离。
3. 通过一次真实 Web/Gateway 生成报告完成端到端验收：报告落盘、审计 JSON、Admin 列表展示、所属用户读取、非所属用户拒绝、管理员删除审计。
4. 正式链路验证后停止使用一次性导入，避免本地过渡副本与共享目录产生重复或不一致。
