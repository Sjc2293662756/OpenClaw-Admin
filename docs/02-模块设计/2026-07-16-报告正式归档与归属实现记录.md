# 报告正式归档与归属实现记录

| 项目 | 状态 |
|---|---|
| 日期 | 2026-07-16 |
| 状态 | 本地双端代码与受控端到端验证完成，待部署联调 |

## 已完成

- GAIOP 新生成报告按 `<GAIOP_REPORTS_DIR>/<sourceUserId 或 _unattributed>/<reportType>/` 成对写入报告实体和审计 JSON。
- 审计 JSON 使用 `relativeFilePath`、`relativeAuditPath`，不把绝对服务器路径作为 Admin 输入字段。
- Admin BFF 在受控报告根目录内递归扫描审计 JSON，保存、下载、预览和删除都使用同一相对路径边界校验；历史根目录导入副本保持兼容。
- 系统设置页面只展示报告存储的部署状态，不向浏览器、接口响应或审计记录回显服务器报告根目录。
- Web `chat.send` 的来源信封已升级为 v2：BFF 从当前激活的数据源读取 `dataSourceId` 后与用户、会话、签发时间一起签名；GAIOP 插件支持 v2 验签，并保留 v1 兼容读取。
- 不可信、缺失或验证失败的用户归属不会被猜测；报告写入 `_unattributed`，由 Admin 的既有权限规则限制为管理员可见。

## 仍待部署联调

- 在 Admin BFF、Gateway 和 GAIOP 部署侧配置同一签名密钥，并显式开启来源信封；密钥不得写入 Git、日志、接口或文档。
- 将 Admin BFF 与 GAIOP Report Skill 指向同一个 `GAIOP_REPORTS_DIR` 共享目录，并以服务账户最小权限运行。
- 在真实 Web/Gateway 链路验证 metadata 透传、生成落盘、Admin 自动入库、所属用户可下载、其他用户被拒绝、管理员删除成对文件。

## 2026-07-17 本地契约收口

- GAIOP Report Skill 现优先读取 `GAIOP_REPORTS_DIR` 作为正式共享根目录；旧 `NAPM_REPORT_OUTPUT_DIR` 仅保留为历史部署兼容别名。Admin BFF 与 Skill 在 ISO 部署时必须显式配置为同一个受控目录或同一个挂载卷。
- Admin BFF 对嵌套正式归档额外校验 `relativeAuditPath` 必须与扫描到的审计 JSON 相同，避免一个审计 JSON 声明或替换另一个受控目录中的报告配对关系；根目录历史导入副本仍按兼容规则处理。
- 新增本地自动化验证：正式报告实体与审计 JSON 成对入库、伪造的审计路径不会登记、页面返回不含服务器路径。该验证不代表 237 已部署或已切换数据源。
- 历史导入报告不迁移归属，不得据文件名、账号名或当前用户补写来源字段。

## 2026-07-18 端到端本地收口

- GAIOP 与 Admin 对目录分段采用同一安全归一化规则：目录仅是受控存储定位，数据库仍保存原始可信 `sourceUserId` 作为读取隔离依据；含特殊字符的合法来源 ID 不会因目录名归一化而漏入库。
- Admin 对正式嵌套归档同时校验用户目录与报告类型目录都与审计 JSON 一致；目录或审计字段不匹配的文件不会登记。
- GAIOP 的环境模板补齐共享报告目录和来源信封开关/密钥占位符，均为空值或安全默认值，不包含真实路径或密钥。
- 新增不依赖报告渲染库的正式归档契约测试，覆盖可信归属字段、目录归一化与 `_unattributed` 回退；真实 Gateway metadata 透传和共享卷仍只能在部署阶段验收。
