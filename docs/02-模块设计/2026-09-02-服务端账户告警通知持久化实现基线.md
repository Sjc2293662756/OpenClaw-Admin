# 服务端账户告警通知持久化实现基线

| 属性 | 内容 |
|---|---|
| 日期 | 2026-09-02 |
| 状态 | 隔离工作树已实现并完成本地自动化验证；未提交、未推送、未部署、未完成生产验收 |
| 页面名称 | 告警通知 |
| 原始告警权威来源 | GAIOP Syslog Receiver |
| 通知展示副本与账户状态 | GAIOP-Admin `wizard.db` |

## 1. 架构结论

本实现采用“三表稳定版”，不增加 Kafka、RabbitMQ、Redis、轮询、WebSocket、第二条 SSE 或独立服务：

```text
NAPM -> Syslog -> Receiver 持久化 -> Receiver SSE
  -> Admin 单一上游消费者
  -> 同一 SQLite 事务保存共享安全投影、账户状态和 BFF 游标
  -> 现有浏览器 SSE 只向在线收件人发送实时事件
```

Admin 保存的事件正文只是告警通知展示副本。Receiver 仍是原始告警、历史查询和详情定位的权威来源；Admin 不保存原始 Syslog 正文，也不改变告警记录、企业微信等外部频道。

相较“只存事件 ID、展示时回查 Receiver”，安全投影更适合本项目：通知分页不依赖 Receiver 在线，读取一次 SQLite 即可完成，Receiver 保留期短于通知保留期时仍可显示安全摘要。代价是一份受控的展示副本，但不会按账户重复正文。

## 2. 三张表

### `alert_notification_events`

每个 Receiver 流事件一行，保存安全投影。`UNIQUE(receiver_generation, stream_sequence)` 是接收幂等键；同一业务告警的 `triggered` 和 `recovered` 只要流序号不同，就分别保留。

主要字段：`event_id`、`receiver_generation`、`stream_sequence`、`alert_id`、`action`、`severity`、`occurred_at`、`received_at`、`safe_payload_json`、`created_at`。

### `account_alert_notifications`

每个账户与事件一行，主键为 `(user_id, event_id)`。只保存账户关系和状态：`read_at`、`cleared_at`、`created_offline`、`created_at`；不复制安全投影正文。

### `account_alert_notification_state`

每个账户一行，保存离线汇总水位和领取租约：`summary_confirmed_through`、`summary_claimed_through`、`claim_token`、`claim_expires_at`、`updated_at`。

现有 `alert_notification_preferences` 继续保存账户总开关、声音和三级页面弹窗/告警通知设置。现有 `alert_stream_runtime` 新增 `receiver_generation`，Receiver 序号重置时 generation 加一，避免新序号与旧事件冲突。

## 3. 写入和故障语义

合法 Receiver 事件严格执行：

1. 校验 `gaiop.alert-event.v1`、序号、动作、严重级别和业务告警 ID。
2. 读取最新有效模块权限与当前账户通知设置，计算收件账户。
3. 在一个同步 SQLite 事务中插入共享事件、账户状态并推进 BFF 游标。
4. 事务提交后，只向事件发生时在线的收件账户广播实时 `alert`。

数据库写入失败时整个事务回滚且游标不推进，Receiver 会按原序号重投。浏览器广播失败不回滚数据库，也不阻塞上游消费；用户仍可从服务端通知列表读取该事件。

`triggered/recovered` 是业务动作；补偿只表示 Receiver 到 BFF 的传输过程，不再成为通知业务类型。浏览器本地游标和 `/api/alerts/changes` 不再承担账户通知历史。

## 4. 收件人与权限

- 只处理状态为 active、最新有效模块权限含 `alerts.notifications=true` 的账户。
- 总开关关闭时不生成新账户通知；重新开启不追溯补发。
- 对应严重级别的“告警通知”关闭时不生成该级账户通知。
- 页面弹窗和声音只控制在线实时提示，不影响已经生成的服务端通知。
- 权限撤销后，新事件不再生成该账户通知，通知 REST 与告警 SSE 也由有效模块权限中间件拒绝。
- 删除账户时，在现有用户删除事务内清理偏好、账户通知和汇总状态，不删除共享事件。

清空仅设置当前账户行的 `cleared_at`。它不会删除 Receiver 告警、共享事件或其他账户数据。

## 5. 在线、离线与多设备

Admin 用现有已认证 `/api/events` 连接表判断账户在线：

- 任意未关闭的连接在该 Receiver 事件接收时间之前已经建立，账户在线。
- 最后一个连接断开后，后续事件标为离线产生。
- 多标签页和多设备只要有一条有效连接，账户仍在线。
- 异常断线通过 response 关闭状态和 close 回调移除；BFF 重启后内存连接表为空，直到浏览器重新认证连接。

浏览器使用独立 `sseConnected` 生命周期事件领取汇总，不再把 Gateway 是否连接误当成浏览器 SSE 是否在线。Receiver 与 Admin 主机必须保持时间同步；时间明显漂移会影响跨重启补偿事件的在线边界判断。

## 6. 离线汇总

下次登录建立第一条已认证 SSE 后，浏览器调用汇总领取接口。服务端在一个事务中按 `summary_confirmed_through < event_id <= 当前离线最大 event_id` 汇总未清空的离线通知，返回总数及轻微、重大、紧急数量。

领取使用 30 秒租约。同一账户多个标签页同时登录时，只有一个标签页获得 `claim_token`；租约过期但未确认时可以重新领取。显示后使用该令牌确认水位：

- 确认汇总不修改任何通知的 `read_at`。
- 已确认的汇总刷新后不重复出现。
- 没有新离线通知时不显示。
- 新表首次上线为空，不回填旧浏览器内存通知，因此不会产生升级前历史汇总。
- 离线事件不逐条弹窗，也不集中播放声音。

当前本地实现的交互默认值是：包含紧急告警时保持到手动关闭；其他汇总 12 秒自动关闭。该值在生产发布前仍可按产品确认调整。

## 7. 通知列表与实时合并

告警通知抽屉改为服务端键集分页，默认每页 30 条，最大 100 条；使用 `beforeId` 加载更多，不再有浏览器 150 条历史上限。支持：

- 全部/未读；
- 轻微/重大/紧急；
- 服务端真实总数和未读数；
- 单条已读、当前筛选全部已读；
- 单条清空、当前筛选清空；
- 只查看本次离线汇总的事件区间。

实时事件以服务端 `notificationId` 去重并插入顶部。分页响应带 `snapshotThroughId`，请求期间新到的 SSE 事件与快照合并，避免重复或覆盖用户已看到的新事件。已读或清空后，现有同一条 SSE 发送账户级状态失效通知，其他浏览器重新读取当前页。

## 8. 索引与容量

当前索引覆盖：

- 共享事件：发生时间、严重级别、业务告警 ID；
- 账户通知：未清空列表、未读列表、离线事件区间；
- 两张状态表均由主键覆盖账户读取。

建议通知在线保留 31 天，但本批不实现也不启用自动清理。容量按“事件数 + 实际收件账户关系数”增长，不按浏览器数量增长。以安全投影平均约 3 KB、每个账户关系及索引约 0.2 KB 粗估：

| 日事件量 | 31 天事件数 | 10 个收件账户关系数 | 粗略空间级别 |
|---:|---:|---:|---:|
| 100 | 3,100 | 31,000 | 数十 MB |
| 1,000 | 31,000 | 310,000 | 数百 MB |
| 10,000 | 310,000 | 3,100,000 | 约 1.5-2.5 GB，需专项压测和清理 |

实际容量受投影正文、SQLite 页和索引影响，必须以上线后的日增量监测为准，不能承诺无限保存。

未来经单独确认启用清理时，顺序必须是：先删除到期 `account_alert_notifications`，再删除没有任何账户引用的到期 `alert_notification_events`，最后校正低于最小保留事件的汇总水位。不得先删共享事件留下账户孤儿，也不得触碰 Receiver 历史。

## 9. 升级、备份与回滚

- 迁移使用 `CREATE TABLE/INDEX IF NOT EXISTS`，并为旧 `alert_stream_runtime` 幂等增加 generation 列。
- 不回填历史通知，不读取 localStorage 旧正文或旧已读状态。
- 旧版代码可忽略新增表和 generation 列，因此代码回滚时保留新表，不执行破坏性降级迁移。
- 发布前必须使用现有 Admin SQLite online backup 机制备份完整 `wizard.db`；该快照自然覆盖新表。
- 生产恢复只能按既有整库恢复流程，在停服务、校验 manifest、SHA-256 和 `integrity_check` 后受控执行；不能用复制运行中 WAL 主库或手工删表代替。
- 现有备份创建为 30 个日周期、12 个周周期、12 个月周期；历史备份自动清理继续保持关闭。

本地升级冒烟已验证：从不含 generation 列的旧流状态表启动，两次幂等迁移后旧游标不变，三张新表存在且 `PRAGMA integrity_check=ok`。
