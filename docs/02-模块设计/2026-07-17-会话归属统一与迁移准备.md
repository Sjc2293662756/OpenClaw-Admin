# 会话归属统一与迁移准备

## 1. 本次完成范围

- Admin BFF 的 `POST /api/workspace/sessions` 是 Web 会话键的唯一签发入口，并在管理 SQLite 的 `workspace_sessions` 中登记所属用户。
- 对话工作台首次发送消息复用该入口；该步骤只登记归属，首条业务消息才会调用 Gateway，不产生浏览器侧伪造的会话键。
- 保留的会话管理类页面复用同一入口后再执行既有的 `/new` 初始化流程，保证旧页面不会绕过 BFF 归属校验。
- RPC 的会话读写、会话列表和 SSE 推送仍由 BFF 按登记归属过滤；管理员保留运维可见性。

## 2. 边界与权威来源

`workspace_sessions.owner_user_id` 是 Web 用户归属的权威记录；Gateway 继续负责会话内容、运行和流式事件。GAIOP 插件可使用 Gateway 上下文中的 `sessionKey` 绑定报告来源和运行期状态，但不保存或推断 Admin 用户身份。

普通用户不得通过自行构造 `sessionKey` 认领会话，也不得查看未登记或归属他人的会话。删除采用 BFF 侧软删除，因此已删除会话即使仍存在于 Gateway 历史中，也不会再向原用户列出或开放访问。

## 3. 历史无归属会话迁移

本次没有迁移任何历史会话，也没有访问 237。集中部署联调阶段应以只读清单开始：核对 Gateway 会话键、创建时间、已有渠道属性和可验证的业务归属；仅在管理员确认的映射上写入 `workspace_sessions`。无法可靠归属的记录必须保持未分配，不得自动分配给首个用户或管理员。

迁移前后均需验证：标准用户只能看到自己的登记会话；无归属会话不可见；管理员可复核；SSE 不向无权用户投递事件；报告来源中的 `sourceSessionId` 与迁移后的会话键一致。

## 4. 验收与部署阶段事项

本地验收覆盖 BFF 签发、所属用户访问、跨用户拒绝、软删除、会话列表过滤和嵌套事件会话键提取，并执行前端类型构建。

仍待部署阶段完成的事项：真实 Gateway 创建/历史/流式事件联调、旧历史迁移演练与回滚预案、目标系统重启后的会话和数据库持续性验证。当前变更不修改 Gateway、GAIOP 运行服务、237 或任何服务器配置。
