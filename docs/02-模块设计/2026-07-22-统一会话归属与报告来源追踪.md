# 统一会话归属与报告来源追踪

## 1. 目标

在不改变飞书、钉钉、企业微信直连 Gateway 的消息主链前提下，统一呈现 Web 工作台和外部频道会话的来源，并把报告准确追溯到来源渠道、渠道用户、会话和触发消息。

本设计不记录或展示“会话使用了哪些 Skill”。现有会话的 Agent、渠道、对端、消息数、模型、Token、最近活动时间、标签、详情、导出、重置和删除能力均保留。

## 2. 会话归属

| 会话来源 | 渠道标记 | 用户标记 | 可见范围 |
|---|---|---|
| webchat 工作台 | `web`（兼容内部字段） | Admin BFF 登录用户 ID 与用户名 | 普通用户仅本人；管理员全部 |
| 飞书、钉钉、企业微信 | Gateway 频道 ID | Gateway 会话对端/平台用户 ID；显示名仅作展示 | 管理员全部；不自动映射为 Web 用户 |

webchat 会话仍由 `workspace_sessions` 保存所有者并在 BFF RPC 代理处执行访问控制。管理员从 Gateway 获取全量会话后，BFF 为列表和详情补充来源字段；普通用户仍只能获取已登记且归属自己的 webchat 会话。

webchat 的底层会话键（例如 `agent:main:main:dm:webchat-...`）仅用作 Gateway、权限和审计关联，不在普通界面展示。BFF 在首条**成功发送**的用户消息后，以去除多余空白后的前 24 个字符生成固定会话标题，超出部分加省略号；这不是 AI 摘要，不调用模型、不会增加 Token 或延迟。左侧历史会话、会话管理和报告文件管理共用该标题；后续消息不会自动改名。一次性历史迁移仅为既有 WebChat 会话读取首条用户消息，写入相同的标题规则；不提供前台按钮，不记录原文，也不影响飞书、钉钉、企业微信会话。

外部频道显示的用户标识来自 Gateway 会话上下文。禁止根据同名显示名称推断其等同于某个 GAIOP Web 账号。

### 2.1 旧版 `main` 共享会话

早期 Web 工作台在未指定会话键时使用 Gateway 默认 `main`。它属于历史 **GAIOP Web Chat**，不是独立产品功能，也不展示 Gateway 的内部客户端标签（例如 `OpenClaw Web Backend`）。

Gateway 会保护默认 `main` 会话，不允许通过 `sessions.delete` 物理删除。管理员在 GAIOP 会话管理中删除该历史项时，BFF 只写入本地 `hidden_legacy_sessions` 退役记录并记录审计；随后该项不再出现在 GAIOP 的会话列表、详情或工作台历史中。此操作不改写 Gateway 私有会话存储，不删除原始历史，因而可安全回滚为移除本地退役记录。其他会话仍调用 Gateway 正式删除接口，并请求归档其历史文本。

新建 WebChat 会话不再使用 `main`：渠道统一显示为 **GAIOP Web Chat**，渠道用户来自 GAIOP 登录账户，会话名称为首条成功发送的用户提问摘要。

### 2.2 待排查：会话列表与继续对话加载慢

2026-07-22 记录：用户反馈会话管理的会话列表打开明显缓慢；从列表点击“继续对话”后，到对话工作台显示既有消息之间也有明显等待。当前先不修改实现。

后续专项排查应分别计时并区分：BFF 的会话列表/归属补充耗时、Gateway `sessions.list` 与 `chat.history` RPC 耗时、浏览器路由与组件挂载耗时，以及 SSE/重复刷新是否造成额外请求。优化必须保持会话权限过滤、历史完整性和继续对话语义，不能以跳过归属校验、减少历史消息或改为重置会话换取速度。

2026-07-30 再次确认：会话列表慢需要优化；“继续对话”进入工作台后长时间不能显示历史消息的问题更严重，应优先定位。输入区完整内部会话键现阶段继续保留，便于把页面现象与具体 `sessionKey`、Gateway 历史和服务端日志对应；待问题稳定后再做最终隐藏。

### 2.3 待决：外部频道的 `/new` 与会话历史

2026-07-22 确认：飞书、钉钉、企业微信的私聊运行时会话按“渠道 + 平台用户”复用稳定 Gateway 会话键。用户发送 `/new` 的当前语义是开始新的 AI 上下文，不会自动产生一条可独立列出、命名和关联报告的外部历史会话；GAIOP 当前会话管理因此只能看到该渠道用户的当前运行会话，而不是其全部历史对话轮次。

这不是数据已经被确认删除的结论，而是当前 Admin 没有外部“会话分段”索引和展示能力。是否调整留待产品讨论：若需要将 `/new` 前后分别作为历史会话管理，应由 Gateway/频道侧提供可信重置事件或会话代次，再由 BFF 持久化渠道、渠道用户、运行时会话键、开始/结束时间和固定标题；报告必须关联该会话分段。标题可沿用首条用户消息的非 AI 截断规则，不增加 Token。未形成该设计和迁移/回滚方案前，不改动频道 `/new` 行为。

2026-07-30 再次确认：外部频道的“历史代次、正确历史模型、按代次生成标题和旧历史读取”属于同一个待决策功能包，需要团队共同决定，暂不拆分实施。外部频道主要用于运维人员快速使用，这些人员可同时拥有独立的 GAIOP 管理员或普通用户账号；当前不自动把平台身份映射、合并或归属到 Web 账号，只保留渠道身份和来源审计。

## 3. 报告来源快照

报告审计 JSON 和 Admin `report_files` 索引新增以下可空字段：

- `source_channel`
- `source_channel_user_id`
- `source_channel_user_name`
- `source_message_id`
- `source_message_preview`

原有 `source_user_id`、`source_session_id`、`data_source_id` 保留。

对于 webchat 报告，BFF 以 `source_session_id` 关联本地 `workspace_sessions.session_title`，在报告文件管理中展示同一会话标题；报告审计仍保留内部会话键，保证会话被删除后审计关系不失真。

Web 路径由 BFF 对 v3 来源信封签名，签名覆盖登录用户、会话、活动数据源、渠道用户和触发消息快照。外部频道由 Gateway 插件从可信频道/会话上下文生成命名空间主体，例如 `channel:feishu:<平台用户ID>`；该主体不会匹配 Web 用户 ID，因此外部频道报告默认仅管理员可见。

报告生成后，Admin 从报告目录旁的审计 JSON 同步索引。即使未来会话删除，报告仍保留渠道、用户、会话和触发消息的来源快照。

## 4. 部署边界

本地代码修改分为两部分：

- `GAIOP-Admin`：数据库迁移、BFF 会话来源补充、报告索引/权限和会话/报告页面。
- `GAIOP-latest`：Gateway 插件和报告输入契约，仅补充可信来源字段。

237 生效必须同时发布新的 Admin BFF 和 Gateway 插件。单独发布 Admin 可显示会话来源和历史报告字段，但新的外部频道报告不会获得完整来源快照；单独发布插件会产生新审计字段，但 Admin 旧版本不会展示它们。

## 5. 兼容与回滚

- 历史会话和历史报告不回填猜测的用户、渠道或消息；缺失字段显示“未记录”。
- 报告 v1/v2 来源信封仍可验证，兼容既有 Web 报告。
- 回滚 Admin 或 Gateway 插件不会删除既有报告文件和审计 JSON；新增索引列为可空列，旧代码可忽略。
