# 报告目录分层与双端适配规划

| 属性 | 内容 |
|---|---|
| 创建日期 | 2026-07-15 |
| 状态 | 本地双端契约与安全边界已完成，待部署联调 |
| 涉及目录 | `GAIOP-Admin`、`GAIOP` |

## 1. 已确认的产品边界

- 报告只能由会话中的 GAIOP AI 自动生成；管理页面不提供上传、新建报告或编辑报告内容。
- “报告文件管理”只负责已生成报告的列表、来源信息、预览、下载和管理员删除。
- “系统设置 → 报告存储位置”只展示本机受控目录的部署状态，不提供文件夹管理、子目录选择、任意路径输入或服务器绝对路径。
- 报告根目录由部署时的 `GAIOP_REPORTS_DIR` 统一确定；管理服务与 GAIOP 报告 Skill 必须指向同一个共享目录。

## 2. 当前行为

GAIOP 报告 Skill 将报告实体和同名审计 JSON 写入 `GAIOP_REPORTS_DIR` 下的用户/报告类型分层目录；GAIOP-Admin 在同一受控根目录内递归扫描审计 JSON，并只登记通过配对与目录边界校验的报告元数据。

系统设置页面不返回或展示真实根目录。部署状态由 Admin BFF 的只读接口提供，不暴露 Gateway Token、NAPM 凭据、服务器路径或其它敏感配置。

## 3. 后续统一目录契约

完成双端适配后，AI 自动生成报告必须使用如下目录结构：

```text
<GAIOP_REPORTS_DIR>/
  <sourceUserId>/
    <reportType>/
      <reportId>.<extension>
      <reportId>.json
```

- `sourceUserId`：使用 Admin 可信来源链传递并经 GAIOP 验证的用户 ID；不得使用用户名、通道 `accountId` 或文件名推断。
- `reportType`：由白名单映射产生，例如 `analysis`、`diagnostic`、`summary`、`inspection`、`scheduled`；不接受浏览器或提示词提供的路径片段。
- 报告实体与同名审计 JSON 始终成对写入、移动和删除。
- 目录分段必须拒绝空值、`..`、绝对路径、分隔符、控制字符与符号链接越界。

缺少可信 `sourceUserId` 的历史报告或外部渠道报告不得伪造归属。后续统一写入保留目录 `_unattributed/<reportType>/`，并继续只对管理员可见。

## 4. 双端改动清单

### GAIOP

1. 报告生成前取得已验证的 `sourceUserId` 与规范化 `reportType`。
2. `ReportStorageService` 根据上述目录契约构造输出目录，继续以 `GAIOP_REPORTS_DIR` 作为唯一根目录。
3. 审计 JSON 保持并补齐相对存储位置字段；不得写入绝对服务器路径。
4. 缺少来源用户时写入 `_unattributed`，不得回退为当前进程用户或通道账号。

### GAIOP-Admin

1. 管理员只读查看 `GAIOP_REPORTS_DIR` 是否已配置且可用；不提供任意路径编辑或绝对路径回显。
2. 报告扫描改为在根目录下安全递归识别配对 JSON，数据库保存经校验的相对路径，不保存或返回任意外部路径。
3. 预览、下载、删除按相对路径解析，并继续执行报告所有者隔离与根目录边界校验。
4. 列表可按用户和报告类型筛选；管理员删除时同时删除报告实体与审计 JSON，并记录不含路径和凭据的审计。

## 5. 联调验收

1. Web 用户生成不同类型报告后，文件落入其用户目录和对应报告类型目录。
2. 同一报告的实体与 JSON 成对存在，Admin 扫描、预览、下载和删除均正常。
3. 普通用户无法读取其他用户目录或 `_unattributed` 目录中的报告。
4. 恶意用户 ID、报告类型或审计 JSON 不能导致路径穿越或目录越界。
5. Admin 与 GAIOP 使用同一 `GAIOP_REPORTS_DIR`，Docker、原生 Gateway 与部署共享卷分别验证。

在上述双端联调完成前，不得宣称网页修改报告位置或按用户/类型目录落盘已经生效。
