# 多数据源会话选择与联合查询规划建议

## 1. 背景与当前事实

当前已经完成数据源管理的基础闭环：管理员可以添加、编辑、删除、测试和启用数据源，凭据加密保存，启用时生成受控运行时桥接。现有数据库和运行时语义仍是“全系统只有一个 `is_active=1` 的运行数据源”。

当前 Web `chat.send` 只读取全局活动数据源 ID 用于报告来源记录，没有形成会话级选源或查询授权。GAIOP 后端多个 Skill 仍直接读取 `NETINSIDE_HOST`、`NETINSIDE_USERNAME`、`NETINSIDE_PASSWORD` 等进程环境变量；原运行时桥接也通过覆盖这些变量适配现有 Skill。

因此，当前基础能力不能安全地直接扩展为工作台切换：如果工作台按钮调用现有“启用数据源”接口，会改变全系统活动源，不同用户、Web 会话和外部频道会互相影响。

## 2. 已确认规则

以下规则已经确认，不属于本规划的待决策项：

1. 所有运维查询必须基于已配置、启用、可用且有权访问的数据源。
2. 没有可用数据源时，Web、飞书、钉钉和企业微信不得调用查询工具，也不得使用旧配置或普通模型回答绕过。
3. 数据源凭据只能在服务端解析，不进入浏览器、模型上下文、频道消息、审计明文或普通运行日志。
4. 无源硬拦截必须在 Web/BFF 和 Gateway/Skill 工具执行层同时生效，不能只隐藏按钮或依赖提示词。
5. 旧 `NETINSIDE_*` 只能作为受控迁移期兼容接口，不得继续作为独立、隐式的运行来源。

## 3. 需要团队决策的核心问题

以下内容仅为建议，尚未形成产品或架构决定：

1. 数据源选择是绑定当前消息、当前会话、当前用户、智能体、频道，还是支持分层默认值。
2. 第一版是否只开放单选，还是同时开放多选和数据源分组。
3. 外部频道使用命令、交互卡片、频道默认源，还是由 AI 自动识别。
4. 多数据源查询采用全量并行、按资产/区域路由，还是由用户显式指定。
5. 某些数据源超时或失败时，是整体失败还是返回明确的部分成功结果。
6. 不同数据源的时区、字段、版本和重复资产如何标准化、比较和合并。
7. 数据源访问权限绑定角色、用户、智能体、频道还是租户，管理员默认是否可访问全部来源。
8. 对话中途切换数据源是否继续沿用当前上下文，还是提示新建会话以减少语义混淆。

未经团队确认，不应把上述建议写成已实现能力，也不应直接改变237的运行语义。

## 4. 建议的目标模型

“唯一运行数据源”建议拆分为两个概念：

- **唯一配置来源**：Admin 数据源注册表是运行配置的唯一权威来源，旧环境变量不再独立兜底。
- **多个可选运行数据源**：一次消息或会话可以选择一个或多个已启用、健康且有权访问的数据源。

建议的选择优先级：

```text
本条消息临时选择
→ 当前会话绑定
→ 当前用户默认值
→ 智能体或频道默认值
→ 系统默认值
```

最终解析结果应固化为本条消息的 `dataSourceIds` 快照。之后即使切换数据源，历史消息、报告和审计仍能追溯当时实际查询的来源。

## 5. Web 工作台建议

在输入区左侧增加“数据源选择器”，显示友好名称而不是 IP 或账号，例如：

- `数据源：香港中心`
- `数据源：香港中心 +2`
- `数据源：自动`
- `未选择数据源`

建议的弹层能力：

- 搜索并单选数据源；
- 后续扩展多选；
- 选择管理员维护的数据源分组；
- 显示启用、健康和无权限状态；
- 明确当前选择作用于本条消息还是整个会话；
- 切换后在对话时间线上增加非模型生成的来源边界提示。

第一版可以只开放单选，但接口和数据结构建议从一开始使用 `dataSourceIds[]`，避免后续多选时再次修改整条链路。

## 6. 外部频道建议

飞书、钉钉和企业微信没有统一的输入区组件，可采用命令和平台交互卡片：

- `/source`：查看当前来源；
- `/source list`：查看有权访问的来源；
- `/source use <名称>`：绑定当前频道会话；
- `/source use <名称1>,<名称2>`：后续多选；
- `/source group <分组>`：选择数据源分组；
- `/source auto`：后续启用受控自动路由。

每个机器人、频道或智能体可以设置默认来源。没有会话绑定或允许的默认来源时，查询应返回固定的选源提示，不调用模型、Gateway 查询工具或 NAPM。

外部频道的选择状态应绑定稳定的频道会话标识，并与 `/new` 的历史代次设计协调；不能只保存为进程内变量。

## 7. 多数据源查询执行建议

多源查询不应把凭据交给模型并由模型自行逐个调用。建议建立服务端数据源解析与编排层：

```text
消息携带 dataSourceIds
→ 权限、启用状态和健康校验
→ 服务端解析凭据
→ 按并发上限并行查询
→ 每份结果附来源、时间和状态
→ 字段、单位和时区标准化
→ AI 仅接收脱敏结果进行比较或总结
```

需要明确：

- 每源超时和总超时；
- 最大并发和最大选择数量；
- 部分失败的稳定错误结构；
- 重试和取消语义；
- 重复资产和跨源同名对象的标识规则；
- 报告、告警分析和审计中的多来源记录；
- 任一来源失效时不得回退到未选择的旧来源。

## 8. 建议的分阶段实施

### 阶段一：无源硬边界与旧回退收口

- 建立统一活动来源状态契约和错误码；
- Web/BFF 与 Gateway/Skill 双层硬拦截；
- 受控迁移旧配置；
- 验证后停止旧 `NETINSIDE_*` 独立兜底；
- 暂时保留一个系统默认数据源。

### 阶段二：会话级单数据源

- Web 增加选择器；
- 会话持久化一个选中来源；
- 外部频道增加命令或默认来源；
- 每条消息和报告记录实际来源；
- 不同用户和会话并发时互不改变全局配置。

### 阶段三：多选与数据源分组

- 接口开放 `dataSourceIds[]`；
- 增加并行查询、部分失败和聚合结果；
- 增加数据源分组、访问权限和审计；
- 完成 Web 与三个外部频道一致验收。

### 阶段四：受控自动路由

- 根据区域、设备、业务标签和资产映射选择来源；
- 无法唯一判断时要求用户确认；
- 用户始终可以显式指定单源、多源或分组；
- 自动选择结果必须进入消息来源快照和审计。

## 9. 非目标与安全边界

- 本规划不授权修改238服务器、NAPM配置或客户频道平台配置。
- 本规划不读取、展示或迁移任何实际密码、Token、Cookie、私钥或频道凭据。
- 不允许通过前端参数直接传入上游地址、账号或密码。
- 不允许工作台切换复用当前全局“启用数据源”接口。
- 不允许为实现多源查询而把凭据写入模型提示、Gateway普通消息或报告正文。
- 在团队完成产品、权限、并发和失败语义决策前，不实施多源联合查询。

## 10. 验收方向

- 无源时所有入口均不能触发查询工具。
- 两个用户同时选择不同数据源时互不串源。
- 同一会话的来源选择可恢复，消息级来源可追溯。
- 多源查询的成功、部分失败和全部失败结果均明确标记来源。
- Web 与外部频道遵循同一权限和解析规则。
- 页面、日志、审计、模型上下文和报告均不泄露凭据。
- 重启、断网、数据源停用和切换后不存在旧环境变量兜底。
