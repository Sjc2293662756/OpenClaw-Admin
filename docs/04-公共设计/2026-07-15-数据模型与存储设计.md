# GAIOP 数据模型与存储设计

| 属性 | 内容 |
|---|---|
| 创建日期 | 2026-07-15 |
| 状态 | 当前实现基线 |
| 代码依据 | `server/database.js`、`server/routes/*` |

## 1. 存储分类

| 存储 | 位置/来源 | 数据 |
|---|---|---|
| 管理 SQLite | `GAIOP-Admin/data/wizard.db` | 用户、审计、数据源、主机网络、敏感配置、会话设置、报告元数据、工坊场景/任务 |
| Gateway | GAIOP 智能体服务 | 会话、消息、任务计划、模型、频道、Skills、记忆和智能体 |
| 报告目录 | `GAIOP_REPORTS_DIR` | 报告实体和配套审计 JSON |
| 运行时桥接 | `GAIOP_ACTIVE_DATA_SOURCE_FILE` | Admin 写入、核心读取的当前运行 NAPM 地址、账号、密码和 TLS 模式 |
| 进程内存 | 管理服务 | 登录 Token 会话、SSE 客户端等 |

浏览器不是任何凭据或权威配置的存储位置。

## 2. SQLite 表

### users

| 字段 | 说明 |
|---|---|
| `id` | UUID 主键 |
| `username` | 忽略大小写唯一 |
| `password_hash` | 带盐哈希，不可回显 |
| `role` | basic/auditor/standard/admin |
| `description` | 可空说明 |
| `status` | active/inactive |
| `created_at/updated_at` | 毫秒时间戳 |

### audit_logs

记录操作者 ID、用户名、角色、动作、目标、详情和时间。当前只保留成功业务事件为主，未记录请求 ID、IP 和完整结果。

### data_sources

保存 IP、类型、账号、AES-256-GCM 密码、状态、TLS 内部模式、唯一运行标记、测试信息和时间。部分唯一索引保证最多一条 `is_active=1`。

状态：`success/failed/untested/disabled`；TLS：`strict/napm_self_signed`。TLS 模式不向普通列表响应公开。

### host_network_config

单例记录（`id=1`）：主机名、域名、IP、掩码、网关、JSON 数组形式的 DNS/内部地址/NTP、时区和语言。它是管理配置，不等于操作系统真实状态。

### system_sensitive_configs

以配置键为主键，类别为 runtime/integration/security/certificate；普通值存 `value_plain`，敏感值存 `value_encrypted`，两者互斥。

### session_settings

单例记录：登录小时、管理端空闲分钟、智能体上下文空闲分钟、历史保留天数和更新时间。

### report_files

保存报告 ID、内部安全文件名、配套审计 JSON 名、展示名称、类型、来源会话/用户/数据源、MIME、大小、状态和时间。实体不存 SQLite。

### scenarios / tasks

原智能体工坊的场景和任务数据，多个结构字段以 JSON 文本保存。后续产品化前需评估拆表、版本和并发更新。

### backup_records

原数据备份遗留表。正式数据备份页面已隐藏，系统升级不能直接把该表视为升级模型；后续清理需先确认无运行依赖。

## 3. 关联和所有权缺口

目前 `source_user_id/source_session_id/data_source_id` 多为可空文本引用，没有外键；Gateway 会话也没有与管理用户建立强制所有者关系。因此当前不能承诺完整多租户隔离。生产多人使用前至少需要：

1. 建立管理用户与 Gateway 会话的所有者映射。
2. 报告写入真实来源并按所有者/管理员过滤。
3. 任务、智能体和数据源如需按组织授权，建立显式关联表。
4. 删除用户时定义历史会话、报告和审计的保留策略。

## 4. 迁移和备份

当前使用启动时 `CREATE TABLE IF NOT EXISTS` 和若干 `ALTER TABLE` 兼容升级，没有独立迁移版本表。进入生产升级前应引入可追踪 schema 版本、向前迁移、备份和回滚规则。

备份 SQLite 时需同时处理 WAL/SHM 或使用 SQLite 在线备份机制；不能只在运行时复制主 DB 文件。报告目录、运行时桥接和加密密钥分别制定备份策略，密钥丢失会导致密文不可恢复。

## 5. 数据安全

- 数据源和敏感配置使用不同密钥优先级，均不提交仓库。
- 运行时桥接含明文凭据，仅服务账号可读，建议 0600。
- 审计与日志不记录密码或完整请求体。
- 报告文件名与根目录双重校验，禁止路径穿越。
