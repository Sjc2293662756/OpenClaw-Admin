|---|---|

## 1. 信任边界

```text
不可信浏览器
  → 管理服务认证与 RBAC
  → Gateway 方法级权限
  → Skills 权威运行数据源
  → NAPM
```

浏览器输入、路由参数、RPC 方法和上传内容均不可信。Gateway 和 NAPM 只通过管理服务或受控运行时访问。

## 2. 认证机制

- 用户密码使用随机盐哈希。
- 登录返回不透明 Token，服务端内存保存创建时间、最后活动和最大过期时间。
- 每个受认证请求检查状态和时间；退出、密码重置/修改会撤销相关 Token。
- 新建、重置和修改密码统一要求至少8位，并同时包含英文字母和数字；中文、空格及特殊符号允许使用。前端提示不能代替服务端校验。
- 同一用户名（大小写不敏感）连续登录失败5次后在进程内锁定5分钟；到期自动解除，成功登录清空失败次数。不存在用户、停用用户和密码错误使用相同外部错误。
- 管理员重置密码后设置 `must_change_password`，撤销目标用户全部Token。临时密码登录只允许认证检查、退出和本人改密；REST管理能力、工作台和Gateway RPC均由统一认证中间件拒绝。
- 首次改密成功会清除标记、撤销旧Token并要求重新登录。
- 管理服务重启会使全部 Token 失效，这是当前已知行为。

## 3. RBAC

REST 使用认证、基础用户工作台边界、管理员、审计查看、系统监控查看等中间件；Gateway RPC 使用显式方法级决策。管理员默认全权，基础和标准用户只允许对话与本人会话相关的明确白名单，审计用户的对话为只读。敏感读取方法即使以 `.get` 结尾也被单独拒绝。

页面、路由和服务端的第一阶段矩阵统一为：

- 基础用户可进入对话工作台、告警记录和报告文件管理，并可从工作台头像菜单修改本人密码和退出；可创建、继续、停止和删除本人 WebChat 会话，左侧历史仅返回本人 active 会话。告警为系统级只读记录；报告只返回 `source_user_id` 与当前登录用户稳定 ID 完全一致的记录，未知归属和他人报告均以 404 隐藏。仪表盘、独立会话管理、频道、系统设置及全部管理页面仍不可访问。
- 标准用户可对本人会话进行正常操作，报告仍仅本人范围；审计和管理员继续按既有矩阵访问管理控制台。
- 审计用户可只读查看全部会话和报告，可查看任务计划、频道、Skills、系统监控、审计信息和账户列表安全投影；不能删除、发送、运行或修改。
- 标准用户可查看频道、Skills 和系统监控的安全投影；不能写任务、安装或更新 Skills、切换模型、修改频道凭据或调用 Office/Wizard。
- 账户新增、编辑、重置密码、启停、删除及其子页面仍仅管理员可访问；记忆、模型、智能体、工坊、系统配置和系统升级也仅管理员可访问。
- 工作台保留所有角色的“管理控制台”入口：有仪表盘权限的角色正常进入；基础用户点击后留在工作台并显示居中“当前账户没有管理权限”提示。基础用户从欢迎页“配置管理”登录时同样回到工作台并显示该提示；直接 URL 进入其他正式管理页面仍统一到“无访问权限”。REST/RPC 仍是最终裁决。
- 基础用户 REST 在认证后先经过专用边界，只允许 `/api/rpc`、工作台会话创建、SSE、本人会话媒体、本人报告的列表/下载/受支持格式预览、告警列表/服务器时间/补偿/当前账户告警偏好与当前页导出、以及本人改密；RPC 再按工作台方法白名单和会话归属裁决。告警规则/接收器配置、系统设置、报告上传/删除/留存管理不在此白名单。
- 非管理员 `config.get`、频道、插件和 Skills 读取使用字段白名单投影，不向浏览器返回地址、路径、凭据或原始配置。审计用户账户读取同样使用字段白名单，不返回密码哈希或首次改密等内部安全状态。

管理员角色内部增加账号保护层，但不新增角色：

- 用户表最多有一个 `is_initial_admin=1`；现有数据库选择最早创建且仍激活的管理员，新安装环境的首个管理员自动标记。
- 初始管理员可创建、提升和管理其他管理员；普通管理员只能管理基础、审计和标准用户。
- 初始管理员不能删除、停用、降级或由他人重置密码，只能本人按正常流程修改密码。
- 初始管理员标记不提供页面或普通接口转移能力；部署侧遗忘密码恢复另行受控设计，不设置固定后门。
- 继续保留不能删除自己和不能删除/停用最后一个有效管理员的保护。

前端 `can*` 判断只用于禁用按钮和解释原因，不能代替服务端检查。

### 3.1 模块覆盖第二阶段

服务端 `module-permissions.js` 是唯一模块目录和有效权限 resolver。登录和每次认证检查投影 `effectiveModules/permissionVersion`；浏览器导航、路由和模块入口只消费该投影，不持有角色默认矩阵。REST、告警 SSE 和 Gateway RPC 均先检查有效模块，再执行原有动作、身份、归属和数据投影；`allow` 不会把模块内的管理员写动作授予非管理员。

初始管理员的 `users/userAdministration` 锁定允许，`platformBranding` 继续受初始管理员身份锁保护。`alerts.export` 依赖 `alerts.records`；`alerts.notifications` 可独立允许，但无 records 时不显示详情跳转。对话工作台不参与配置，保留原会话边界。变更后只向目标用户发送 `permissionsChanged`，目标重取投影并重建 SSE。

## 4. 敏感数据

| 数据 | 处理 |
|---|---|
| 用户密码 | 单向哈希 |
| NAPM 密码 | AES-256-GCM，独立环境密钥 |
| 环境敏感项 | AES-256-GCM，优先独立密钥 |
| Gateway 配置 | 非管理员递归掩码敏感键 |
| 运行时桥接 | 明文仅供 Skill 运行，文件权限限制 |
| 报告/审计 | 不记录凭据和真实服务器路径 |

## 5. TLS

GAIOP 最终对外使用 HTTPS 443。NAPM 同厂自签名证书采用“数据源级自动兼容”，仅对已识别的数据源放宽证书验证；不得设置 Node 全局 `NODE_TLS_REJECT_UNAUTHORIZED=0`。跨厂商或高安全场景再设计 CA/证书固定。

## 6. 当前风险

- `server/index.js` 仍包含大量隐藏模块和遗留实现，需继续缩小可达接口面。
- RPC 方法虽保留只读分类辅助，但非管理员仅允许角色显式集合；新增 Gateway 方法需显式评审。
- Token和登录失败计数只在内存，服务重启会清空；尚无集中会话存储或CSRF/SameSite Cookie模式。
- `.env.example` 和部分内部变量仍含历史技术名称，不能在用户界面展示；重命名需兼容迁移。

## 7. 生产最低要求

- 设置符合规则的初始管理员密码和高强度加密密钥，不保留共享默认重置密码。
- 仅 443 对公网，管理服务/Gateway 绑定回环或私网。
- 限制 `.env`、SQLite、报告和桥接文件权限。
- 开启依赖漏洞检查、密钥扫描、审计备份和时间同步。
- 持续执行四角色页面、直接 REST/RPC、会话/报告归属和敏感投影回归。
