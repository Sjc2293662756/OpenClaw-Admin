| 属性 | 内容 |

## 1. 问题与目标

此前存在三类体验问题：

1. 新电脑第一次打开 GAIOP 时可能因浏览器或操作系统的深色偏好而直接进入深色界面。
2. 登录页继承深色组件变量后，浅色输入框中的文字可能显示为白色，账号和密码难以辨认。
3. 对话工作台和系统配置只完成部分深色适配，出现页面外壳、卡片、输入区、按钮和文字混用深浅颜色的情况。

本次目标是把“首次浅色、登录固定浅色、登录后可手动切换深色且关键页面完整适配”固化为可测试的产品规则，而不是依赖浏览器当前主题或单个页面的临时颜色覆盖。

## 2. 已确认的产品规则

| 场景 | 规则 |
|---|---|
| 新浏览器、新设备、缺失主题值或非法主题值 | 一律浅色主题 |
| 浏览器或操作系统为深色模式 | 不自动改为 GAIOP 深色主题 |
| 已明确选择深色的已登录用户 | 保留深色偏好，直到用户手动切换 |
| 旧版本主题偏好 | 兼容读取旧键并迁移到 GAIOP 新键 |
| 欢迎页与登录页 | 始终浅色，不提供或继承深色外观 |
| 登录后的管理界面与对话工作台 | 保留浅色/深色切换入口 |

主题仅影响显示层，不改变权限、会话、数据源、Gateway、Skill、频道、报告或服务器配置。

## 3. 实现设计

### 3.1 挂载前的默认主题

`index.html` 在 Vue 加载前把文档主题设为浅色。只有浏览器内存在明确、有效的深色偏好时，才会在首帧切为深色。这样避免 Vue 挂载、路由守卫或组件初始化之间出现黑底闪烁，也避免把系统深色模式误当成产品偏好。

### 3.2 主题存储与兼容迁移

主题状态统一由 `src/stores/theme.ts` 处理：

- 新键为 `gaiop_theme`；
- 兼容旧键 `openclaw_theme`；
- 只接受 `light` 与 `dark` 两个值；
- 缺失、异常、不可读存储均安全回退为 `light`；
- 用户主动选择后写回新键。

应用根组件同时同步 `html[data-theme]` 与浏览器 `color-scheme`，保证 Naive UI、原生表单控件和页面 CSS 使用同一主题状态。

### 3.3 入口路由隔离

欢迎页和登录页通过路由元数据标记为 `lightOnly`。在这些路由上，Naive UI 强制使用浅色主题，文档根元素也同步保持浅色；离开入口后恢复用户此前保存的后台主题偏好。

登录页额外固定输入框背景、文字、占位符、光标和聚焦边框，避免组件变量受其他主题状态影响造成低对比度。

### 3.4 深色页面适配

本次覆盖以下区域：

| 页面/模块 | 已适配内容 |
|---|---|
| 对话工作台 | 页面背景、侧栏、品牌区、历史会话、用户菜单、顶部栏、状态文字、新对话按钮 |
| 对话主区 | 欢迎引导、标题、说明、快捷问题、消息承载区、输入区 |
| 系统配置总览 | 介绍卡、章节容器、边框、章节标题、说明和提示标签 |
| GAIOP 服务连接 | 返回入口、顶部介绍区、标题与说明 |
| Syslog 告警接入 | 返回入口、顶部介绍区、标题、说明与启用提示 |
| 数据源管理 | 辅助说明文字 |

实现时发现 Vue scoped CSS 中把 `:global()` 只包在祖先选择器上会丢失后续局部选择器，导致深色规则看似存在却没有命中实际元素；并且工作台部分深色规则排在同等优先级的浅色规则之前，会被后者覆盖。现已将完整选择器纳入全局范围，并把工作台深色规则置于浅色规则之后。该经验适用于之后新增主题页面。

## 6. 回归与后续要求

1. 新增页面必须同时确认浅色、深色下的背景、正文、输入、按钮、卡片、表格、提示与悬浮状态。
2. 不得仅因系统 `prefers-color-scheme` 为深色就切换产品主题。
3. 登录、欢迎和其他未认证入口必须维持浅色与可读输入控件。
4. scoped 样式涉及全局主题祖先时，应验证编译后的选择器和计算样式；不要仅以源码中的规则存在作为验收依据。
5. 正式验收仍应在四角色和真实 Gateway 已连接的环境下，人工覆盖登录、工作台新对话/历史会话、系统配置及主题往返切换。

## 7. 回滚边界

本主题整改是 Admin 前端与 BFF 静态发布的一部分，不涉及 GAIOP 后端行为或运行时敏感配置。若需撤销 237 发布批次，使用受控回滚脚本恢复 `20260721T033750Z` 的发布前 Admin 目录，再执行回环监听、健康接口和 Gateway 连接验证。不得以回滚主题为由覆盖 `data/wizard.db`、用户图片删除记录、环境文件、报告或其他用户数据。
