# 运行数据源查询边界与迁移规划

| 属性 | 内容 |
|---|---|
| 日期 | 2026-07-21 |
| 最后更新 | 2026-07-30 |
| 状态 | 产品规则已确认；双端强制执行与受控迁移待开发 |
| 适用范围 | Admin 数据源、Admin BFF、GAIOP Gateway、Skills、Web 工作台与外部频道 |

> 2026-07-30 补充：已经确认的是“无可用数据源时禁止查询”和“Admin 管理成为唯一配置来源”。会话级单选、多选联合查询、数据源分组、外部频道选源及 AI 自动路由仍需团队决策，不属于本文已经确认的产品规则。规划建议见[多数据源会话选择与联合查询规划建议](2026-07-30-多数据源会话选择与联合查询规划建议.md)。

## 1. 已确认的产品规则

所有运维查询必须基于一条已启用的运行数据源。没有已启用且可用的运行数据源时，Web、飞书、钉钉、企业微信和任何其他入口均不得调用 Gateway、Skill、NAPM 或其他查询工具；不能以普通模型回答或页面隐藏作为绕过方式。

这是一条查询授权边界，而不是单纯的前端表单规则。客户管理员在外部频道平台配置谁可使用机器人，GAIOP 不在本阶段重复实现外部平台的成员白名单；但无论消息来自哪个频道，数据源前置条件必须一致。

## 2. 当前事实与缺口

| 项目 | 当前事实 | 缺口 |
|---|---|---|
| Admin 数据源 | 管理页可维护、测试和启用数据源，并保存受控状态 | 不能仅凭页面记录推断 Gateway/Skill 已使用同一来源 |
| Gateway/Skill 查询 | 现有查询仍可能依赖旧 `NETINSIDE_*` 兼容回退配置 | 旧回退配置、Admin 记录与运行时桥接尚未形成可验证的唯一来源 |
| BFF 对话入口 | 当前 `chat.send` 未把活动数据源作为硬性前置校验 | Web 工作台仍可能在 Admin 列表异常时继续查询 |
| 外部频道 | 长连接直接进入 Gateway 频道组件 | 需要在 Gateway/Skill 消费查询工具前执行同一前置校验 |

此前一次受控迁移尝试确认：Admin 所需运行时桥接目标存在，但桥接文件当时不存在；迁移在写入前停止，未创建或改写记录、未改动 Gateway、未重启服务，也未读取或输出上游地址、账号、密码等敏感值。之后用户已通过 Admin 页面补录数据源，但三处状态的一致性仍需由正式迁移和校验能力证明。

## 3. 目标架构

```text
管理员启用数据源
  → Admin SQLite 加密记录
  → 受控运行时桥接（仅服务账户可读）
  → BFF 查询前置校验
  → Gateway / Skill 查询前置校验
  → NAPM 查询
```

任何一层无法确认“存在、启用、可读取且一致”的运行数据源时，应返回明确的不可查询状态，不向下游发送查询请求。UI 只展示脱敏状态，不能展示桥接路径、上游地址、账号、密码或旧环境变量值。

## 4. 实施顺序

1. 定义 BFF 和 Gateway/Skill 共用的活动数据源状态契约及错误码。
2. 在 BFF 的 Web 对话、报告、告警分析入口先增加硬性前置校验。
3. 在 Gateway/Skill 的实际查询工具调用前增加独立校验，防止外部频道和绕过 BFF 的路径绕过规则。
4. 实现旧回退配置到 Admin 加密记录与运行时桥接的受控迁移：版本化备份、字段校验、内部加密写入、启用状态校验和可回滚验证。
5. 在迁移完成并经真实数据源联调后，逐步取消旧 `NETINSIDE_*` 查询回退；取消前不得贸然启用全渠道阻断，以免中断当前客户查询。

## 5. 迁移与回滚要求

迁移只能在服务器内部处理敏感字段。界面、审计和日志只记录脱敏状态、迁移阶段、是否成功和回滚结果。写入前必须建立版本化备份；任一字段、桥接生成、启用校验或健康验证失败时，恢复原记录与原桥接状态，不改写 Gateway 配置或服务进程。

## 6. 验收标准

- 无活动数据源时，四类 Web 角色和三类外部频道均不能触发任何查询工具。
- 有活动数据源时，BFF 与 Gateway/Skill 使用同一来源标识；来源切换有审计且不泄露凭据。
- Admin 记录、运行时桥接和实际消费状态可通过脱敏状态接口一致验证。
- 迁移失败、桥接缺失、数据源停用、认证失败和重启恢复均有明确错误、审计和回滚结果。
- 客户外部频道成员范围仍由飞书、钉钉、企业微信等平台管理员配置，不与上述数据源规则冲突。
