# 单用户模块权限覆盖设计

| 属性 | 内容 |
|---|---|
| 日期 | 2026-08-31 |
| 状态 | 第二阶段正式实施基线 |
| 范围 | GAIOP-Admin 页面、REST、SSE、Gateway RPC 与 SQLite |

## 1. 目标与不变量

本阶段在 `basic/auditor/standard/admin` 四角色默认矩阵之上增加单用户模块覆盖。没有覆盖时完全沿用角色默认；`allow` 强制增加，`deny` 强制削减；删除覆盖恢复角色默认。覆盖只属于目标用户，不改变角色或同角色其他用户。

以下边界不因模块覆盖改变：

- 对话工作台不进入可配置目录；未获得 `data.allUsers` 与 `sessions` 的交集时，左侧历史仍只有本人会话。
- `data.allUsers` 只扩大仪表盘、会话、报告的读取范围，必须与对应模块同时允许；它本身不开放页面、REST 或 RPC 模块。
- 报告列表、预览和下载先执行 `source_user_id` 归属；只有有效 `data.allUsers` 才可读全部记录，无权访问统一 404。
- 会话列表、历史、详情、媒体和 session SSE 执行 `workspace_sessions.owner_user_id` 归属；全量范围下的他人会话仍只读，发送、停止、重置、修改和删除继续执行原角色及本人归属门禁。
- 告警记录、通知和导出仍是系统级脱敏数据；导出只接受当前页六字段且最多 100 条。
- 审计、认证、首次改密、初始管理员、最后管理员、敏感字段投影和退役接口 410 不可绕过。
- 账户列表和账户管理不进入个人覆盖目录：basic/standard 不看账户列表，auditor 全量只读，admin 按既有账户治理规则管理，模块覆盖不能增加或削减这些能力。
- 模块允许只开放该模块已登记的入口、REST/SSE 和 Gateway 能力。初始管理员专属或现有高风险写动作继续执行原有身份/动作保护，不把某个模块的允许扩张为管理员全局写权限。

有效权限只由服务端固定目录和 resolver 计算。前端不得从角色重新推算默认权限。

## 2. 固定模块目录

风险枚举固定为 `low/medium/high/critical`；分组固定为“数据范围、业务管理、系统运维、高级管理”。`dataScope` 是覆盖生效后仍必须执行的数据范围。

|---|---|---|---|---|---|---|---|---|

### 2.2 依赖与锁定

- `data.allUsers` 不设置模块依赖，避免它反向开放页面；运行时按 `data.allUsers AND 对应模块` 计算读取范围。
- basic/standard 对他人会话的写操作不会因 `data.allUsers` 放行；前端按 `ownerUserId` 隐藏操作，服务端读写门禁分离并继续最终裁决。
- 告警导出是 `alerts.records` 内置操作，不再作为独立权限项。
- `alerts.notifications` 可独立允许；无 records 时服务端仍发送脱敏通知，前端隐藏“查看详情”。
- `systemConfiguration` 自身就是侧栏正式父入口，不依赖 `settings`。
- 目标是初始管理员时，全部模块锁定为允许，只展示、不允许个人覆盖，确保最高治理入口不会自降权。
- 账户列表和账户管理由服务端固定角色投影：basic/standard 均拒绝，auditor 仅账户安全投影只读，admin 允许进入账户治理；普通管理员仍只管理 basic/standard，初始管理员管理全部角色。个人模块权限读取、保存和恢复始终要求初始管理员身份。
- `platformBranding` 始终受初始管理员身份锁；覆盖不能提升其他用户为初始管理员。
- 锁定和依赖是服务端校验，前端禁用只用于解释原因。

### 2.3 复核后的双层门禁规则

审计 Router 的列表与导出不再在有效 `audit` 模块门禁之后重复检查旧的 auditor/admin 角色集合；生产装配与 HTTP 测试共用 `createAuditModuleRouter`，内部只重复认证，不重新推翻个人 allow。对其余“外层模块 + 内层门禁”逐项复核后，保留的内层限制均属于目录已经声明的动作或数据范围：账户写入、配置写入、升级执行和频道管理仍要求管理员；会话留存概览仍限制全量只读角色；报告根目录仍为管理员部署信息。它们不是模块查看权限的重复角色判断，个人 allow 不会绕过这些边界。

## 3. 数据模型与迁移

新增表：

```sql
CREATE TABLE user_module_permission_overrides (
  user_id TEXT NOT NULL,
  module_key TEXT NOT NULL,
  effect TEXT NOT NULL CHECK (effect IN ('allow', 'deny')),
  updated_by TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, module_key)
);
```

`users` 新增 `permission_version INTEGER NOT NULL DEFAULT 0`。启动迁移幂等创建表、列和 `updated_by/updated_at` 索引；不修改既有用户角色、状态、密码或数据归属。`inherit` 不落库。

覆盖保存采用一个 SQLite 事务：读取目标用户与当前版本、校验 `expectedVersion`、删除旧覆盖、插入新覆盖、将 `permission_version + 1`、写结构化审计。事务失败不留下部分覆盖或版本变化。用户删除时同事务清理其覆盖。

## 4. 唯一 resolver

服务端 resolver 输入用户数据库行和该用户覆盖，按固定顺序计算：

1. 从固定目录读取角色默认 `defaultAllowed`。
2. 应用 `allow/deny` 得到候选 `effectiveAllowed`。
3. 应用初始管理员全部权限锁和品牌身份锁；账户治理另由固定角色投影计算，不进入覆盖 resolver。
4. 校验依赖；持久化写入前依赖不满足直接拒绝，读取时若遇到历史异常数据则安全降级依赖项并报告诊断，不自动改库。
5. 投影 `moduleKey/defaultAllowed/override/effectiveAllowed/locked/lockReason/risk/group/dependencies/dataScope`。

认证 session 不作为权限权威缓存。每个受认证请求从 SQLite 刷新角色、状态、初始管理员标记、`permission_version` 和 `effectiveModules`，REST、SSE、RPC 共用同一投影。前端只保存服务端返回的 `effectiveModules` 与 `permissionVersion`。

## 5. 在线生效

保存或恢复默认成功后，BFF 立即：

1. 更新与目标用户关联的 SSE client 权限快照；
2. 只向目标用户发送 `{type:"permissionsChanged", permissionVersion}`；
3. 浏览器重新调用 `/api/auth/check` 获取完整投影；
4. 若当前路由失权，替换到无权限页；导航立即重算；
5. 断开并重建唯一 `/api/events`，使告警通知过滤与新权限一致。

不广播覆盖内容给其他用户。同角色其他用户的版本和连接不变化。目标用户被停用或删除时，先发送目标事件再关闭其既有 SSE 连接，避免已撤销账户继续接收数据。

## 6. 前端管理体验

入口位于账户列表的“权限”操作，仅初始管理员可打开。抽屉顶部可直接切换目标用户；内容按“数据范围、业务管理、系统运维、高级管理”分组，显示角色默认和“角色默认/允许/拒绝”三态选择，不重复显示最终结果列；支持搜索和只看个人调整。初始管理员全部只读锁定；账户列表、账户管理和平台品牌配置不在该抽屉显示。

切换只修改本地草稿。选择用户区域和固定底栏使用不透明白色背景；底栏显示个人增加、个人削减和待保存数量，无覆盖时显示“尚无个人调整”。每行“恢复默认”和底栏“全部恢复默认”始终显示，当前已经跟随默认时禁用。保存前展示增加/削减差异，涉及 `high/critical` 的增加或削减必须二次确认。

角色编辑与权限覆盖分开保存。角色变化后重新读取权限投影，覆盖仍保留并在新角色默认上重新计算。

## 7. 测试不变量

- 四角色无覆盖逐项等于第 2.1 节。
- allow、deny、空集合恢复、角色变化和同角色用户隔离均覆盖。
- 未知 key、非法 effect、重复项、锁定项、依赖冲突、版本冲突、非初始管理员写入均拒绝。
- 导航、直接路由、REST、告警 SSE 和已登记 RPC 使用同一有效权限；共享对话 RPC 明确保留工作台固定边界。
- `data.allUsers` 的四角色默认、个人 allow/deny、对应模块交集、会话读写分离、报告列表/下载、仪表盘聚合和 SSE/媒体范围均覆盖。
- 报告本人 404、会话归属、告警系统级范围、审计与第一阶段 basic 告警/导出/偏好不回退。
