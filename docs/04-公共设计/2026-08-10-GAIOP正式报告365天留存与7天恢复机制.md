# GAIOP 正式报告 365 天留存与 7 天恢复机制

> 状态：代码与部署模板已完成，尚未部署 237，自动处理默认关闭。

## 1. 范围与归属

本机制只接受 `report_files` 中报告 ID、`stored_name`、`audit_name` 的精确登记关系，并按 `report_deliveries.event_name` 补齐同一报告的交付事件。受管实体仅包括正式 DOCX/PDF、其配对审计 JSON、数据库中的来源字段以及已登记交付事件。来源信封、频道发送副本、会话、告警和其他目录不在范围内。

这里的“来源记录”是已经幂等落入 `report_files.source_*` 的报告元数据，随该报告数据库记录一起隔离、恢复或永久删除。Sidecar 的共享 `report-attribution/index.json` 是跨报告的上游登记索引，不是单报告独占文件；为避免与 Sidecar 并发改写共享文件，本批不把它当作可删除实体，也不会修改它。永久删除报告后索引中的历史登记不再能通过实体和审计配对验证，后续如需治理该共享索引，应由 Sidecar 自己的独立策略处理。

正式报告根目录由 `GAIOP_REPORTS_DIR` 指定，恢复根目录由 `GAIOP_REPORT_RECOVERY_DIR` 单独指定。实现不按扩展名扫描候选，也不递归删除报告根目录。缺少登记、配对内容不一致、大小不一致、时间异常、路径越界、符号链接、未知恢复区条目或实体缺失时均保护原数据并记录无敏感信息的原因代码。

## 2. 生命周期

1. 自动候选必须同时满足数据库 `created_at` 和正式文件 `mtime` 严格早于 UTC 365 天截止时间，且 `long_term_keep=0`。
2. 到期组按最老优先、单批最多 `GAIOP_REPORT_RETENTION_MAX_ITEMS` 条处理。系统先持久化精确文件计划，再把审计、交付事件和正式文件逐个原子改名到以报告 ID 哈希隔离的恢复目录；正式文件最后移动。
3. 计划开始后，报告从正常列表与下载接口隐藏。失败保留 `quarantine_error` 和文件计划，后续可幂等重试，不删除数据库记录。
4. 管理员可在 7 天恢复期内把全部实体移回原登记位置；恢复失败保留 `restore_error`。
5. 只有 `quarantined_at` 严格早于 UTC 7 天截止时间时才允许永久删除。删除前必须先写入不含报告内容和路径的审计意图；审计不可写时不删除文件。物理文件全部删除成功后，才在事务中删除 `report_deliveries`、文件计划和 `report_files`，并完成永久删除审计。

清理审计表 `report_retention_audits` 不保存报告名称、正文、路径、来源正文或交付正文，仅保存报告 ID、动作、结果、稳定原因代码、实体数量、字节数和 UTC 时间。该表按 3 年保护，本批不提供清理实现。

## 3. 长期保留与管理操作

`report_files.long_term_keep=1` 的报告永不进入自动隔离或永久删除候选。管理员在报告页可设置或取消长期保留，并可打开“报告恢复区”执行整组恢复。原 DELETE 接口改为“仅到期报告移入恢复区”，不再即时永久删除。

## 4. 自动处理边界

- `GAIOP_REPORT_RETENTION_AUTO_PROCESS=false`：默认值；one-shot 在导入数据库模块前直接退出，不创建、迁移或处理数据。
- `gaiop-report-retention-cleanup.timer`：每日 UTC 02:45 触发，`Persistent=true`。
- one-shot 复用 Admin 清理单实例锁，只获得 Admin 数据库、正式报告根、恢复根和自身运行锁目录的写权限。
- 不实施任何磁盘水位策略，也不授权全盘或跨组件清理。

## 5. 验证覆盖

专项测试覆盖幂等迁移、365 天双时间边界、7 天严格边界、长期保留、成组隔离与恢复、重启式重试、文件操作失败保留数据库、审计不可写禁止永久删除、路径穿越、符号链接、大小不一致、未知恢复条目、单批上限和默认关闭运行器。生产启用前仍须只读核对实际目录、开关、timer、候选和前后计数，并取得单独确认。
