# GAIOP 正式报告留存部署与回滚说明

> 本文是尚未实施的部署模板，不是 237 发布记录。当前分支未访问、迁移或删除任何生产报告。

## 1. 安装前只读核查

部署负责人须重新确认当前 Admin 提交、`GAIOP_REPORTS_DIR` 的解析后真实目录、数据库 `report_files/report_deliveries` 行数、正式 DOCX/PDF 与配对 JSON 数量、未知条目、符号链接和目录权限。另选独立的 `GAIOP_REPORT_RECOVERY_DIR`，确认它不在正式报告根目录内，也不与来源信封或频道发送目录重叠。

禁止读取报告正文、凭据或环境文件秘密值。只记录数量、总字节、最早/最晚时间和稳定原因代码。

## 2. 安装步骤

1. 备份当前应用代码和数据库；不移动或删除任何报告文件。
2. 发布应用代码并构建前端。首次启动只执行幂等表结构迁移，保留所有既有报告与交付记录。
3. 创建恢复目录，属主为 `gaiop:gaiop`、权限建议 `0750`；安装 `deploy/systemd/gaiop-report-retention-cleanup.service` 和 `.timer`。
4. 在 `/etc/gaiop/admin.env` 中配置恢复目录、批次上限和锁路径，必须保持 `GAIOP_REPORT_RETENTION_AUTO_PROCESS=false`。
5. 执行 `systemd-analyze verify`、`systemctl daemon-reload`，可启用 timer 调度，但关闭态 one-shot 只能返回 `auto_process_disabled`。
6. 验证 Admin 服务、报告列表、下载、长期保留标记和空/既有恢复区读取；核对部署前后数据库行数和文件数量完全不变。

未经单独的生产候选核查和启用确认，不得把开关改为 `true`。

## 3. 关闭与回滚

- 关闭：先保持或改回 `GAIOP_REPORT_RETENTION_AUTO_PROCESS=false`，停止并禁用 timer；不删除恢复目录、文件计划或审计。
- 代码回滚：在确认没有 `quarantined/quarantine_pending/*_error` 状态后才回滚旧代码。若已有恢复区报告，必须先使用当前版本完成恢复或保留当前服务进行处置，不能让旧版本扫描恢复目录。
- 数据库新增列和表保持向后兼容，常规代码回滚不删除它们。不得通过回滚脚本删除表、截断记录或清空恢复目录。
- 任一文件与数据库不一致时停止自动处理，保持现场并使用原因代码诊断；不得扩大路径或权限尝试补删。

## 4. 部署后验收

- Admin 服务与既有报告查询、分页、筛选、下载保持正常；隔离态报告不出现在正常列表。
- systemd unit 只声明 `/var/lib/gaiop/admin`、正式报告目录、恢复目录和自身锁目录可写。
- timer 为每日 UTC、`Persistent=true`；并发运行只允许一个实例获得锁。
- 自动开关仍为 `false`，报告文件数、配对 JSON 数和 `report_files/report_deliveries` 行数与部署前一致。

## 5. 首次启用前待确认

首次真实处理必须另行只读汇报实际目录、候选报告组数、实体数、预计字节、最早/最晚时间、长期保留数及所有保护/异常原因。取得确认后才允许启用；本分支不包含生产启用或数据处理。
