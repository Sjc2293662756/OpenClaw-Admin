## 1. 故障现象

钉钉配置对象存在且为启用状态，但运行时检查失败：

```text
id: dingtalk-connector
Status: error
ERROR: plugin failed during register: Error: Cannot find module 'openclaw/plugin-sdk/core'
```

`openclaw channels status` 中没有钉钉频道，只显示飞书和企业微信运行。因此“配置已保存”并不代表钉钉已经接入成功。

## 2. 原因与修复判断

只读预检得到：

- 钉钉插件版本为 `0.8.23`，声明 peer 依赖 `openclaw >=2026.4.9`；
- 当前核心版本为 `2026.5.4`，满足声明范围；
- 当前核心实际导出钉钉使用的 `openclaw/plugin-sdk`、`openclaw/plugin-sdk/channel-entry-contract` 和 `openclaw/plugin-sdk/core`；
- 钉钉插件自己的 `node_modules/openclaw` 不存在，共享插件根目录也没有可供其解析的顶层 `openclaw`；
- 企业微信官方修复后的独立 peer 链接正常工作。

因此本次采取最小修复：不重装钉钉、不修改配置，只在钉钉插件自己的 `node_modules` 下建立指向当前全局核心的 `openclaw` 链接。该做法只适用于已经验证版本范围和导出入口的当前组合，ISO/升级程序不能对所有插件机械复制。

## 4. 备份与修复命令

修复前在 237 创建受保护备份目录：

```text
/home/netinside/.openclaw/backups/gaiop-dingtalk-peer-before-20260720T025733Z
```

目录权限为 `0700`，其中只保存修复前 `openclaw.json`、钉钉 `package.json` 和“链接原本不存在”的状态标记，文件权限为 `0600`；内容未打印、未下载、未进入 Git。

核心修复命令如下：

```bash
plugin_dir='/home/netinside/.openclaw/npm/node_modules/@dingtalk-real-ai/dingtalk-connector'
core_dir='/home/netinside/.npm-global/lib/node_modules/openclaw'
link_path="$plugin_dir/node_modules/openclaw"

test -f "$plugin_dir/package.json"
test -f "$core_dir/package.json"
test ! -e "$link_path"
test ! -L "$link_path"

install -d -m 755 "$plugin_dir/node_modules"
ln -s "$core_dir" "$link_path.gaiop-tmp"
mv -T "$link_path.gaiop-tmp" "$link_path"
```

建立链接后、重启前先验证：

```bash
openclaw plugins inspect dingtalk-connector --runtime
```

返回 `Status: loaded` 后才执行：

```bash
openclaw gateway restart
```

## 6. 回滚命令

如果本次链接导致异常，只允许在确认目标仍是本次创建的精确路径后撤销：

```bash

expected_target='/home/netinside/.npm-global/lib/node_modules/openclaw'
```

本次没有修改频道配置，正常回滚不需要恢复 `openclaw.json`；服务器备份仅作为事故保护，不能打印其中的凭据。
