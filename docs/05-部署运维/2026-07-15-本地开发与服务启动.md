# 本地开发与服务启动

| 属性 | 内容 |
|---|---|
| 创建日期 | 2026-07-15 |
| 状态 | 本地开发基线 |

## 1. 组成

本地至少需要：GAIOP Gateway、GAIOP-Admin 管理服务、Vite 前端。NAPM 可使用可访问的测试数据源。浏览器只访问前端端口，`/api` 由 Vite 代理到管理服务。

## 2. 准备

```powershell
cd D:\杨硕文件\GAIOP\GAIOP\GAIOP-Admin
npm install
Copy-Item .env.example .env
```

随后只在本机 `.env` 填写真实值；`.env` 已忽略提交。不要把真实值复制到文档或聊天记录。

## 3. 启动

```powershell
npm run dev:all
```

也可分别运行：

```powershell
npm run dev:server
npm run dev
```

端口来自 `.env`：`PORT` 为管理服务，`DEV_PORT` 为 Vite。当前本地约定通常由环境决定，不应在源码中假定固定端口。访问 `http://127.0.0.1:<DEV_PORT>/welcome`。

## 4. Gateway 连接

管理服务通过内部兼容变量配置 Gateway WebSocket 和认证。若 Gateway 在麒麟服务器回环地址上，可使用 SSH 本地端口转发，再让管理服务连接本地映射端口。`ssh -N` 成功后不显示命令提示符属于正常现象，窗口需保持运行。

当前 237 本地开发链路为：

```text
前端 127.0.0.1:3002
→ Admin BFF 127.0.0.1:3000
→ 本地 Gateway 隧道 127.0.0.1:3003
→ 237 Gateway 回环端口 18789

Admin BFF
→ 本地告警接收器隧道 127.0.0.1:3004
→ 237 接收器回环端口 19090
```

根目录提供 `启动GAIOP本地开发环境.cmd`、`连接237GAIOP服务.cmd` 和 `Start-Gateway237Tunnel.cmd`。脚本从本机安全存储读取 SSH 连接信息；不得打印、复制或提交其明文。任何由开发代理发起的 237 SSH 连接、隧道、只读查询、配置写入、服务重启或部署，都必须先得到用户对该次操作的明确授权。用户本人双击脚本属于用户操作，不自动授权开发代理执行服务器命令。

## 5. 两个代码目录的本地联调

`GAIOP-Admin` 与相邻 `GAIOP` 共同运行时，需要统一两个共享目标：

```text
GAIOP_ACTIVE_DATA_SOURCE_FILE = D:\杨硕文件\GAIOP\GAIOP\GAIOP\config\runtime-active-data-source.json
GAIOP_REPORTS_DIR             = 双方共同使用的受控报告目录
```

第一项由管理端写入、智能体核心读取；第二项由核心报告 Skill 写入、管理端读取。实际值只写入两个服务各自的本地 `.env`，不要把真实路径和凭据提交仓库。完整关系见[双目录集成关系](../01-总体设计/2026-07-15-GAIOP与GAIOP-Admin职责和集成关系.md)。

## 6. 验证

1. 欢迎页、两个登录入口和退出回欢迎页。
2. 管理服务健康和 Gateway 连接状态。
3. 对话发送、历史打开和删除。
4. 管理员数据源列表、测试和运行源状态。
5. 用户/审计/报告/会话设置页面。
6. 修改代码后执行 `npm run build`。

## 7. 常见问题

- 前端可开但接口失败：确认管理服务端口与 Vite 代理 `PORT` 一致。
- Gateway 离线：确认隧道、WebSocket 地址、Token 和目标实例。
- 数据源接口 503：配置 `DATA_SOURCE_ENCRYPTION_KEY`。
- 敏感配置保存 503：配置 `SENSITIVE_CONFIG_ENCRYPTION_KEY` 或兼容密钥。
- 报告为空：确认管理服务与 Skill 的 `GAIOP_REPORTS_DIR` 完全一致。
- 系统监视器数据显示电脑磁盘：本地部署监测的就是本机，部署麒麟后才监测麒麟。
