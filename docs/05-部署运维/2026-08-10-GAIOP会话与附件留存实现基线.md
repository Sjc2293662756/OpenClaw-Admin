## 2. 活动时间与会话归属

自动留存消费 `sessions.list`，但不会把所有可展示时间都当成删除证据：

- 可接受：`lastInteractionAt`、`lastMessageAt`、`lastUserMessageAt`、`lastAssistantMessageAt`、`lastActivity`，以及带有上述来源标记的 `conversationLastActivity`；
- 不可接受：`updatedAt`、`createdAt`、`sessionStartedAt`。这些字段可能来自后台维护、交付重试或单纯创建，不足以证明真实最后活动；
- 缺少可靠时间时记录 `last_activity_missing` 并保护。当前 Gateway 若只提供 `updatedAt`，该会话不会进入自动标记，必须等正式 API 提供可靠活动字段，不能猜测。

WebChat 只信任 active `workspace_sessions.owner_user_id`。外部频道必须由 Gateway 明确给出单一 source channel 和稳定 peer，才登记为 `channel_peer`。以下任一条件都会保护会话：归属未知、默认共享 `main`/`agent:main:main`、多渠道共享、运行或流式中、有 active run、排队消息、待处理任务或待交付结果。

## 3. 180 天与 7 天状态机

`session_retention_records` 保存策略和状态，不保存正文：

1. 自动标记开启后，真实最后活动严格早于 `now - 180 天` 的标准会话进入 `pending_delete`；恰好 180 天仍保护。
2. `marked_at` 使用本次标记时间，`delete_after = marked_at + 7 天`。
3. 管理员可在会话列表看到“7 天待删除”并取消。取消写入该次活动快照，同一或更早快照不会重复标记；有新的真实活动后重新计算。
4. `long_term` 永不进入自动标记或删除；设置长期保留会取消当前待删除状态，取消长期保留则恢复标准规则。
5. 最终删除前重新读取 Gateway 会话并再次检查时间来源、归属、共享、活动/任务状态、活动快照变化和附件。

`GAIOP_SESSION_RETENTION_AUTO_MARK` 与 `GAIOP_SESSION_RETENTION_AUTO_DELETE` 相互独立，样例和代码默认都为 `false`。`gaiop-admin-session-retention.timer` 是独立每日调度模板；本批没有安装、启用或启动该 unit。

## 4. Gateway 删除与失败一致性

会话实际删除只调用现有正式 RPC：

```json
{ "method": "sessions.delete", "params": { "key": "<sessionKey>", "deleteTranscript": true } }
```

没有直接删除 Gateway JSONL、索引、转录或媒体的代码，也没有文件删除回退。Gateway WebSocket 只有响应 frame `ok=true` 时 `gateway.call` 才成功；随后 Admin 才在一个 SQLite 事务中更新 `session_retention_records` 和 `workspace_sessions`。Gateway 失败时两项会话元数据和全部附件记录保持不变。

普通手工 `/api/rpc` 删除沿用现有归属和角色边界，并新增同一附件阻断。删除成功/失败、自动标记、取消和长期保留写入 `audit_logs` 的 `session_retention` 类别，只含操作者、sessionKey、动作、结果、RPC 方法和稳定错误码，不含聊天正文、附件内容或附件路径。当前核心审计没有自动删除路径，因此满足不少于 3 年保护；未来新增审计清理时必须继续保留这一底线。

## 5. 附件能力与准确缺口

`session_retention_attachments` 只登记明确 sessionKey、受限相对引用、`follow_session`/`temporary` 类别、归属状态和生命周期。`follow_session` 随会话进入或取消待删除；`temporary` 的 `expires_at` 最晚为登记基准后 7 天。

当前 Admin 正式 RPC 清单和现有 Gateway 契约没有 `media.delete`、`attachment.delete` 或等价接口，也没有证明 `sessions.delete` 会原子删除显式登记附件。安全结论是：

- 有登记附件的会话不能执行最终 Gateway 删除；
- 可靠归属附件到期后报告 `attachment_delete_api_unavailable`；
- 无可靠归属附件报告 `attachment_ownership_unverified`；
- 临时附件的 7 天到期已登记，但物理删除能力未实现，不能宣称“最多保存 7 天”已经闭环；
- 不得为了满足期限直接删除媒体文件或放宽路径范围。

因此当前 Gateway 能安全完成“无登记附件会话”的正式删除，不能安全完成附件物理删除。后续只有在 Gateway 提供正式、可验证、与会话一致的附件删除 API 后，才能单独补实现和联调。

## 6. Admin 最小操作与接口

- 会话列表显示待删除、长期保留和附件保护标签。
- 管理员可取消待删除、启用/取消长期保留；审计用户只读，基础/标准没有留存管理 REST 权限。
- `GET /api/session-retention` 返回策略、安全摘要和待删除/长期保留记录。
- `POST /api/session-retention/cancel`、`PUT /api/session-retention/long-term`、`POST /api/session-retention/attachments` 均为管理员专属。
- 附件登记响应只返回内部 id、sessionKey、类别、归属/生命周期和时间，不返回附件引用。
