## 根因与上游证据

- 早期指定会话中的过程文本由 Gateway/OpenClaw 助手回合产生并正式持久化，结构是普通 `assistant` 消息中的 `text + toolCall`，不是 `thinking/reasoning`，也不是 Admin 前端生成。
- 当前新会话的 Gateway 历史仍发送同类 `assistant(text + toolCall)` 回合；后续 `toolResult` 以 `toolCallId` 关联，最终回复是独立的 text-only `assistant` 回合。
