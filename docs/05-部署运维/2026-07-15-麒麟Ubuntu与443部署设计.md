# 麒麟、Ubuntu 与 HTTPS 443 部署设计

| 属性 | 内容 |
|---|---|
| 创建日期 | 2026-07-15 |
| 状态 | 目标部署设计，待正式实施验证 |

## 1. 推荐形态

优先在独立麒麟测试环境采用容器或受控 systemd 服务部署 GAIOP-Admin，并连接同机原生 GAIOP Gateway。开发完成后迁移到 Ubuntu 时保持相同目录、环境变量和反向代理契约。对用户只暴露一个 443。

```text
公网/用户 → HTTPS 443（Nginx）
  ├─ /          → GAIOP-Admin 静态资源或 Node 静态服务
  ├─ /api/*     → 127.0.0.1:<管理服务端口>
  └─ SSE        → 同一 /api 路径，关闭代理缓冲

管理服务 → 127.0.0.1:<Gateway端口>
GAIOP Skills → NAPM HTTPS
```

Gateway 不直接对公网开放。前端和 Gateway 通常属于同一 GAIOP 主机，因此不在页面提供“GAIOP 服务 IP”配置。`GAIOP-Admin` 与 `GAIOP` 的职责、共享文件和联调边界见[双目录集成关系](../01-总体设计/2026-07-15-GAIOP与GAIOP-Admin职责和集成关系.md)。

## 2. 目录建议

```text
/opt/gaiop/admin/app/          # 程序和 dist
/etc/gaiop/admin.env           # 管理服务环境，只读
/var/lib/gaiop/admin/          # SQLite
/var/lib/gaiop/reports/        # 报告共享目录
/run/gaiop/                    # 可重建运行时桥接，或使用 /var/lib 受控路径
/var/log/gaiop/                # 服务日志
```

实际目录可调整，但程序、配置、持久数据、报告和日志必须分离。服务用户不使用 root；配置、桥接和数据库默认仅服务用户读写。

## 3. 构建与运行

- 在兼容环境执行 `npm ci`、`npm run build`。
- 生产运行 `node --env-file=<env> server/index.js` 或容器入口。
- `better-sqlite3`、`node-pty` 含原生依赖，必须在目标 x86_64/Node 版本验证，不直接复制其他平台的 `node_modules`。
- systemd 配置自动重启、工作目录、环境文件、文件权限和启动顺序。

## 4. Nginx 要点

- 443 配置正式证书或企业信任证书；80 仅重定向到 443。
- `/api/events` 等 SSE 禁用缓冲、增加读超时并保持连接。
- 上传大小目前无需为报告开放大文件上传；系统升级实现前不开放升级上传。
- 增加安全响应头、访问日志脱敏和合理请求体限制。

## 5. 持久化与迁移

持久化对象包括 SQLite、报告目录、必要配置和加密密钥。运行时桥接可由数据库运行源重新生成，但其中含明文凭据，备份时需按敏感文件处理。两个服务的 `GAIOP_ACTIVE_DATA_SOURCE_FILE` 与 `GAIOP_REPORTS_DIR` 必须分别指向同一个共享目标。迁移顺序：停写/在线备份 SQLite、同步报告、迁移密钥和环境、启动管理服务、重建运行源、连接 Gateway、冒烟测试。

## 6. 验收

- 公网只需 443，内部管理/Gateway 端口不暴露。
- 登录、对话、SSE、仪表盘和管理接口均通过同一域名。
- 管理服务重启后 Gateway 自动恢复连接；Token 失效行为符合当前设计。
- 运行源真实参与 Skills 查询；报告目录两端一致。
- 麒麟和 Ubuntu 分别验证原生依赖、文件权限、中文路径/时区和服务自启动。
