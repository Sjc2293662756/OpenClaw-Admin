# GAIOP 安全风险整改与回滚方案

| 项目 | 内容 |
|---|---|
| 日期 | 2026-07-20 |
| 状态 | 本地设计草案；未授权、未连接、未修改 237 或任何目标环境 |
| 适用范围 | Gateway、Admin BFF、反向代理、频道插件与 ISO 制作流程 |
| 不在范围 | NAPM 业务策略、客户平台账号权限、实际密码/Token/私钥与未经审批的服务器操作 |

## 1. 目的与已知事实

本方案把当前安全审计发现转化为可审批、可分批实施、可验证、可回滚的变更计划。它不是服务器操作手册，不表示下列目标已经在 237 或 ISO 中生效。

当前已知风险为：

1. 飞书、钉钉和企业微信的可用人员与群组范围由客户在各平台后台管理；GAIOP 必须确保这些对话入口不获得 Admin 配置或运维能力，具体业务工具边界另行设计；
2. Gateway 存在非回环监听、认证与访问速率限制需进一步核验和收口的风险；
3. 频道插件曾因单插件安装重建共享 npm 依赖树，导致其他频道的 `openclaw` peer 链接失效；
4. 组件版本、构建来源和校验值尚未形成可交付的不可变冻结记录。

本方案不假定当前服务器实际配置。任何关于监听地址、认证开关、频道名单、工具权限、插件目录或版本的结论，均须在得到该次只读授权后再以脱敏证据确认。

## 2. 目标状态与不可突破的边界

```text
用户/外部频道
  → HTTPS 443 / 受控反向代理
  → Admin BFF（认证、RBAC、审计）
  → 本机或受控私网 Gateway
  → 固定版本的 GAIOP Skills 与频道插件
```

- 对用户只暴露 443；BFF、Gateway 与 Syslog 接收器默认仅绑定回环或受控私网。
- 外部频道依照最小可用原则限定可访问范围，并将高风险工具能力与开放群策略解耦。
- 浏览器、日志、审计、发布清单和回滚记录均不得包含密码、Token、Secret、私钥、Webhook、NAPM 凭据或完整客户配置。
- 所有生产写操作均需本次明确授权、先备份、后验证；任一关键检查失败即停止并按预定路径回滚。
- 首次验证在克隆/准生产环境完成；客户运行环境不得成为频道/核心升级的首个试验场。

## 3. 决策与审批前置项

以下项目改变客户可用性或外部频道使用方式，不能由开发人员自行假定：

| 决策项 | 需确认内容 | 默认建议 |
|---|---|---|
| 频道准入 | 各频道的私聊、群聊、允许群/人员、应急联系人 | 由客户平台管理员在飞书、钉钉、企业微信后台决定；GAIOP 不维护重复人员或群组白名单 |
| 对话工具边界 | Web 与外部频道可调用的业务工具及其必要业务产物 | 后续单独敲定并做回归；原则上管理操作只保留在认证后的 Web 管理面 |
| 交付网络形态 | 客户采用公网版还是私网版，以及其入口网络能力 | 产品正式同时支持公网版和私网版；两者均使用 BFF 在前、Gateway 在受控内部网络的同一分层 |
| Gateway 网络面 | 是否有受控私网调用方确需直连 Gateway | 默认仅回环；确有需要时使用明确来源限制和独立认证方案 |
| 登录与限流策略 | 可信反代、源 IP 获取、失败阈值、封禁时长、运维豁免方式 | 在反代与服务端分层限流，避免仅依赖前端 |
| 可用性目标 | 可接受的维护窗口、最大中断、恢复时间与回退责任人 | 先在准生产演练，再安排可回退的维护窗口 |
| 密钥与备份 | 保管责任、加密介质、保留期、恢复授权人 | 密钥与业务备份分开加密保存，至少两名授权责任人 |

未完成上述确认时，只能进行本地设计或经授权的只读预检，不得改变 237 行为。

## 4. 整改工作包

### 4.1 外部频道准入与对话/管理面隔离

**已确认产品决策（2026-07-20）：** 飞书、钉钉、企业微信中的人员、私聊、群聊和应用可用范围，均由客户平台管理员在对应平台后台管理。GAIOP 不新增第二套人员或群组白名单，不干预客户组织权限。

**目标：** 无论客户在平台侧如何配置机器人可用范围，外部频道都只作为 GAIOP 对话入口，不能获得 Admin 配置、部署、服务管理、插件管理、凭据读取或任意命令能力。Web 对话也遵循同一管理面隔离原则。

实施设计：

1. 不读取、不保存、不维护外部平台的人员或群组名单；部署与客户管理员只需按各平台自身能力配置机器人可用范围。
2. 把“谁能发消息”与“对话能做什么”分离：前者属于客户平台后台，后者属于 GAIOP/Gateway 的统一对话能力边界。
3. 当前不仓促增加全局工具拦截。先完成业务工具、报告生成、数据包分析等必要内部动作的能力矩阵和 Web/三频道回归场景，避免误伤 Skill。
4. 矩阵确认后，再决定 Gateway 级工具白名单与插件语义保护的组合方式；管理操作始终保留在认证后的 Admin BFF/Web 管理面。

**备份与回滚：** 本项不计划写入外部平台的人员或群组策略。将来若因对话工具边界需要调整 Gateway 配置，才按单独审批流程备份 Gateway 配置、版本清单和启用状态；失败时恢复同一配置快照并验证原有频道消息路径。

**通过条件：** 客户平台允许的用户仍可完成已批准的 GAIOP 对话；外部与 Web 对话均不能进入 Admin 或运维能力；GAIOP 不保存外部人员/群组策略；BFF/Gateway 审计仅记录动作结果，不泄露内容或凭据。

### 4.2 Gateway 网络面、认证与速率限制

**已确认产品决策（2026-07-20）：** GAIOP 正式支持公网版和私网版。两种形态均保持“用户 HTTPS 入口 → Admin BFF → 受控内部 Gateway”的一致产品边界；差异仅在最外层的客户网络、证书、反向代理、VPN/WAF 和访问策略。该决策不表示任何现有服务器已经完成相应网络配置。

**目标：** Gateway 不被公网直接访问，所有对外入口经过 TLS、认证、请求体限制与速率限制。

实施设计：

1. 经授权只读确认 Gateway、BFF、接收器与反向代理的监听地址、端口暴露、服务依赖和健康检查，不读取或输出秘密字段。
2. 将 Gateway、BFF、接收器设置为回环或经审批的私网地址；Nginx 仅暴露 HTTPS 443，80 仅做跳转（如交付方案采用该入口）。
3. 在受控反向代理实施登录、写操作和 SSE 的差异化连接/请求限制；服务端继续保留认证、RBAC、输入大小和超时边界，不能由反代单独承担安全控制。
4. 对 Gateway 管理或 RPC 能力使用独立认证，禁止把 Gateway Token 暴露给浏览器；密钥仅从部署侧受限环境文件提供。
5. 先在准生产对正常登录、登录失败、SSE、管理员写操作、限流命中和服务重启做验证，再安排生产切换。

**备份与回滚：** 版本化保存当前反向代理和服务单元配置、监听策略、服务状态和校验和；若切换后健康检查、登录、SSE 或内部 BFF→Gateway 调用失败，恢复上一版本配置并重载/重启受影响服务，复测 443、BFF 健康和 Gateway 连通性。

**通过条件：** 外部扫描只能发现批准的 HTTPS 入口；内部服务不直接暴露；正常业务与 SSE 可用；异常认证和突发请求被拒绝或受限且不影响已建立的合理会话。

### 4.3 频道插件与 Gateway 供应链冻结

**已确认产品决策（2026-07-20）：** Gateway 核心、频道插件及其依赖只能通过 GAIOP 系统升级模块升级。客户不能从频道页面、命令行、插件安装器或单独升级包安装/升级任何频道插件；即使升级目标只有一个频道，也必须由系统升级模块按完整兼容组合执行备份、验证和失败整体回滚。该目标能力尚未实现，当前系统升级模块不得宣称已经支持核心或频道插件升级。

**目标：** 单个频道插件变更不会在运行目录破坏其他频道，所有候选版本可精确复现和整体回退。

实施设计：

1. 系统升级模块接受受控升级包并读取兼容矩阵；它是唯一的核心/频道插件升级入口，升级页面之外不提供安装或升级动作。
2. 为 Gateway、飞书、钉钉、企业微信记录精确版本、来源、包校验和、`peerDependencies`、入口、插件 ID 与兼容矩阵；发布清单不记录凭据。
3. 在干净且版本化的临时目录安装完整候选组合，禁止在客户运行目录逐个原地安装或使用 `latest`。
4. 静态核验全部插件入口、版本、peer 依赖和索引，再切换候选目录并重启 Gateway。
5. 检查 Gateway RPC、所有交付插件、所有升级前已启用频道和真实消息；钉钉 CLI 深探针结果必须结合真实消息验证解释，不能单独作为失败或成功结论。
6. 任一失败即恢复旧程序、完整插件依赖目录与配置快照，重启并再次执行全频道验证。

**备份与回滚：** 备份必须覆盖当前程序版本、完整插件依赖树/索引、服务配置、频道配置与持久化边界；不得只备份目标插件。回滚以原子目录切换或等价方式恢复整套兼容组合，禁止在故障状态临时补装单个插件。

**通过条件：** 冻结记录可复现构建；三插件均处于可加载状态；已启用频道恢复运行并经真实消息验证；人为制造兼容或入口失败时能自动回到旧组合。

### 4.4 ISO 与持久化恢复基线

**目标：** ISO 在无开发隧道和人工窗口条件下，能够恢复服务、持久数据与最小安全边界。

实施设计：

1. 冻结两仓提交、Node/Gateway/插件精确版本、ISO 校验和与构建证据。
2. 固定独立服务账户、程序/配置/SQLite/报告/告警/运行时桥接/日志目录及最小权限。
3. 将 `/etc/gaiop/*.env`、密钥托管、备份介质、保留期和恢复授权作为交付审批输入，不写入仓库。
4. 在准生产完成断电重启、网络短断、备份恢复、443、SSE、告警、报告与频道恢复测试后，才冻结候选 ISO。

**备份与回滚：** 备份 Admin SQLite、告警事件和接收器状态、报告目录、运行时桥接及必要密钥材料；密钥与数据分开加密。ISO 或程序回退不得覆盖已产生的业务持久化数据，恢复后必须验证服务账户权限和共享目录契约。

**通过条件：** systemd 依序自恢复；仅 443 对用户可达；恢复后的数据源、报告、告警和频道满足既定验收矩阵。

## 5. 分阶段执行与停止条件

| 阶段 | 内容 | 环境 | 停止/回滚条件 |
|---|---|---|---|
| 0 | 设计评审、风险确认、回滚演练计划与责任人确认 | 本地 | 任一决策项未确认，不进入服务器预检 |
| 1 | 脱敏只读预检、基线取证与备份演练 | 237（逐次授权） | 实际拓扑与设计不一致、无法完成安全备份或证据含敏感信息 |
| 2 | 频道/网络策略在准生产验证 | 克隆或准生产 | 正常对话、SSE、任一频道或 Gateway 健康检查失败 |
| 3 | 生产小批次变更与观察 | 237（逐次授权） | 触发预设错误阈值、任一业务验收失败或维护窗口到期 |
| 4 | ISO 冻结与恢复验收 | 候选 ISO/准生产 | 重启、恢复、权限或版本一致性未通过 |

每次 237 操作前，执行者必须向用户说明本次命令、目的、影响范围、备份位置和回滚命令并获得明确授权；完成后在 `docs/05-部署运维` 新建或更新脱敏运维记录，写明时间、现象、诊断/变更命令、非敏感结果、验证、回滚与未完成项。

## 6. 授权后只读预检清单

以下仅是未来申请授权时应说明的检查目的，不构成当前可执行命令，也不允许输出机密配置：

| 检查目的 | 允许记录的证据 | 禁止输出 |
|---|---|---|
| 监听与暴露面 | 服务名、监听类别（回环/私网/公网）、端口、进程健康状态 | IP、完整反代配置、Token、证书私钥 |
| Gateway 认证与限流 | 开关是否存在、策略状态、非敏感错误码 | Gateway Token、完整认证头、Cookie |
| 频道策略与工具面 | 频道标识、启用状态、策略类别、工具类别 | appSecret、botId、Secret、平台用户名单或消息内容 |
| 插件基线 | 包名、精确版本、校验和、peer 范围、加载状态 | npm 用户目录中的凭据、完整客户配置 |
| 备份可恢复性 | 备份编号、时间、权限检查结果、恢复演练结论 | 备份文件内容、密钥材料、报告正文 |

## 7. 验收证据与文档联动

安全整改完成不能仅以“配置已保存”判定。交付证据至少包括：批准记录、脱敏基线、备份编号、版本与校验清单、变更步骤、健康检查、四角色直接接口结果、443/SSE、三频道真实消息、断网重连、备份恢复和一次失败回滚演练结果。

验收项与[测试策略与模块验收矩阵](../06-测试验收/2026-07-15-测试策略与模块验收矩阵.md)、[交付前权限与验收执行清单](../06-测试验收/2026-07-18-交付前权限与验收执行清单.md)、[ISO 交付运行基线](2026-07-18-ISO交付运行基线与冻结准备.md)和[频道插件依赖隔离与升级保护规划](2026-07-20-频道插件依赖隔离与升级保护规划.md)共同执行。
