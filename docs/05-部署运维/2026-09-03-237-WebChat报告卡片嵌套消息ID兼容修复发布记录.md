# 2026-09-03 237 WebChat 报告卡片嵌套消息 ID 兼容修复发布记录

## 结论

本次故障的直接根因已确认在 GAIOP-Admin WebChat 消息归一化层：生产 Gateway 的 `chat.history` 返回了消息 envelope，持久消息字段位于嵌套 `message` 对象中，真实持久消息 ID 位于 `message.__openclaw.id`。旧代码只读取 envelope 顶层 ID，正文虽然可以显示，但 `report_files.source_message_id` 无法与对应 assistant 完成消息相等，独立报告卡片因此没有进入 transcript。

报告生成、正式归档、后台登记、用户归属和下载权限在本次故障会话中均有生产证据，不是本次卡片消失的首个失配层。

## 故障证据

- 会话：`agent:main:main:dm:webchat-e883c381016743bfb5996af9ed053394`。
- 会话登记为 active，归属当前用户；非本人报告在列表和下载接口继续不可见。
- Gateway `chat.history` 的 assistant 完成消息使用嵌套 envelope；来源持久消息 ID 为 `134ba389-82a2-4740-8ff6-c8d95a1083ce`。顶层 ID 是传输 envelope ID，不能用于报告来源关联。
- 对应报告状态为 `ready`；正式报告和配对审计 JSON 均为普通文件，登记大小与文件大小一致。
- `report_files` 的 `source_session_id`、`source_user_id`、`source_message_id` 与该会话、当前用户和来源消息一致；本人列表查询可见，非本人查询仍隐藏。
- 因此首次失配发生在“消息 ID 归一化 -> 报告与完成消息关联”，而不是“文件生成 -> 登记”或权限过滤。

## 最小修复

提交：`0c9c523b7b55518913a634471ca9f69030ea000c`（`fix(webchat): preserve nested gateway message identity`）

修改范围限定在 GAIOP-Admin：

- `src/api/rpc-client.ts`：处理嵌套 `message`，按优先级读取嵌套 `id`、`messageId`、`message_id`、`__openclaw.id` 和明确 metadata ID，再回退到顶层字段。
- `src/stores/chat.ts`：实时 envelope 使用同一归一化规则；过滤只有 envelope `type` 的伪消息，避免传输 ID 与内层持久消息重复。
- 为顶层传输 ID 与嵌套持久 ID 不同、实时事件经历史回拉后仍稳定关联、不重复和不跨会话分别保留回归测试。
