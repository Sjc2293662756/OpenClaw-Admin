# 2026-08-22 Admin 报告后台登记修复记录

## 1. 结论与当前状态

本批修复 Admin 报告“文件已经生成并被报告归因 Sidecar 捕获，但没有及时进入 Admin `report_files` 台账”的问题。

根因不是留存期限改变，也不是报告被删除，而是原来的登记同步主要挂在 `GET /api/reports` 请求上：只有管理员打开报告列表时，Admin 才会触发一次登记。报告在后台生成后，如果没有人打开列表，就会暂时处于“文件存在、Sidecar 有索引、数据库未登记”的状态。留存服务对未登记文件默认保护，因此没有误删，但这批报告没有进入完整的 365 天在线留存和 7 天恢复区流程。

本批代码已经完成并通过本地验证，但**尚未提交到远端，也尚未发布 237**。本记录不能作为生产已部署证明；生产发布仍需取得明确执行指令后，按现有受控发布脚本单独执行。

## 2. 修复范围

### 2.1 Admin/BFF

- 新增 `server/report-registry-sync.js`。
- Admin 启动完成路由注册后立即执行一次报告和交付登记同步。
- 默认每 30 秒执行一次后台同步，可通过 `GAIOP_REPORT_REGISTRY_SYNC_INTERVAL_MS` 调整，但最小间隔为 5 秒。
- 同步复用现有 `syncGeneratedReports()` 和 `syncReportDeliveries()`，只写 Admin 自己的 `wizard.db`，不新增第二套报告登记规则。
- 单次同步失败只记录安全错误并继续运行，不使 Admin 进程退出。
- Admin 收到 `SIGINT` 或 `SIGTERM` 时停止定时器。

## 3. 代码安全边界

后台同步只负责把能够由现有报告登记逻辑可靠配对的报告和审计文件写入 Admin 台账。未知文件、格式错误、路径异常、配对不完整或归属不明确的内容继续保护；同步失败也不会触发删除。

报告留存任务仍然是另一条独立链路：它只处理已登记、满足期限、通过实体和审计配对检查的报告组。新增后台同步不会把 Admin 变成全盘清理器，也不会越过 GAIOP 后端和 OpenClaw 的所有权边界。
