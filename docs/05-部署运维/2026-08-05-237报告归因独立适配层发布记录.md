# 2026-08-05 237 报告归因独立适配层发布记录

## 1. 结论

本次将报告来源登记从报告 Skill 和同事维护的后端插件中解耦，改为独立 Sidecar 适配层。报告生成逻辑、OpenClaw 核心、频道插件均未修改；曾由本分支修改的 `ReportStorageService.js` 已恢复为当前同事 `main` 基线文件。

237 当前闭环如下：

1. Sidecar 每 3 秒增量读取 OpenClaw 会话记录，只接受可唯一验证的报告/审计配对；
2. 正式工具结果优先使用 `reportId` 或明确路径；历史 `exec` 生成仅在回执文件名、受控目录实体和审计配对唯一时登记；
3. 旧输出目录中的报告与审计以原子复制方式进入正式目录 `_sidecar/<文件哈希>/`，原文件不删除、不改写；
4. 来源信息写入独立索引 `/var/lib/gaiop/report-attribution/index.json`，不改报告和审计 JSON；
5. Admin BFF 同步报告列表时合并该索引，审计原有来源字段始终优先；
6. 报告文件管理页面每 5 秒后台刷新，通常在生成完成后的 3 至 8 秒内可见；
7. 升级服务在每次升级的冒烟阶段检查索引契约和 30 秒新鲜度，Sidecar 停止时升级失败并进入既有回滚流程。

Sidecar 是 `netinside` 用户级 systemd 服务，不监听网络端口；Admin、Gateway、升级服务的公网边界没有变化。

## 2. 根因

问题不是单一前端故障，而是四层契约不一致：

- 同事当前后端的公开工具结果只保证 `reportId`，OpenClaw 持久化历史还可能仅保留文本或 `exec` 回执，不保证保存服务器 `filePath/auditPath`；
- 报告 Skill 的同事基线默认写旧输出目录，而报告管理器只扫描正式目录；
- 旧审计 JSON 不包含来源用户、渠道和会话字段；
- BFF 对已迁移副本仍按审计中的旧相对路径校验，且同一 `reportId` 已登记时会发生重复 ID 冲突。

因此只改前端刷新、只扫目录、继续向 Skill 塞来源参数或继续修改后端插件都不能稳定闭环。

## 3. 实现边界

- 未修改 `GAIOP-latest` 工作树或远端分支；
- 未修改报告 Skill、OpenClaw 核心或频道插件；
- Sidecar 仅读取会话索引、会话 JSONL、Web 来源快照和两个受控报告目录；
- 不读取来源签名密钥、Token、密码或 `.env` 内容；
- `exec` 回执不能唯一落到一个报告/审计配对时拒绝登记，不按“最近文件”猜测；仅在多个同名历史候选中使用 15 分钟生成时间窗口且结果唯一时接受；
- BFF 只用 Sidecar 补空字段，不覆盖审计已经声明的来源；
- 用户级服务工作副本位于 `/home/netinside/.local/lib/gaiop-report-attribution`，不会因 Admin 发布目录权限或切换而失效。
