## 1. 现象与根因

237 Gateway 返回的默认运行会话键为 `agent:main:main`，而 Admin BFF 原有的历史共享会话保护只识别简写 `main`。这导致：

1. 前端虽然把两种键都显示为“历史默认会话”，后端却不会把完整键转入本地退休分支；
2. 用户点击删除时，请求会继续发给 OpenClaw，因默认会话受保护而失败；
3. 该记录没有真实消息活动时间，只有 Gateway 后台维护产生的 `updatedAt`；
4. 工作台对空活动时间使用 `Date.parse('')` 排序，结果为 `NaN`，记录会保留 Gateway 原始顺序并可能出现在顶部。

发布前只读核对确认：

- Gateway 共返回 55 条会话；
- 默认记录键为 `agent:main:main`；
- 真实消息活动字段均为空，`updatedAt` 为 2026-07-29 12:22:30（UTC+8）；
- `hidden_legacy_sessions` 没有对应退休标记；
- `workspace_sessions` 没有把该系统记录登记为用户 WebChat；
- 237 已部署代码不支持完整默认键。

## 2. 修复内容

1. BFF 将 `main` 与 `agent:main:main` 统一识别为 OpenClaw 历史默认运行会话。
2. 对完整默认键执行删除时，仅写入 Admin 本地 `hidden_legacy_sessions`，不调用 Gateway 删除，不修改 OpenClaw 会话存储。
3. 对话工作台历史列表无条件排除默认运行会话；OpenClaw 仍可供系统事件、定时任务和其它默认运行入口使用。
4. 新增统一会话活动时间比较器；BFF 优先使用专用消息活动字段，普通会话在这些字段缺失时使用 Gateway 当前唯一覆盖完整的 `updatedAt`。
5. `main`/`agent:main:main` 不使用 `updatedAt` 且不进入工作台历史，避免后台维护再次造成默认会话置顶。
6. 保留 `agent:main:main:dm:webchat-*` 用户专属会话，不得被默认键规则误过滤。

需要回滚时：

2. 如需撤销本地退休标记，先停止 Admin，并使用退休前数据库备份恢复 `wizard.db`；

不得以回滚本修复为由覆盖报告目录、OpenClaw 会话目录、频道插件或其它运行数据。
