## 1. 发布前事实

- Admin 已配置正式报告目录 `/var/lib/gaiop/reports`，但该目录为空。
- 实际运行的 `openclaw-gateway.service` 使用旧报告 Skill：不支持 `GAIOP_REPORTS_DIR`，也未将相对实体/审计路径写入审计 JSON。
- 旧输出目录保留 167 组可配对报告，未直接暴露给 Admin。
- 现有 Gateway 服务账户 `netinside` 无法访问正式目录；`gaiop` 服务账户可以访问。

完整只读证据见[报告存储只读核对记录](2026-07-22-237报告存储只读核对记录.md)。

## 2. 备份与回滚设计

每个尝试批次均先在受保护目录备份：

1. 运行中完整报告 Skill（其中包含旧输出目录与历史报告）；
2. `/var/lib/gaiop` 和 `/var/lib/gaiop/reports` 的 ACL；
3. Gateway 用户服务的报告目录环境覆盖文件（若原本存在）。

任一阶段失败时，固定脚本自动恢复旧 Skill、两处 ACL、原环境覆盖文件，并重新加载/重启原 Gateway 服务；测试报告若已生成，只删除该次脚本记录的精确实体和审计 JSON，不清理目录内其他文件。

手动回滚须在获得服务器写操作授权后，按以下顺序执行：从最终备份恢复完整报告 Skill，恢复两份 ACL，恢复或删除本次环境覆盖文件，执行用户级 systemd reload/restart，再确认 Gateway active 与旧输出目录可用。不得删除旧输出目录或 167 组历史报告。

## 3. 实施内容

使用本地 `GAIOP-latest` 中的 `openclaw-napm-report` 源码、模板和引用文档构建部署包；部署包刻意不包含 `output`，以避免覆盖服务器既有报告。

服务器侧变更仅包括：

- 替换当前报告 Skill 为包含 `GAIOP_REPORTS_DIR`、用户/报告类型目录分层和审计相对路径的版本；
- 对 `/var/lib/gaiop` 为 `netinside` 增加仅可穿过的最小 ACL，对 `/var/lib/gaiop/reports` 增加读写和默认继承 ACL；
- 为 `openclaw-gateway.service` 新增仅包含正式报告目录的用户级 systemd 覆盖；
- reload 并重启现有 OpenClaw Gateway 用户服务；
- 生成一份不含客户数据的快速报告，验证正式目录写入和实体/审计 JSON 配对。

未修改 NAPM 查询 Skill、告警 Skill、频道插件、Admin BFF 代码、数据源配置或历史报告内容。

## 4. 中间失败与自动回滚

| 批次 | 失败阶段 | 原因 | 结果 |
|---|---|---|---|
| `20260722T032451Z` | `DIRECTORY_ACCESS` | 仅授权报告子目录不足以穿过上级 `/var/lib/gaiop` 目录 | 自动恢复原 ACL 与服务状态；未切换 Skill、未生成测试报告 |
| `20260722T032611Z` | `SMOKE_REPORT` | 测试快速报告错误地传入空 `sections`，不符合既有输入契约 | 自动恢复旧 Skill、ACL 和环境覆盖；未保留正式目录测试文件 |

两次失败均未改变最终运行状态，保留备份以供追溯。
