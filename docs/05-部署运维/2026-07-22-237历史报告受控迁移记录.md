## 1. 迁移边界

- 旧目录：当前 Gateway Skill 的历史输出目录；迁移过程只读，不移动、不删除、不修改其中任何文件。
- 正式目录：`/var/lib/gaiop/reports`；仅新增经过配对验证的报告实体和新的最小审计 JSON。
- 旧审计中的用户字段未作为可信归属依据。全部历史导入项写入 `_unattributed` 分区，`sourceUserId` 固定为 `_unattributed`，因此只对管理员可见。
- 不重启 Admin BFF、Gateway、Syslog 接收器；不改数据源、频道配置、环境变量或公网路由。

## 3. 备份、执行与自动回滚

成功批次开始前保存正式目录的递归 ACL 和本批次迁移清单。清单使用不可预测的指纹文件名，仅在服务器受保护备份目录中保存，用于精确验证与回滚；不向客户端返回历史报告名称或内容。

每个候选项均执行：

1. 复制旧报告到正式目录的 `_unattributed/<报告类型>/`；
2. 生成带 `relativeFilePath`、`relativeAuditPath`、稳定迁移指纹和原始生成时间的新审计 JSON；
3. 验证实体与审计 JSON 的相对路径、配对和管理员专属归属；
4. 以 BFF 服务账户运行同一归档扫描逻辑（使用内存数据库，不写 SQLite）验证可导入。

任何完成标记之前的失败都会按迁移清单删除本次新增副本、恢复迁移前 ACL，并保留旧目录。曾自动回滚的中间批次为 `20260722T044358Z`、`20260722T044453Z` 与 `20260722T044540Z`；原因分别是验证探针的本地脚本兼容性问题，均未修改旧目录或保留新增报告。

## 5. 回滚方法

迁移后的回滚必须先取得新的服务器写操作授权。回滚应使用本批次备份中的 `migration-plan.json` 精确删除本批次新增的正式报告实体与审计 JSON，并使用 `formal-reports-recursive.acl` 恢复迁移前 ACL；旧 Gateway 目录不参与删除或覆盖。

若 BFF 已在迁移后登记了报告 SQLite 记录，回滚还必须在停止 BFF 并备份 SQLite 后，按迁移清单中的 `stored_name` 精确删除对应 `report_files` 行，再启动 BFF 并复核回环监听、Gateway 连接、报告目录配对与列表响应。不得使用目录级清理或通配删除。

## 6. 使用说明与未完成项

- 管理员刷新“报告文件管理”后可看到历史导入项；如报告生成时间早于当前筛选窗口，请在页面选择“自定义”时间范围后查看。
- 当前历史报告保持管理员专属。将来如需分配给普通用户，必须先设计可审计的归属确认流程，不能根据未签名的旧审计字段直接开放。
- 真实 Web/Gateway 来源签名、会话归属和新报告的自动用户隔离仍按既有路线图继续联调；本次迁移不代表这些后续契约已完成。
