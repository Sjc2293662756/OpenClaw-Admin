## 1. 需求与最终行为

本批次将基础用户从原先的“多个管理页面可读、对话只读”调整为“仅使用对话工作台和本人改密”。最终行为如下：

- 登录后可进入 `/workspace`，可新建对话、向本人会话发送消息、停止生成、继续历史对话，并可在工作台左侧删除本人会话；
- 工作台左侧历史只显示 `workspace_sessions.owner_user_id` 属于当前用户且状态为 active 的 WebChat 会话，默认运行会话和其他用户会话不返回；
- 工作台左下角头像菜单保留“修改密码”和“退出登录”；基础用户不显示“管理控制台”入口；
- 基础用户直接访问仪表盘、告警、独立会话管理、报告、频道、Skills、系统设置及其他管理页面时进入统一“无访问权限”页；
- 标准、审计和管理员的既有页面与业务权限不因本批次改变。

## 2. 服务端强制边界

本次不是仅隐藏前端入口。基础用户请求在通用认证后先经过 `BASIC_WORKSPACE_ONLY` REST 边界：

| 接口 | 基础用户结果 | 约束 |
|---|---|---|
| 认证、退出、`GET /api/auth/check` | 允许 | 沿用登录、过期和首次改密规则 |
| `GET /api/health` | 公开健康摘要 | 不返回敏感配置 |
| `POST /api/workspace/sessions` | 允许 | 服务端创建随机 WebChat key 并登记当前用户归属 |
| `POST /api/rpc` | 进入 RPC 白名单 | 仍需通过方法和会话归属双重校验 |
| `GET /api/events` | 允许 | SSE 仅投递当前用户可访问 sessionKey 的事件 |
| `GET /api/media` | 本人会话 | 必须携带并通过 `X-GAIOP-Session-Key` 归属校验 |
| `PUT /api/users/<本人ID>/password` | 允许 | 路径用户必须等于当前登录用户，且校验当前密码 |
| 其他业务 REST | `403 BASIC_WORKSPACE_ONLY` | 在管理 Router 前拒绝并写入安全审计摘要 |

基础用户 Gateway RPC 精确允许：

- 本人会话读：`sessions.list/get/history/usage`、对应单数别名、`chat.history` 和 `usage.sessions`；
- 工作台对话：`agent`、`chat.send`、`chat.abort`、`agent.abort`；
- 工作台历史删除：`sessions.delete`、`session.delete`；
- 基础连接状态：`status`、`health`。

频道、插件、Skills、全局 Usage、系统监控、配置、任务、模型、智能体、导出及其他管理 RPC 对基础用户全部拒绝。所有会话范围 RPC 在转发 Gateway 前执行 `ensureWorkspaceSessionAccess`；列表和 Usage 在返回前按 `listOwnedWorkspaceSessionKeys` 过滤，因此直接构造他人 sessionKey 也不能绕过。
