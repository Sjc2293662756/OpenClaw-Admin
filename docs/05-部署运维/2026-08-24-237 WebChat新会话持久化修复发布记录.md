# 2026-08-24 237 WebChat 新会话持久化修复发布记录

## 1. 问题

WebChat 首次发送长报告请求时，实时内容可以显示，但切换会话或刷新页面后，消息和左侧历史会话消失。普通短问答偶尔正常，导致问题看起来像报告渲染异常。

## 2. 根因

工作台首条消息使用了“Admin BFF 登记会话后直接发送正式消息”的路径，没有执行项目原有的 Gateway `/new` 会话初始化。Gateway 可以通过实时事件暂时返回消息，但没有稳定的 `sessions.list`/`chat.history` 记录，页面刷新后无法回放。

这不是报告内容、Markdown 渲染或存储清理问题。其他入口已经使用统一的 `sessionStore.createSession()` 流程，因此本次只修正 ChatPage 的新工作台入口。

## 3. 修复

- ChatPage 首次发送改为调用 `sessionStore.createSession({})`；
- 保持现有顺序：BFF 登记归属 -> Gateway `/new` 初始化并持久化 -> 发送首条正式需求；
- 不新增 Gateway 协议，不修改 OpenClaw 核心、频道插件或报告存储；
- 增加会话 store 回归测试，锁定新会话返回前必须完成 `/new` 初始化。

## 4. 验证

- `npm run build`：通过；
- `src/stores/session.test.ts`、`src/stores/chat.test.ts`：通过（17 项）；
- `git diff --check`：通过；
- 完整 Vitest 中已有 `server/lib/session-ownership-service.test.js` 的 10 项因当前 worktree 缺少 `better-sqlite3` Node 24 原生绑定文件失败，非本次改动引入，前端及会话相关测试不受影响。

发布后使用新 WebChat 会话验收：

1. 发送普通问题和“给我回溯238web 最近7天的综述报告！”；
2. 等待实时回复后切换到另一会话，再切回；
3. 刷新页面；
4. 确认左侧仍有该会话，`chat.history` 能回放用户消息和助手报告，且不会回到欢迎页空白状态。
