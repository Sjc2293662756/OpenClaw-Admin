## 1. 原因

237 正式报告目录、审计 JSON 成对归档、Admin 扫描和 SQLite 架构均正常，但 Admin 未配置报告来源签名密钥。BFF 因此不会向 Web `chat.send` 注入可信来源信封，Gateway/报告 Skill 无法写入来源渠道、用户、会话和数据源。

## 2. 发布内容

- 更新 Gateway 根插件的报告来源追踪逻辑：Web 使用 Admin 签名信封；飞书、钉钉、企业微信从 Gateway 会话上下文提取渠道、用户和会话归属。
- 更新报告输入契约，使来源渠道、渠道用户、来源会话和来源数据源写入正式报告审计 JSON。
- 更新 237 Admin 前端构建：报告文件管理列表移除“触发消息”列，保留来源渠道、来源用户、来源会话、来源数据源。
- 在服务器本地生成并配置 Admin/Gateway 共用的报告来源签名密钥。密钥未输出、未写入本地文件、未进入 Git 或本文档。

## 3. 备份与回滚

成功批次在受保护目录创建了以下范围的备份：Admin 前端构建目录、Gateway 根插件、报告输入契约、Admin 环境文件和 Gateway 来源追踪 drop-in。发布脚本在预检、切换、重启或健康验证任一步失败时自动恢复这些文件并恢复原服务状态。

本次两次未完成尝试均已自动回滚：第一次因 user-systemd 环境读取方式导致验证误判，第二次因 Admin 冷启动窗口过早进行健康检查。最终批次改为验证受保护的 drop-in 文件，并最多等待 120 秒检查 Admin 回环健康端点后完成。
