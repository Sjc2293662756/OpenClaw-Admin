## 根因

新版 Gateway 对 WebChat 发送会从 `chat.send` 兼容回退到带 `sessionKey` 的 `agent`。原 BFF 只在 `chat.send` 成功后写入 `workspace_sessions.session_title`，因此对话实际成功，但标题没有保存，页面只能回退显示“GAIOP Web Chat”。

同时，新版 Gateway 历史中的用户正文可能带 `[Mon 2026-07-27 11:20 GMT+8]` 时间信封；旧标题解析器没有过滤该前缀，并且会把 `/status` 等控制命令当成标题。

修复前只读诊断：

- WebChat 登记会话：20
- 已直接写入工作区标题：4
- 历史标题表：8
- Gateway WebChat 会话：26
- Gateway 中可读取首条用户内容的会话：24

## 修复内容

- 将 `agent + sessionKey` 识别为 WebChat 兼容发送路径，沿用原有会话归属校验。
- `chat.send` 和带会话标识的 `agent` 成功后均写入首条真实用户请求标题。
- 严格过滤 Gateway 时间信封。
- 忽略 `/status`、`/new` 等控制命令，等待后续真实请求成为标题。
- 历史恢复只覆盖空标题或控制命令占位标题，不覆盖已有正常标题。
- 无真实用户请求的控制会话继续使用页面默认名称，不展示控制命令。
