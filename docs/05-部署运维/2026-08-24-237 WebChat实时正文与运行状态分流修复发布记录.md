# 237 WebChat 实时正文与运行状态分流修复发布记录

日期：2026-08-24

## 1. 问题与生产证据

用户在会话 `agent:main:main:dm:webchat-288e17f63044441c9bbb10e168f84f41` 生成 238web 最近 7 天综述报告时，页面实时阶段反复追加“报告已生成”等旧内容；刷新后重复内容消失，权威历史恢复正常。

237 只读核查确认：Gateway transcript 只有一个用户回合、一次 `napm-summary`、一次 `napm-report-export`、三个助手回合和两个工具结果，持久化内容不存在重复哈希。GAIOP 后端去重正常，重复只存在于 Admin 浏览器的实时投影。

## 2. 根因

OpenClaw 在同一次运行中会发出两类实时数据：

- `chat`：面向会话正文的累计快照，同一 run 的新快照应替换旧快照；
- `agent`、`tool`、`model`：面向运行状态、模型阶段和工具执行的遥测，不属于会话正文。

此前 Admin 将两类数据都递归提取为助手正文，并在内容不是前缀时直接拼接。报告包含多个工具阶段，低层 `agent` 文本会在阶段切换时重新开始，因而形成“旧内容 + 新内容 + 再次旧内容”的长串重复。刷新后页面重新读取未损坏的 Gateway transcript，所以又恢复正常。

这不是报告文件、报告留存、来源归因或后端去重故障，也不是正常的流式输出现象。

## 3. 第一阶段修复

本次只完成数据职责分流：

1. 会话正文只接收 `chat` / `chat.*` 事件；store 层和两个页面入口均设硬边界。
2. `agent`、`tool`、`model` 继续更新运行状态和工具进度，但不再进入 transcript 正文。
3. 同一 run 的 `chat.delta` 使用固定临时消息 ID；累计快照只替换同一个气泡，不再拼接到工具调用前的持久化助手消息。
4. 运行结束后停止保护临时投影；下一次 `chat.history` 以 Gateway 持久化 transcript 为唯一权威，防止临时内容跨切换或刷新残留。
5. 历史回拉期间仅保护本地待持久化的用户占位消息和当前正在进行的一个 `chat` 流，不再保护任意合成助手消息。

默认交互保持为：流式正文开启、运行状态显示、工具详情默认收起。后续第二阶段再在高级配置中增加显式开关；“运行过程”仅指可审计的状态和工具步骤，不展示模型隐藏推理文本。

## 8. 17:43 现场记录与规范投影补充修正

用户在 17:43 使用新会话发送“给我回溯238web 最近3天的综述报告！”，现场复制内容仍显示大量逐字累计和阶段重置文本。对应会话为 `agent:main:main:dm:webchat-e8352f4cf89142de9344b06296a4f7bb`。237 只读核查确认该键同时存在于 Admin 和 Gateway、Gateway transcript 实体存在，因此本次现象不属于建会话、历史持久化、报告文件或来源登记故障。

现场记录暴露了第一阶段剩余的协议归一化漏项：

- `chat` 的 `runId` 和 `state` 可能位于 `payload/data` 等内层封装，第一版只从顶层读取；
- 同一个 `chat` 事件可能同时携带累计 `message` 和短 `delta`，通用递归正文提取会把两者都当作候选消息；
- 当运行字段未识别时，实时消息没有稳定投影 ID，仍可能进入历史的相邻正文拼接分支。

补充修正不再依赖顶层字段或内容前缀：

1. 在受限深度内递归解析 `runId/state/phase/status`；
2. 每个 `chat` 事件只选取一个规范助手投影，优先保留完整累计正文，不把短 `delta` 建成独立气泡；
3. 即使传输层暂时缺少 `runId/state`，也使用当前会话的稳定临时投影 ID；
4. 所有非前缀阶段快照都执行替换，彻底禁止在 `chat` 投影中使用字符串相加。

补充回归以现场结构覆盖多层封装、累计正文与短 `delta` 并存、英文准备阶段切换到中文最终阶段三种情况。相关测试提升为 5 个文件、36 项通过，生产构建和 `git diff --check` 通过。

## 10. 2026-08-25 实时回复停滞现场证据

用户反馈 WebChat 发送消息后助手正文不实时刷新，部分会话在当前页面表现为空，切换页面或重新进入会话后才显示。目标会话为 `agent:main:main:dm:webchat-5e28576e4dc8494589f42925051b35ac`。

- Admin 工作区记录存在且为 `active`，所属账号角色和状态均正常；
- Gateway 会话索引和 JSONL transcript 均存在；
- transcript 依次存在用户消息、一个无正文的助手工具调用消息、工具结果和最终助手消息；
- 用户消息时间为 `2026-08-25T05:07:52.751Z`，最终助手消息已于 `2026-08-25T05:08:04.416Z` 持久化；
- 切换页面后能够显示，是因为重新进入会话重新调用 `chat.history`，不是模型未回复、权限拒绝、会话未创建或历史数据丢失。

根因是 8 月 24 日为解决多工具报告重复正文而建立的事件分流边界仍有两个现场漏项：

1. 生产 Gateway 的部分运行只通过精确会话范围内的 `agent` / `assistant` 流提供实时助手正文，没有同步发出可供当前页面投影的 `chat.*` 正文事件；前端只更新运行状态，因此当前页看不到正文。
2. 运行结束时只安排一次 `chat.history` 回拉。若它与页面已有的历史请求重叠，会复用并等待旧请求，不会再发起一次真正的新请求；若此时最终消息尚未完成持久化，最终刷新会被竞态吞掉。

## 17. 2026-08-25 历史收敛卡顿优化

默认正文分流正确后，用户现场反馈报告和工具型会话仍有间歇性卡顿。代码审查确认卡顿来自前端历史收敛调度，而不是模型生成速度或 237 的 `chat.history` 延迟：

- 发送阶段存在 1.4、4.2、10 秒三次兜底回拉；
- 终态阶段又存在 0.1、0.6、2、6 秒四次顺序回拉，极端情况下还有一次最终回拉；
- 流式 `chat.delta` 安静 200 ms 后也可能触发整段历史请求；
- 每次历史响应即使与当前内容完全相同，仍替换整个消息数组并更新同步时间；
- 大型工具结果虽然已从默认正文隐藏，消息数组替换仍会触发报告附件扫描、结构解析和 Vue 依赖重算。

提交 `3e77e50`（`perf(webchat): avoid redundant history convergence`）完成以下优化：

1. 流式非终态 `chat` 只更新当前实时气泡，不再回拉完整历史；
2. 发送兜底与终态收敛改为互斥策略，终态出现后立即取消发送兜底 timer；
3. 同一会话的重复终态事件复用一个收敛任务，不重新启动轮询窗口；
4. 权威历史出现完整的“用户回合末尾助手回复”后立即停止后续重试；
5. 历史消息逐字段和结构内容相同则保持原消息数组引用，不触发正文、附件和结构解析重绘；
6. 静默且无变化的历史检查不再更新 `lastSyncedAt`；
7. 新回合开始和会话切换统一取消旧 timer，避免上一回合的延迟任务影响当前页面。

专项回归新增三类约束：16,000 字工具结果的相同历史返回保持消息数组引用；非终态流式快照 1 秒内不产生历史请求；重复终态事件在首次权威历史成功后推进 20 秒也不再请求。WebChat store 专项 23 项通过，前端完整 Vitest 为 24 个文件、130 项全部通过；`vue-tsc` 和 Vite 生产构建通过，4652 个模块完成。
