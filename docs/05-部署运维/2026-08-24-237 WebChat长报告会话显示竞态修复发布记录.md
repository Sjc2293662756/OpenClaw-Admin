# 2026-08-24 237 WebChat 长报告会话显示竞态修复发布记录

## 1. 结论与范围

本批处理“生成最近七天综述报告”等长时间报告请求在聊天区不显示、刷新后回到“开始智能运维分析”的同类问题。问题属于 Admin WebChat 前端/BFF 会话消息显示链路，不是报告存储清理问题，也没有修改 GAIOP 后端、Gateway、OpenClaw、频道插件或报告数据。

覆盖范围：

- `useChatStore` 的会话历史回拉、实时事件识别和发送后兜底刷新；
- BFF 会话事件归属提取；
- ChatPage、Office AgentChatPanel 等复用 `useChatStore` 的 Admin 对话入口；
- 回归测试和生产构建。

## 2. 根因

报告请求与普通问答的执行形态不同：`chat.send` 可能在较长工具链完成后才返回，同时新会话路由切换会触发历史回拉。旧逻辑存在两个相互叠加的窗口：

1. 本地刚追加用户消息后，较早发出的 `chat.history` 可能返回空数组或不完整历史，旧赋值直接覆盖本地消息，页面因此被清空；
2. 报告/工具事件可能嵌套在超过原四层的 Gateway 信封中，前端和 BFF 提取不到精确 `sessionKey`，实时事件被丢弃；而发送期间没有提前启动历史兜底，实时事件丢失时没有恢复路径。

## 3. 修复内容

- 将前端和 BFF 的事件遍历边界从 4 层提高到 8 层，覆盖 `context`、`meta`、`request`、`response`、`envelope`、`body` 等信封，并在已知字段之外继续检查对象字段；仍要求精确会话键匹配，不放宽跨会话授权。
- 所有历史刷新统一合并本地待确认消息，空/部分历史不能覆盖刚发送的用户回合。
- 发送后立即启动 1.4 秒、4.2 秒和 10 秒的同会话历史刷新；发送 RPC 成功后保留第二轮短窗口，失败时清理定时器和本地占位消息。
- 为深层报告事件、路由历史竞态和长时间发送补充自动化回归测试。

## 8. 二次复现与补充修复（2026-08-24）

用户在新会话中观察到报告回复“显示一瞬间后消失”，复用旧会话时只剩用户请求。该现象说明第一批修复仍有一个遗漏窗口：实时报告回复已经进入前端消息列表，但 Gateway 随后的 `chat.history` 暂时只返回用户消息；原合并逻辑只保留 `web-*`/`local-*` 本地用户占位，因此把带 `messageId` 的助手报告误删。

补充修复将历史合并改为保留当前会话中尚未出现在历史响应里的所有实时消息，并按消息 ID、角色和正文去重；已存在的同 ID 消息按较长正文更新。这样既能保留报告回复直到 Gateway 历史落库，也不会放宽会话隔离。
