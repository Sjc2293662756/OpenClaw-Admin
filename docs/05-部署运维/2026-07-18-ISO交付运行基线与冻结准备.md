# GAIOP ISO 交付运行基线与冻结准备

| 项目 | 状态 |
|---|---|
| 日期 | 2026-07-18 |
| 状态 | 本地交付基线已定义；未部署、未冻结 ISO |

## 1. 目的与边界

本基线面向以已验证的 237 系统镜像为基础制作的 GAIOP ISO。它定义镜像内应有的运行组件、持久化边界、启动顺序、首次初始化和验收门槛；不授权网页安装系统软件，不修改 237、NAPM、rsyslog 或防火墙。

本期告警只覆盖 Syslog。SNMP Trap、任意服务器路径选择、客户网页上传报告和系统升级包安装均不属于首次 ISO 交付范围。

## 2. 镜像内组件与服务关系

```text
用户浏览器
  → HTTPS 443 / 反向代理
  → GAIOP-Admin（静态前端 + BFF）
  → 本机 GAIOP Gateway / Skills
       ├→ NAPM 数据源
       ├→ 频道长连接组件
       └→ 报告生成 Skill

NAPM Syslog → rsyslog → GAIOP Syslog 接收器（仅本机回环 HTTP）
                                  ↑
                           Admin BFF 读取正式告警接口
```

| 组件 | 交付责任 | 对外暴露 |
|---|---|---|
| 反向代理与前端 | 统一 HTTPS 入口、静态资源、`/api/*` 反代 | 仅 443 |
| GAIOP-Admin BFF | 登录、权限、审计、配置、报告与告警页面接口 | 仅回环/私网 |
| GAIOP Gateway / Skills | 对话、数据查询、报告生成、频道运行时 | 不直接公网暴露 |
| rsyslog | 接收 NAPM Syslog 并写受控日志 | 仅部署确定的 UDP 接收范围 |
| GAIOP Syslog 接收器 | 解析日志、持久化规范化告警、提供本机健康与告警接口 | 默认 `127.0.0.1:19090` |

ISO 内不提供“安装频道插件”“安装 rsyslog”或“升级系统软件”的网页按钮。系统依赖由镜像制作阶段固定，Admin 仅管理应用配置并展示运行状态。

## 3. 目录、数据与权限

建议将程序、配置、持久化数据和日志分离；实际根目录可按 ISO 制作规范调整，但角色不可混用。

| 类别 | 建议位置 | 备份 | 说明 |
|---|---|---|---|
| Admin 程序 | `/opt/gaiop/admin` | 否，可由发布包重建 | 前端构建产物与 BFF 代码 |
| GAIOP 程序/Skills | `/opt/gaiop/gateway` | 否，可由发布包重建 | Gateway 与后端 Skill 工作区 |
| 部署环境文件 | `/etc/gaiop/*.env` | 单独加密保管 | 仅服务账户可读，不入 Git |
| Admin SQLite | `/var/lib/gaiop/admin` | 是 | 用户、配置、审计、会话等 |
| 告警事件与接收器状态 | `/var/lib/gaiop/alerts` | 是 | 接收器启用状态和规范化事件 |
| 正式报告目录 | `/var/lib/gaiop/reports` | 是 | Admin 与报告 Skill 共用的 `GAIOP_REPORTS_DIR` |
| 运行时数据源桥接 | `/var/lib/gaiop/runtime` | 是，按敏感文件保管 | 可由授权配置重建，但可能含凭据 |
| 应用日志 | `/var/log/gaiop` | 按保留策略 | 不写入密钥或原始凭据 |
| rsyslog 输入日志 | ISO 受控日志目录 | 按告警保留策略 | 接收器只读读取，不向网页回显路径 |

服务使用独立非 root 账户。报告、SQLite、告警状态目录仅允许相应服务账户读写；接收器对 rsyslog 输入日志只授予必要的只读权限。

## 4. 启动顺序与自动恢复

1. 操作系统网络与时间同步可用。
2. rsyslog 启动并监听部署确定的 Syslog 输入。
3. GAIOP Gateway / Skills 启动。
4. GAIOP Syslog 接收器启动，恢复持久化的启用状态，并开始跟随受控 Syslog 日志。
5. GAIOP-Admin BFF 启动，连接本机 Gateway 与接收器。
6. 反向代理启动或重载，对外仅提供 HTTPS 入口。

所有长期服务必须由 systemd 管理，配置 `Restart=on-failure`（或等价策略）、启动依赖、最小文件权限和健康检查。接收器模板位于 GAIOP 后端仓库，ISO 制作时以实际程序根目录、服务账户和 Node 运行时替换其中的部署占位约定。

## 5. 环境变量与敏感配置

- Admin BFF 与报告 Skill 使用相同的 `GAIOP_REPORTS_DIR`；Gateway systemd 模板从部署侧 `GAIOP_OPENCLAW_ENTRY` 读取 OpenClaw 入口的绝对路径，避免将当前开发机路径固化进镜像仓库。
- Admin BFF 通过 `GAIOP_ALERT_RECEIVER_URL` 访问本机接收器；可选内部 Token 同时写入 BFF 与接收器的根权限环境文件，绝不回显给浏览器。
- 接收器的日志输入路径、事件目录和监听地址只由部署环境文件控制；浏览器只得到健康、启用状态、最近接收时间和错误码。
- 数据源加密密钥、频道凭据、Gateway 凭据、报告来源签名密钥和升级内部 Token 均在 ISO 安装/首次初始化时注入，不写入镜像仓库、页面、审计文本或日志。

旧 SSH 告警读取变量仅用于历史开发兼容，正式 ISO 不以它作为告警数据源。

## 6. 首次初始化流程

1. 部署人员注入初始管理员口令和加密密钥，启动全部服务。
2. 管理员登录后创建并测试 NAPM 数据源，再设为活动数据源。
3. 按需填写飞书、钉钉、企业微信频道凭据，逐频道保存并统一应用；频道私聊范围继续由各平台后台控制。
4. 在告警接入配置确认接收器健康、启用状态与最近接收时间；NAPM 发送端 Syslog 目标由实施人员在 NAPM 侧配置。
5. 在系统设置确认报告存储状态；不显示或编辑服务器绝对路径。
6. 创建一次无业务测试会话，并在具备结构化结果时生成一份测试报告后删除，用于验证权限、归档和审计。

## 7. 备份、恢复与升级边界

备份至少包含 Admin SQLite、告警事件/状态、正式报告目录、运行时数据源桥接和所需密钥材料；密钥与业务数据分开加密保管。恢复后必须重新检查服务账户权限、Gateway 连接、接收器健康和报告目录读写。

当前没有可验收的升级包，因此系统升级模块不作为 ISO 首次交付阻塞项。未来升级必须先执行备份、兼容性检查和任务进度记录，失败后能恢复到升级前程序与持久化数据。Gateway/频道插件不得在客户运行目录逐个原地安装或升级；必须按[频道插件依赖隔离与升级保护规划](2026-07-20-频道插件依赖隔离与升级保护规划.md)执行全插件兼容校验、版本化暂存、重启健康检查和失败自动回滚。

## 8. ISO 冻结前验收门槛

| 类别 | 必测结果 |
|---|---|
| 安装与重启 | 断电/重启后所有 systemd 服务按顺序恢复；不依赖开发隧道或人工启动窗口 |
| 网络与入口 | 仅 HTTPS 入口对用户开放；Gateway、BFF 和接收器不直接公网暴露 |
| 数据源与会话 | 管理员可配置并测试数据源；工作台会话创建、发送、历史、删除和归属隔离正常 |
| 告警 | rsyslog、接收器、BFF 正式接口和浏览器告警列表能接收一条新的 NAPM Syslog 事件 |
| 频道 | 已启用频道在重启后恢复，真实收发与平台侧访问范围符合预期 |
| 报告 | 结构化结果可生成 DOCX、审计 JSON 成对归档、Admin 可按权限下载和管理员删除 |
| 安全 | 普通用户无法读取他人报告或管理敏感配置；密钥不出现在接口、日志、审计或镜像仓库 |
| 恢复 | 备份恢复后 SQLite、报告、告警与关键服务均可用 |

## 9. 本地收口结果与后续部署输入

本次已完成本地基线文档、无敏感环境变量样例、Gateway/Admin/接收器 systemd 模板、Nginx 反向代理模板，以及只读部署预检脚本收口。尚未在 237 或任何服务器安装、重启、改防火墙、改 rsyslog 或写入配置。

模板位置：`GAIOP-Admin/deploy/iso/`（Admin、Nginx、预检）与 `GAIOP-latest/deploy/iso/`（Gateway）；接收器模板位于 `GAIOP-latest/skills/openclaw-napm-syslog-receiver/scripts/`。它们是 ISO 制作输入，不是可直接在任意机器执行的一键安装器。

`GAIOP-Admin/deploy/iso/README.md` 规定了三份环境文件和 service/Nginx 模板的受控目标位置；所有 `.env.example` 只提供变量名、非敏感默认值和目录契约，完成后的 `/etc/gaiop/*.env` 不得进入 Git 或被网页读取。

备份与恢复范围、恢复顺序和验收条件见 `GAIOP-Admin/deploy/iso/backup/README.md`。它不包含真实密钥、保留周期或备份目的地；这些必须在 ISO 冻结前由交付方与客户确认。

ISO 制作前仍需由部署负责人确认：实际 OS/Node 路径、最终服务账户、反向代理证书方案、数据保留周期、备份介质与密钥托管方式。确认后按第 8 节在准生产环境验收，再冻结 ISO。

`GAIOP-Admin/deploy/iso/release-manifest.example.yaml` 是 ISO 组装清单样例：它把两个仓库的交付组件、受控配置、首次启动生成项、持久化目录和明确排除项固定为机器可读的发布记录。ISO 制作流水线应填写实际发布编号与两端源码版本，但不得写入任何真实凭据、证书或客户数据。

`GAIOP-Admin/deploy/iso/release-freeze-record.example.yaml` 是每个候选 ISO 的冻结记录模板：在构建完成后记录不可变提交号、ISO 校验和、构建/测试证据、Linux 目标验证、持久化与密钥边界确认及验收签署。实际完成件应作为交付证据单独保管，不能替代部署审批，也不得包含客户数据或任何密钥。
