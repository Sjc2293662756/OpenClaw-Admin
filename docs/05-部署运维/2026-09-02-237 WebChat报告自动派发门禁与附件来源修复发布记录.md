# 2026-09-02 237 WebChat 报告自动派发门禁与附件来源修复发布记录

## 结论

本次故障根因不在 Admin 卡片组件。指定生产会话的报告文件和审计已经生成，报告也已登记为 `ready`，但报告审计和 `report_files` 的用户、会话、来源消息字段均为空；精确会话报告查询因此返回 0。Gateway 权威历史同时只有一条 assistant 完成消息，没有 WebChat 原生的 user、toolCall 和 toolResult 回合。

生产实际加载的 extension 插件已经定义“自动报告派发仅归企业微信所有”的判定函数，但 `reply_dispatch` 注册入口没有调用该门禁。WebChat 巡检请求因此进入自动派发路径，报告生成后直接写入 assistant 完成消息，截断原生工具回合并丢失正式报告来源。

## 最小修复

1. 在生产真实加载的 extension 插件 `reply_dispatch` 入口调用既有渠道判定；非企业微信返回 `undefined`，继续走 WebChat 原生回合。没有修改 Skill、OpenClaw 核心、报告生成服务、频道权限或存储体系。
2. Admin 报告映射继续优先使用唯一来源消息 ID。若该 ID 唯一命中 assistant 消息，只有消息本身具备明确报告完成信号时才直接把卡片放在其后；普通 assistant 消息、文件名、报告时间、最近消息和会话末尾均不能触发关联。
3. 对已损坏会话只使用同一插件审计 turnId 中的精确会话 scope、报告 ID、派发 sessionKey，以及 Gateway 原始 transcript 的持久 assistant 消息 ID。目标会话、报告和消息仅在本记录中保留短哈希 `e679df8c706f`、`12872a2620b6`、`76e7074da73c`。
4. 一次性来源修复先备份目标审计和 `wizard.db`，然后只补目标报告的属主、精确会话、持久完成消息 ID、WebChat 渠道和安全短预览。未修改 Gateway transcript，也未关联同日另一份无来源报告。
