# 237 会话身份字段只读核对记录

| 项目 | 内容 |
|---|---|
| 时间 | 2026-07-22（Asia/Hong_Kong） |
| 操作性质 | 经用户授权的只读会话身份字段核对 |
| 目标 | 确认飞书会话是否把平台用户姓名传给 Gateway，并核对历史 WebChat 会话能否从既有登记安全恢复账户归属 |
| 影响 | 未写入配置、数据库、插件、服务、网络或防火墙；未重启服务；未安装软件 |

## 1. 执行命令与脱敏原则

所有命令经受控 SSH 连接执行，连接凭据仅来自本机用户安全存储，未打印、复制或写入本记录。

1. `openclaw gateway --help` 与 `openclaw gateway call --help`：确认只读 RPC 查询入口。
2. `openclaw gateway call sessions.list --json --params '{}' --timeout 5000`：服务器端立即筛除非白名单字段，仅保留飞书会话的 `channel`、`lastChannel`、`peer`、`label`、`senderId`、`senderName`、`userId`、`userName`、`displayName`、`channelUserId`、`channelUserName`。不返回消息正文、认证信息或配置。
3. 尝试以只读方式查询 `/var/lib/gaiop/admin/wizard.db` 的 `workspace_sessions` 与本地用户关联：先探测 `sqlite3`，再尝试使用已部署 Admin 的原生 SQLite 依赖；两者均未完成查询，未作替代安装或任何写操作。

非交互式 SSH 的 `PATH` 不包含 `openclaw`；后续只读命令显式使用既有运行时路径 `/home/netinside/.npm-global/bin/openclaw`。这是环境路径现象，不是服务故障，也未修改服务器环境。

## 2. 结果

### 飞书身份字段

Gateway 返回的飞书会话中确认存在渠道标记和 `displayName`，其值为飞书 `ou_...` open_id（本记录不保留完整 ID）；未返回下列任一姓名字段：

- `senderName`
- `userName`
- `channelUserName`
- 独立的用户昵称字段

因此，当前 Admin 只能可靠显示“飞书用户（open_id）”，不能把 open_id 伪装成姓名，也不能按同名猜测匹配 GAIOP 本地账户。若产品需要显示飞书姓名，须另行设计并授权飞书插件/平台通讯录权限适配，并验证最小权限、缓存/保存边界和失败降级。

### 历史 WebChat 归属

本次未能从 237 SQLite 成功取得历史 `workspace_sessions` 对照证据：服务器未提供 `sqlite3` 命令行工具；第二种只读加载尝试也未完成。没有因此安装工具、复制数据库或读取配置。

在缺少唯一登记或审计证据时，历史 WebChat 会话不得自动归属给任何 GAIOP 账户。可以安全补充会话标题（首条用户消息的固定截断摘要），但不能据聊天内容猜测账户身份。

## 3. 回滚与后续

本次为纯只读操作，无服务器变更，无需回滚。

后续如需受控迁移历史 WebChat 归属，应先完成只读证据导出方案，只接受以下唯一且可审计的证据：BFF `workspace_sessions` 登记、已签名报告来源或明确包含会话键的 Admin 审计记录。任何不满足唯一性条件的记录保持“历史 webchat 用户未登记”。
