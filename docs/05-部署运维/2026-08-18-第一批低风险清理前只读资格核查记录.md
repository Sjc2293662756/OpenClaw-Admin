## 2. 核查实现基线

Admin 增加 `server/retention-qualification.js`，仅使用受控目录直接子级的 `lstat`、`readdir`、必要的信封元数据解析，以及可注入的只读关联查询。Upgrade 增加 `src/services/RetentionQualification.js`，仅查询升级任务/备份归属并对登记路径执行 `lstat`、`realpath`、直接子级 `readdir`。两个模块均：

- 不导入或调用任何清理器、删除 API、锁、审计或数据库迁移；
- 只读数据库连接使用 `readonly` 和 `query_only`，数据库不存在时失败关闭；
- 输出只包含策略版本、类别、计数、字节数、UTC 时间和稳定原因码，不返回完整路径、任务 ID、信封内容、报告正文或秘密；
- 资格分类固定为 `safe_candidate`、`protected`、`unknown_or_error`。

Admin 来源信封严格要求受控目录直接子级、SHA-256 文件名、v3 结构、文件大小、issuedAt 和 mtime 均严格早于 48 小时线，并通过只读报告/交付关联查询确认无活动引用。上传中转严格要求 UUID v4 `.zip`、直接子级、mtime 严格超过 24 小时，并必须由调用方提供已知无活动任务/锁的证明；缺少证明时归入 `unknown_or_error`。

Upgrade 包严格按数据库任务归属和文件身份判断；活动任务、未知包、异常时间和非终态均保护，`failed`/`rolled_back` 只有任务终态时间和文件 mtime 都严格超过 7 天才可列候选。staging 需要独立的无任务、无锁、无引用证明。回滚备份需要数据库归属、严格超过 90 天、超出每组件最近 5 个可用组、非共享物理目录及非空有效 manifest；无数据库归属的目录不扫描并继续保护。
