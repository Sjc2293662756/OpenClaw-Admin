# 2026-08-18 第一批低风险清理前只读资格核查记录

## 1. 范围与结论

本批只实现并验证无副作用的资格核查逻辑，未运行任何生产清理 one-shot，未启用或修改 timer，未删除、移动、压缩或修改生产文件，未写入生产数据库或审计。

生产核查未能完成：当前执行环境对 237 的只读 SSH 连接返回 `Permission denied (publickey,password)`。匿名 HTTPS 健康检查仍返回 `200`，但水位接口要求登录并返回 `401`。在不能安全读取生产目录、只读数据库和 systemd 状态的情况下，所有生产类别只能记为 `unknown_or_error`，不能把历史记录或用户提供的约数当作本批候选结果。

## 2. 核查实现基线

Admin 增加 `server/retention-qualification.js`，仅使用受控目录直接子级的 `lstat`、`readdir`、必要的信封元数据解析，以及可注入的只读关联查询。Upgrade 增加 `src/services/RetentionQualification.js`，仅查询升级任务/备份归属并对登记路径执行 `lstat`、`realpath`、直接子级 `readdir`。两个模块均：

- 不导入或调用任何清理器、删除 API、锁、审计或数据库迁移；
- 只读数据库连接使用 `readonly` 和 `query_only`，数据库不存在时失败关闭；
- 输出只包含策略版本、类别、计数、字节数、UTC 时间和稳定原因码，不返回完整路径、任务 ID、信封内容、报告正文或秘密；
- 资格分类固定为 `safe_candidate`、`protected`、`unknown_or_error`。

Admin 来源信封严格要求受控目录直接子级、SHA-256 文件名、v3 结构、文件大小、issuedAt 和 mtime 均严格早于 48 小时线，并通过只读报告/交付关联查询确认无活动引用。上传中转严格要求 UUID v4 `.zip`、直接子级、mtime 严格超过 24 小时，并必须由调用方提供已知无活动任务/锁的证明；缺少证明时归入 `unknown_or_error`。

Upgrade 包严格按数据库任务归属和文件身份判断；活动任务、未知包、异常时间和非终态均保护，`failed`/`rolled_back` 只有任务终态时间和文件 mtime 都严格超过 7 天才可列候选。staging 需要独立的无任务、无锁、无引用证明。回滚备份需要数据库归属、严格超过 90 天、超出每组件最近 5 个可用组、非共享物理目录及非空有效 manifest；无数据库归属的目录不扫描并继续保护。

- Admin 资格核查定向测试：`3/3` 通过，覆盖 48 小时严格边界、关联保护、符号链接/未知项、无副作用和 staging 活动证明。
- Upgrade 资格核查定向测试：`3/3` 通过，覆盖成功/终态包、7 天严格边界、staging 活动保护、回滚最近 5 组、共享/manifest/归属保护和无删除。
- 新增 JavaScript `node --check`：通过；`git diff --check`：通过。
- Admin/Upgrade 全仓测试和前端构建未在本机执行：隔离 worktree 没有依赖安装，且当前 Node 24 与项目 `better-sqlite3` 的既有 ABI 运行条件不匹配。该环境限制不改变生产数据。

## 5. 关闭态与下一步

本批没有运行清理器，因此没有产生删除、移动、压缩、审计、锁或清理状态写入。生产 timer、开关、水位事件和业务计数因 SSH 访问失败未重新读取；保持现状，不作启用判断。

在获得可审计的只读生产访问并完成一次前后快照之前，建议下一批仍保持全部清理 timer 关闭。访问恢复后，如确有合格且无引用的条目，优先单独评估 Admin 升级上传中转清理；若活动/锁证明或任何归属不完整，继续保持关闭，不扩大候选范围。

本批未部署 237，未读取或删除生产会话、附件、报告正文、日志或秘密，未修改后端、Gateway、Caddy、系统日志配置或生产开关。
