## 发布结论

- 已在 Admin 前端/BFF 范围内修复 WebChat 首回合回复错序、实时消息转持久历史不收敛，以及报告附件卡片因消息对象替换而闪退、漂移或重复的风险。

- 报告绑定只接受精确且唯一的来源消息 ID，或规范化后唯一的来源用户消息预览；同一用户回合还必须只有一条明确报告完成信号。已删除文件名、任意时间距离、单候选和会话末尾兜底。
- 下载继续复用既有受鉴权报告接口。基础、标准和管理员只能读取、下载本人报告；审计员保持全量只读；未授予报告管理、预览、删除、恢复区或他人报告能力。
- 未修改 OpenClaw/Gateway、GAIOP 后端、报告 Skill、频道插件、Caddy、系统日志或第二套报告下载/权限体系。

## 生产故障证据与根因

生产会话 `agent:main:main:dm:webchat-ce9eff6e30e74698902f54cfd2321c92` 的只读核查仅读取会话、消息和报告元数据，没有读取报告正文、凭据或报告内部路径。实时结果为：

- Admin 会话登记存在且为 active，归属于 active 管理员；当前用户具备该本人会话使用权限。
- Gateway 会话索引和 transcript 都存在且为普通文件；权威历史只有一条 `assistant + text` 消息，没有用户消息、工具过程或 thinking 消息。
- 助手文本是正常的最终回复，明确表示对象目录未命中且没有生成报告；该会话的 `report_files` 精确结果为 0，跨会话来源预览候选也为 0。
- 因此本次“发送后 Web 端看不到回复”不是报告登记、报告权限、下载、卡片组件或思考过程过滤造成的。上游在该会话只持久化了助手回合，是触发 Admin 展示缺陷的输入形状。

Admin 原合并顺序先放 Gateway 历史，再把当前浏览器的 `web-*` 用户占位追加到末尾，结果为 `assistant -> user`。页面自动滚动到底部后停在用户问题，回复位于问题上方，看起来像没有显示；历史收敛又只检查未合并的 Gateway 历史，其中找不到当前用户回合，因此临时状态长期不退出。

报告卡片是独立的第二个问题。原映射以 `Map<ChatMessage, ...>` 保存消息对象引用，而逐字展示和实时历史收敛会克隆或替换消息对象，渲染层随后查不到同一引用，卡片可能闪现后消失。原关联函数还包含文件名、30 分钟时间距离、全局单候选和任意跟随助手等推测规则，无法满足稳定归属要求。

“显示运行过程/只显示结果”的既有边界保持不变：完整 Gateway 历史仍在 store 中，默认 transcript 排除 tool、toolResult 和 thinking，只保留正式文字与图片；本次目标消息本身就是规范 `assistant + text`，不应被该投影过滤。

## 修复设计

### 实时与历史合并

1. 合并 pending 项时先用前后持久消息作为稳定锚点；若新会话权威历史暂时只有助手结果，当前本地用户占位固定插在第一条助手回复之前。
2. 用户内容比较会移除传输时间信封并规范化空白，使本地首问和 Gateway 持久消息可以稳定去重。
3. 历史收敛改为检查合并后的 transcript；一旦当前用户回合后已有完整助手回复，临时 stream 即退出，由权威历史接管。
4. 后续普通回合按既有锚点顺序合并，不会把已有报告卡片或临时回合搬到会话尾部。

### 报告关联与 transcript

1. 附件映射键改为稳定消息索引，不再依赖 Vue 渲染中的对象身份。
2. 来源消息 ID 必须在当前会话内唯一；ID 缺失或因 Gateway 持久化变化时，只允许规范化来源预览唯一命中用户消息。
3. 来源用户消息到下一条用户消息之间必须只有一条明确报告完成助手消息；歧义时不显示卡片，不猜最近消息，也不追加到会话末尾。
4. `reportId` 在请求合并和 transcript 投影两层去重；BFF 返回结果还会按当前 `sourceSessionId` 再过滤。
5. 会话切换使用同步清理，进入空白新对话或其他会话时不会短暂显示上一会话卡片。
6. Chat 工作台和 Office 面板共用 `message -> report -> later message` 的独立 sibling transcript 项顺序。

## 权限边界

- `/api/reports?sourceSessionId=...` 和 `/api/reports/:id/download` 继续使用既有认证、会话归属和报告属主规则。
- basic、standard、admin 可读取并下载自己的 ready 报告；非本人列表为空，按 ID 下载返回 404。
- auditor 保持既有全量只读能力，不获得删除或恢复操作。
- 本次没有因对话卡片放开报告管理器、预览、删除、恢复区、根路径或内部存储字段。
- 前端只消费安全报告元数据，卡片不显示服务器绝对路径、`MEDIA:` 路径或登记存储名。
