## 1. 变更原因与版本选择

237 原飞书插件 `@larksuite/openclaw-lark@2026.4.10` 能建立 WebSocket 长连接，但插件未在 manifest 中声明 `contracts.tools`。在 Gateway `2026.5.4` 上执行运行时检查时，会对插件注册的 39 个工具逐项报告：

```text
ERROR: plugin must declare contracts.tools before registering agent tools
```

升级前对 npm 发布包进行了只读核验：

- `2026.5.13` 是已核验版本中首个同时声明 `openclaw >=2026.5.4` 和 `contracts.tools` 的版本；
- 选择同一核心兼容线中更新的稳定版本 `2026.5.20`，不直接跳到与当前核心跨度更大的 `2026.7.x`；
- `2026.5.20` 声明 `openclaw >=2026.5.4`，manifest 中有 39 个工具契约；
- 静态检查发现该插件引用的 21 个 `openclaw/plugin-sdk/*` 路径全部由 Gateway `2026.5.4` 导出；
- 本次不迁移到 `@openclaw/feishu`，因为该路线需要同步评估并升级 Gateway 核心。

## 2. 变更前备份

变更前备份了旧飞书插件、Gateway 配置和版本信息，备份目录权限为 `700`，其中普通文件权限已收紧为仅属主可读写：

```text
~/.openclaw/backups/gaiop-feishu-plugin-before-20260720T034444Z
```

备份内容包括：

- `~/.openclaw/openclaw.json`；
- 插件索引刷新前的 `~/.openclaw/plugins/installs.json`；
- 配置清理前快照和升级过程产生的失败候选目录。

文档不记录频道 Secret、Gateway Token、服务器登录凭据或完整频道配置。

## 3. 首次安装、自动回滚与暴露的问题

首次使用 Gateway 官方插件安装命令：

```bash
openclaw plugins install --force --pin '@larksuite/openclaw-lark@2026.5.20'
```

安装器没有沿用旧的 `~/.openclaw/extensions/openclaw-lark` 路径，而是执行了以下操作：

```text
Installing @larksuite/openclaw-lark@2026.5.20 into ~/.openclaw/npm…
Linked peerDependency "openclaw" -> ~/.npm-global/lib/node_modules/openclaw
Removed previous plugin install directory: ~/.openclaw/extensions/openclaw-lark
Installed plugin: openclaw-lark
```

首次受控脚本仍按旧 `extensions` 路径检查版本，因此出现：

```text
Error: Cannot find module '~/.openclaw/extensions/openclaw-lark/package.json'
ROLLBACK=completed
```

该错误是本次升级脚本的路径假设不正确，不是新版飞书插件与 Gateway 不兼容。保护脚本随即恢复旧飞书目录和旧配置，并重启 Gateway。

回滚核查进一步发现：官方安装器会重建共享 `~/.openclaw/npm/node_modules` 依赖树，导致此前为企业微信和钉钉建立的插件级 `openclaw` peer 链接被清除。Gateway 重启后产生两条真实故障：

```text
wecom-openclaw-plugin failed to load ...
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'openclaw'

dingtalk-connector failed during register ...
Error: Cannot find module 'openclaw/plugin-sdk/core'
```

这说明即使只升级一个频道插件，也必须把共享 npm 树中的全部频道插件视为受影响组件，并在重启前重新校验其 peer 依赖。

## 4. 最终修复操作

在第二次安装后，对飞书版本、工具契约和三个频道的 peer 链接统一校验。三个插件分别保留自己的解析入口，并共同指向已冻结的全局 Gateway 核心：

```bash
CORE="$HOME/.npm-global/lib/node_modules/openclaw"

ln -s "$CORE" "$HOME/.openclaw/npm/node_modules/@larksuite/openclaw-lark/node_modules/openclaw"
ln -s "$CORE" "$HOME/.openclaw/npm/node_modules/@wecom/wecom-openclaw-plugin/node_modules/openclaw"
ln -s "$CORE" "$HOME/.openclaw/npm/node_modules/@dingtalk-real-ai/dingtalk-connector/node_modules/openclaw"
```

实际执行脚本在创建链接前检查目标目录和现有链接；错误目标被移动到受控备份目录，不会直接递归删除。上面的命令仅用于说明最终结构，不应脱离完整备份、版本检查和回滚事务单独执行。

旧飞书目录移走后，持久化插件索引仍保存旧来源，产生：

```text
duplicate plugin id detected
source: ~/.openclaw/extensions/openclaw-lark/index.js
winner: ~/.openclaw/npm/node_modules/@larksuite/openclaw-lark/index.js
```

同时，配置中还保留了已停用但未安装的 `plugins.entries.feishu`，它指向另一条官方插件路线，与当前 `openclaw-lark` 无关。经备份后使用 Gateway 自带命令清理：

```bash
openclaw config unset plugins.entries.feishu
openclaw plugins registry --refresh --json
openclaw gateway restart
```

索引刷新后，`openclaw-lark` 和 `feishu` 相关诊断数为 0。

## 6. 回滚方法

若真实飞书消息测试或后续观察出现问题，应停止继续变更并按以下事务回滚：

1. 备份当前失败候选和当前配置；
2. 移走 npm 目录中的 `@larksuite/openclaw-lark@2026.5.20`；
3. 从本次备份恢复 `openclaw-lark@2026.4.10` 和变更前配置；
4. 重新校验飞书、企业微信、钉钉各自的 `node_modules/openclaw` 链接；
5. 刷新插件索引并重启 Gateway；
6. 对三个插件执行 runtime inspect，对三个频道执行 status/probe，并检查启动日志。

不得只恢复飞书目录后立即结束；本次事件已经证明共享 npm 依赖树可能同时影响企业微信和钉钉。

## 7. 用户验收与后续要求

- 2026-07-20 用户已分别验证飞书、企业微信和钉钉真实消息，三个机器人均可正常回复；本次升级和依赖恢复的正向收发验收通过。
- 私聊/群聊覆盖、断网重连、会话隔离、凭据失效和升级失败回滚仍属于后续集中验收范围，本次单条正向消息验证不替代这些场景。
- ISO 冻结清单暂以 Gateway `2026.5.4`、飞书 `2026.5.20` 为候选组合，最终仍需在克隆/准生产环境做冷启动和失败回滚演练。
- 频道插件升级器必须在安装后统一重建或验证全部已交付插件的 peer 依赖，不能只检查本次目标插件。
- 升级器必须刷新持久化插件索引，并把旧来源、重复 ID、未加载插件、频道未恢复运行作为失败条件。
- 当前系统升级模块尚未实现上述频道级事务和自动回滚，不得据此开放客户自行升级频道插件。
