## 原因

Admin BFF 已把 Web 来源信息写入 `chat.send.metadata`，但 237 Gateway 的真实工具调用上下文不会继续携带该 metadata。报告工具因此无法获得可信来源信息，新生成报告仍显示“未记录”。

## 修复

- Admin 在发送消息时，把同一份签名来源信封原子写入专用运行目录。
- 文件名只使用会话标识的 SHA-256，不在文件名暴露会话内容。
- Gateway 按当前会话读取快照，并复用既有 HMAC 验签和 24 小时有效期校验。
- Admin 与 Gateway 通过各自受限的 systemd drop-in 使用同一签名密钥；密钥未输出、未写入 Git 或本文档。
- `netinside` 仅获得父目录的穿越权限和专用快照目录的读取权限。
- 报告文件管理继续保留来源渠道、来源用户、来源会话、来源数据源，移除“触发消息”列。

## 备份和回滚

发布前备份 Admin 构建、Admin 服务端来源模块、Gateway 根插件、报告输入契约、Admin/Gateway drop-in、相关环境文件和目录 ACL。切换、重启、健康检查或链路探针任一步失败时自动恢复。

发布前的若干校验尝试均因环境文件或目录权限检查失败而自动回滚，未形成生效版本。最终批次显式校正专用目录属主及最小 ACL 后完成。
