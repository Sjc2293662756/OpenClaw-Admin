# 237 历史 WebChat 会话标题迁移记录

| 项目 | 记录 |
|---|---|
| 日期 | 2026-07-23 |
| 目标 | 将本地已验证的历史 WebChat 首条提问标题回填到 237 Admin 持久化数据库 |
| 结果 | 成功完成，无需重启 Admin 服务 |

## 1. 原因与范围

2026-07-23 的 Admin 前端/BFF 发布包按持久化数据保护规则未携带 `wizard.db`。因此，本地开发库中已生成的历史 WebChat 展示标题不会随代码发布自动进入 237。

本次仅写入 Admin 数据库的 `historical_webchat_titles` 展示表；不改写 Gateway 历史、不改写会话归属、不猜测历史用户身份、不处理飞书、钉钉或企业微信会话，不修改用户、密码、数据源、报告、频道、网络或防火墙。

标题规则与已发布代码一致：读取每条历史 WebChat 会话的首条用户消息，去除多余空白后取前 24 个字符，超出部分加省略号。该规则不调用 AI，不增加 Token、模型费用或对话延迟。

## 2. 受控操作与备份

使用受控本地调用器 `ops\237\Invoke-237HistoricalWebChatTitleMigration.ps1` 建立 SSH 会话。凭据只由本机用户安全存储在进程内使用，未输出、复制或写入文档。

迁移前由 SQLite 的一致性备份能力在 237 创建快照，目录格式为：

`/var/backups/gaiop/admin-historical-title-<UTC迁移批次>/wizard.db.before-title-migration`

迁移过程先完成 Gateway 会话/历史读取和标题计算；只有读取阶段结束后才在单一 SQLite 事务中写入标题。若读取或事务发生未处理错误，不会留下部分标题写入。Admin BFF 保持在线，无服务重启。

## 3. 验证结果

迁移器只返回计数，未返回会话键、用户消息或数据库内容：

| 指标 | 结果 |
|---|---:|
| 可处理的历史 WebChat 会话 | 9 |
| 本次新增标题 | 8 |
| 原本已有标题 | 1 |
| 无首条用户消息 | 0 |
| 读取失败 | 0 |
| 当前历史标题总数 | 8 |

运行态核验：

- `gaiop-admin.service`：`active`；
- Admin 监听：仅 `127.0.0.1:3000`；
- 未改动 Gateway、Caddy/443、网络或公网路由。

## 4. 回滚方法

如需恢复迁移前状态，必须在维护窗口执行：停止 `gaiop-admin.service`、将当前 `wizard.db` 作为故障副本保留、恢复本次 SQLite 一致性快照并确保所有者为 `gaiop:gaiop`，再启动并验证服务、回环监听、健康接口和 Gateway 连接。

不得在 Admin 服务运行时直接覆盖数据库文件，也不得删除备份目录。恢复前先通过受控只读检查确认本次 UTC 迁移批次目录；恢复完成后记录恢复时间、验证结果和保留的故障副本位置。

## 5. 后续

新创建的 WebChat 会话会在首条成功发送后由 BFF 自动生成相同规则的固定标题；无需再次人工迁移。外部频道用户显示名和 `/new` 后的会话分段仍按既有产品设计记录，未在本次修改。
