# 2026-08-06 个人微信报告接入 GAIOP 报告管理器：适配记录

> 个人微信频道接入的实施见《2026-08-06-个人微信频道接入-实施与部署记录.md》，备份回滚见《2026-08-06-个人微信频道-备份回滚与运维记录.md》。

## 1. 背景

微信端生成的报告此前只落在 OpenClaw 侧（`~/.openclaw/workspace/skills/openclaw-napm-report/output/`），GAIOP 报告管理器（读 `wizard.db` 的 `report_files`/`report_deliveries` + `/var/lib/gaiop/reports`）看不到。

## 2. 机制（与企业微信一致）

GAIOP 报告归属侧车 `gaiop-report-attribution.service`（运行 `server/report-attribution-worker.js`）增量扫描 Gateway 会话存储：

1. 解析会话键得到渠道与对端用户；
2. 发现 `napm-report-export`/`exec` 工具产生的报告文件 + 审计 JSON；
3. 归档到报告根目录 `_sidecar/<hash>/...` 并写归因索引 `/var/lib/gaiop/report-attribution/index.json`；
4. GAIOP 报告管理器列表请求时执行 `syncGeneratedReports`，依据归因索引登记进 `report_files`。

## 3. 本次修改

- `server/report-attribution-worker.js`：
  - `EXTERNAL_CHANNELS` 增加 `openclaw-weixin`（及 `weixin` 别名）——此前微信会话因此被直接跳过；
  - `parseSessionIdentity` 支持带账号段的会话键（`agent:main:openclaw-weixin:<accountId>:direct:<peer>`）：优先取 `direct` 之后的段作为对端用户，兼容 per-channel-peer 与群聊键。
- 新增 `scripts/gateway237-report-attribution-weixin-deploy.cjs`：更新 237 侧工作器副本并重启服务。
