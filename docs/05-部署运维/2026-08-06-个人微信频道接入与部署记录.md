# 2026-08-06 个人微信频道接入、插件依赖处理、部署及验证记录

## 1. 背景与目标

在 GAIOP Admin“频道管理”页新增独立的“个人微信”模块，实现：

- 个人微信扫码添加账号（填写账户名称/备注 → 显示二维码 → 扫码 → 成功加入列表）；
- 支持第二个、第三个个人微信账号，账号级隔离、互不覆盖；
- 支持启用、停用、删除单个账号，删除只删除该账号自身授权/管理信息，不卸载插件；
- 首次安装插件与日常添加账号严格分离，账号增删不得触发 npm install / 插件升级 / 依赖重建；
- 微信 Token、登录凭据由 OpenClaw 个人微信插件原生保存，GAIOP 不复制、不明文保存、不返回；
- 不破坏现有企业微信、飞书、钉钉频道。

## 3. 个人微信整体架构

```
浏览器(公网 HTTPS 443 → Caddy → 127.0.0.1:3000)
  → GAIOP Admin BFF (gaiop 用户, 127.0.0.1:3000)
  → 个人微信适配器 (netinside 用户, 127.0.0.1:19091, systemd 用户服务)
  → @tencent-weixin/openclaw-weixin@2.4.4 插件 dist 函数
  → 腾讯 iLink Bot API (https://ilinkai.weixin.qq.com)
```

职责边界：

- Admin BFF：扫码会话编排、GAIOP 管理信息（SQLite）、审计、与 Gateway 状态合并；
- 适配器：调用插件自身导出的 `startWeixinLoginWithQr` / `waitForWeixinLogin` 驱动扫码；调用插件 `saveWeixinAccount` / `registerWeixinAccountId` / `clearStaleAccountsForUserId` / `triggerWeixinChannelReload` 完成凭据持久化；调用 `clearWeixinAccount` / `unregisterWeixinAccountId` 删除账号；通过 `openclaw config set / patch` 修改配置；
- 插件：保存每个账号的 Token / baseUrl / userId，原生管理登录状态；
- 适配器与 BFF 之间使用回环 HTTP + 随机 Token 头（`X-GAIOP-Weixin-Token`，仅 127.0.0.1 可达）。

## 4. 扫码登录流程

1. 管理员在“个人微信”模块点击“添加个人微信”，填写账户名称（必填）/ 备注（可选）；
2. BFF 创建会话并调用适配器 `/qr/start`；
3. 适配器启动一个 worker 子进程，worker 调用插件 `startWeixinLoginWithQr` 向腾讯 iLink 获取二维码 URL；
4. worker 输出 `qr_ready`，适配器记录 `qrcodeUrl`，BFF 用 `qrcode` 库生成二维码图片返回前端显示（二维码只走内存/响应，不进审计日志与普通日志）；
5. 前端轮询 `/api/channels/personal-wechat/onboarding/:id`，BFF 后台调用适配器 `/qr/wait` 长轮询；
6. 状态流转：等待扫码 → 已扫码 → （如需要）输入手机微信显示的验证码 → 连接成功/过期/失败/取消；
7. 连接成功后，worker 调用插件函数把 Token 等凭据写入插件自身存储，并触发频道配置刷新；适配器把 `accountId`（插件归一化后的文件安全 ID）与 `userId` 回传 BFF；
8. BFF 把账户名称、备注、accountId、userId 等管理信息写入 `personal_wechat_accounts` 表并记录审计。

验证码流程：worker 中插件的 `waitForWeixinLogin` 需要验证码时在 stdout 输出提示，适配器识别后向 BFF 返回 `verification_required`，BFF 让前端弹出验证码输入；管理员提交后 BFF 调适配器 `/qr/verify`，适配器把验证码写入 worker 的 stdin（插件原生读取），继续轮询。

## 5. 多账号保存与隔离

- 插件侧：每次扫码登录创建一个独立账号条目，索引在 `~/.openclaw/openclaw-weixin/accounts.json`，凭据在 `~/.openclaw/openclaw-weixin/accounts/<accountId>.json`（0600），多个账号并存；
- 插件原生约束：同一微信用户（userId）再次扫码绑定新 bot 时，插件会清理该 userId 之前绑定的旧账号（`clearStaleAccountsForUserId`，防止 contextToken 串线）。因此“多个个人微信账号”指多个 bot 条目；不同微信用户扫码可各自绑定，同一微信用户重复扫码会替换旧绑定。GAIOP 前端会展示该约束；
- 会话隔离：`openclaw.json` 新增 binding，只对 `openclaw-weixin` 频道设置 `session.dmScope=per-account-channel-peer`，会话键为 `agent:<agent>:openclaw-weixin:<accountId>:direct:<peer>`，不同微信账号与不同联系人之间上下文不串线；全局 `session.dmScope` 仍为 `per-channel-peer`，企业微信/飞书/钉钉的会话键格式不变；
- GAIOP 侧：`personal_wechat_accounts` 表按 accountId 独立记录，启停/删除只作用于单个 accountId。

## 8. openclaw.json 修改了什么

- `plugins.entries.openclaw-weixin.enabled = true`；
- `plugins.allow` 追加 `openclaw-weixin`；
- `channels.openclaw-weixin.enabled = true`；
- `bindings` 新增一条路由绑定：
  ```json
  {
    "type": "route",
    "agentId": "main",
    "match": { "channel": "openclaw-weixin", "accountId": "*" },
    "session": { "dmScope": "per-account-channel-peer" }
  }
  ```
  > 注意：`match.accountId` 必须显式为 `"*"`。OpenClaw 2026.5.4 会把缺省 accountId 的 binding 归一化为“只匹配 default 账号”，导致真实账号不命中、会话键仍为 per-channel-peer；加 `"*"` 后才是频道通配，多个微信账号各自获得独立会话键 `agent:main:openclaw-weixin:<accountId>:direct:<peer>`。
- 后续每新增账号：`channels.openclaw-weixin.accounts.<accountId>.enabled = true`（由适配器在扫码成功后写入）；停用写 `false`；删除时移除该账号配置项；
- `channels.openclaw-weixin.replyProgressMessages = false`：关闭微信插件的工具进度气泡（频道级，对全部个人微信账号生效），减少工具调用期间的刷屏；最终答复仍为流式发送。
- 未改动全局 `session.dmScope`（保持 `per-channel-peer`）。

## 11.1 微信报告接入 GAIOP 报告管理器

### 背景

微信端生成的报告此前只落在 OpenClaw 侧（`~/.openclaw/workspace/skills/openclaw-napm-report/output/`），GAIOP 报告管理器（读取 `wizard.db` 的 `report_files`/`report_deliveries` 表 + `/var/lib/gaiop/reports` 报告根目录）看不到。

### 机制（与企业微信一致）

GAIOP 的报告归属侧车（`gaiop-report-attribution.service`，运行 `server/report-attribution-worker.js`）增量扫描 Gateway 会话存储（`~/.openclaw/agents/main/sessions/`）：

1. 解析会话键得到渠道与对端用户（如 `agent:main:wecom:direct:yangs` → wecom/yangs）；
2. 发现 `napm-report-export`/`exec` 工具产生的报告文件 + 审计 JSON；
3. 归档到报告根目录（`_sidecar/<hash>/...`）并写入 `/var/lib/gaiop/report-attribution/index.json`；
4. GAIOP 报告管理器在列表请求时执行 `syncGeneratedReports`，依据归因索引把报告登记进 `report_files`。

### 本次修改

- `server/report-attribution-worker.js`：
  - `EXTERNAL_CHANNELS` 增加 `openclaw-weixin`（及 `weixin` 别名）——此前微信会话因此被直接跳过；
  - `parseSessionIdentity` 支持带账号段的会话键（`agent:main:openclaw-weixin:<accountId>:direct:<peer>`）：优先取 `direct` 之后的段作为对端用户，兼容原有 per-channel-peer 与群聊键。
- 新增 `scripts/gateway237-report-attribution-weixin-deploy.cjs` 与配套部署步骤：更新 237 侧工作器副本并重启服务。

### 验证结果（237 实时）

- 归因索引新增微信条目：`_sidecar/c10c5d97d9b4ba8f59a4/napm_全局综述报告_20260806_141356.docx/.json`，`sourceChannel=openclaw-weixin`、`sourceUserId=channel:openclaw-weixin:<对端微信ID>`、`evidence=exec_tool_result`；
- 用 DB 临时副本执行报告管理器同步逻辑：`report_files` 新增该报告行（`source_channel=openclaw-weixin`、`status=ready`、文件存在），与企微 `_sidecar` 登记路径一致；
- 报告管理器打开后会自然完成线上登记；后续微信端生成报告会由侧车自动归因登记。

### 已知记录（不做处理）

- 微信平台对高频 bot 消息的投递侧限制迹象（服务端全部发送成功、客户端只显示部分），插件对单段流式回复有 1 秒/条节流，多轮工具叙述不走该节流；平台确切上限未证实，留待后续有需要再查。
- 模型在工具调用间隙输出的过程叙述会以多条消息发出，无频道级配置可单独关闭；暂不处理。
- NAPM 报告生成偶发失败属后端（NAPM/报告技能）问题，由他人修复，不在本记录范围。
