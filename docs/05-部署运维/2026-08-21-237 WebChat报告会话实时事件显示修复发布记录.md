# 2026-08-21 237 WebChat 报告会话实时事件显示修复发布记录

## 1. 结论与范围

本批修复 WebChat 请求报告或工具链响应后，主聊天区仍停留在“开始智能运维分析”、刷新后刚创建会话从左侧历史消失的问题。修复范围仅为 GAIOP Admin 前端聊天状态与回归测试：

- 递归识别 Gateway 事件中的 `sessionKey`，兼容 `payload`、`data`、`event`、`session`、`message`、`result` 包装层；
- 递归提取嵌套实时消息，并继续执行当前会话精确隔离；
- 发送成功后按 1.4 秒、4.2 秒和 10 秒执行同会话历史兜底刷新；
- 静默历史响应为空或不完整时保留本地刚发送消息，避免短暂响应清空页面；
- ChatPage、Office AgentChatPanel 等复用 `useChatStore` 的入口统一生效。

本批没有修改 GAIOP 后端、Gateway、OpenClaw、频道插件、报告目录、数据库结构、Caddy、Syslog 或公网监听范围。

## 2. 根因与修复边界

前端 `src/stores/chat.ts` 原先只读取事件顶层或一层 `session` 中的会话键。报告/工具链事件的消息和会话键常位于更深的 `payload.message.sessionKey` 等结构中，事件因此在 `shouldApplyRealtimeEvent` 前被丢弃。发送后已有 `schedulePostSendRefreshes`，但原实现没有调用它，导致实时事件丢失时没有可靠的历史回拉兜底。

BFF 已有同字段集合的递归事件键提取逻辑，本批没有重复修改 BFF，也没有放宽会话归属授权或实时跨会话隔离。
