# 237 报告存储只读核对记录

| 属性 | 内容 |

| 操作类型 | 经用户授权的 237 只读检查 |
| 范围 | 报告正式目录、服务账户访问、文件计数与两端目录配置状态 |
| 服务器变更 | 无：未创建、删除、移动或修改文件，未修改配置，未重启服务 |

## 1. 现象

Admin 的“报告文件管理”页面为空。需要确认正式报告存储是否已经部署、是否有可显示的报告实体与审计 JSON，以及 Admin/当前 Gateway 是否已完成同一目录联调。

## 2. 诊断命令与保护措施

通过本机用户安全存储中的受控连接信息运行固定检查器：

```powershell
./Invoke-237ReportStorageInspect.ps1
```

远端固定脚本只执行以下只读项目：

- 判断 `/var/lib/gaiop/reports` 是否存在；
- 判断 `gaiop` 服务账户是否具备该目录读写权限；
- 统计目录内文件、审计 JSON 与可配对报告的数量，不读取或输出文件名、报告内容或审计内容；
- 仅返回 Admin 与 ISO Gateway 环境文件中 `GAIOP_REPORTS_DIR` 的状态标记（缺失、预期目录、自定义或不可读），不输出环境变量值、Token、密码或签名密钥；
- 读取 Admin、ISO Gateway 和现有 OpenClaw Gateway 服务状态，不重启服务。

## 4. 结论

页面为空的直接原因是正式共享目录当前没有任何可被 Admin 安全登记的报告实体/审计 JSON 对。

目录本身已创建，Admin 也已配置到该目录，因此不是页面权限或目录不存在的问题。当前实际运行的是旧 `openclaw-gateway.service`，而不是 ISO `gaiop-gateway.service`；ISO Gateway 的报告目录配置尚未处于可核验状态。现有 Gateway/报告 Skill 尚未确认写入正式共享目录，故报告生成链与 Admin 扫描链没有完成 237 联调。

进一步确认后，根因完整如下：

1. 当前运行中的报告 Skill 是旧版实现，仅向其旧输出目录写入；该目录已积累 167 组报告实体/审计 JSON。
2. 当前运行中的报告 Skill 不包含 `GAIOP_REPORTS_DIR` 正式共享目录契约，无法仅通过新增环境变量切换输出位置。
3. 现有 Gateway 服务账户 `netinside` 无法访问 `/var/lib/gaiop/reports`；即使升级 Skill，也必须先以最小权限方式授予其必要目录访问权。
4. Admin 为避免把不受控文件或旧目录内容直接暴露给浏览器，只扫描正式共享目录，因此不会自动显示旧目录的 167 组历史报告。

> 此记录描述发布前的只读事实。后续适配已完成，详见[报告 Skill 正式目录适配发布记录](2026-07-22-237报告Skill正式目录适配发布记录.md)。

这与[报告目录分层与双端适配规划](../04-公共设计/2026-07-15-报告目录分层与双端适配规划.md)中“本地双端契约完成、待部署联调”的状态一致。

## 5. 后续与回滚

后续应先在不影响现有报告生成的前提下，完成以下受控变更：备份旧报告 Skill 和旧输出目录、部署已具备正式目录契约的报告 Skill、以最小权限授予现有 Gateway 服务账户对正式目录的访问、配置该服务使用正式目录，并以一份无客户敏感数据的测试报告验证生成、扫描、下载和用户隔离。是否迁移旧目录的 167 组报告，需单独决定；不应未经确认直接复制或让 Admin 扫描旧目录。

该步骤涉及 Gateway 代码、目录权限、运行时配置与服务重启，实施前必须说明备份与回滚方案并获得写操作授权。

本次为纯只读检查，没有服务器变更，因此无需回滚。
