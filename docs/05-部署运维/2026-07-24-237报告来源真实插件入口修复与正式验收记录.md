## 1. 最终根因

此前只发布并校验了：

`/home/netinside/.openclaw/workspace/napm-openclaw-plugin.remote.js`

但 237 的 OpenClaw 插件信息明确显示真实入口为：

`/home/netinside/.openclaw/extensions/napm-openclaw-plugin/index.mjs`

该入口优先加载同目录 `index.js`；文件不存在时，加载同目录
`napm-openclaw-plugin.remote.js`。237 实际存在的是后者，因此真实运行时一直
加载 extension 目录中的旧副本，workspace 文件即使哈希正确也不会让实际
`napm-report-export` 生效。

这就是多次出现“发布脚本成功、workspace 哈希一致、隔离探针通过，但真实报告
仍为未记录”的直接原因。此前发布门禁直接 `require()` workspace 文件，也绕过了
真实 `index.mjs` 入口，属于验收设计缺陷。

## 2. 最终修复

- 发布器同时备份并替换 workspace 副本和 extension 真实加载副本。
- 切换阶段强制校验两个副本 SHA-256 完全一致。
- 发布后的快照验证、历史真实 toolCallId 验证和报告端到端验证，全部改为从
  extension 的 `index.mjs` 导入插件。
- 报告执行通过唯一 `toolCallId` 反查 OpenClaw 会话 JSONL 和 sessionKey，再读取
  Admin 签名 sidecar 快照；不使用“最近会话”或模糊匹配。
- 对 JSONL 异步刷盘增加短时精确重试，仍要求 toolCallId 唯一匹配。
- 保留哈希化解析审计，只记录参数类型、长度、短哈希、耗时和是否命中，不记录
  原始 toolCallId、用户正文或敏感配置。
