## 1. 问题与边界

此前 BFF 在 `chat.send` 中附加 `metadata.gaiopReportProvenance`，同时又把同一来源信封持久化为服务器端签名快照。237 当前 Gateway 对自定义参数存在版本兼容限制，这会使 Admin 客户端进入 `agent` 兼容回退；报告来源等管理信息也没有必要进入 Gateway/模型的数据面。

本次按“BFF 优先、GAIOP 其次、OpenClaw 核心不改”的原则拆分：

1. 用户消息仍通过 Gateway 标准对话参数发送，模型只接收正常对话内容。
2. BFF 在服务器端按会话保存签名来源快照。
3. GAIOP 报告插件按会话或工具调用标识读取并验签快照。
4. 会话归属、会话标题和报告文件管理继续使用各自现有存储，不互相借用模型上下文。
5. `agent` 回退保留为 RPC 版本兼容保障，但不再承担报告来源传输。
