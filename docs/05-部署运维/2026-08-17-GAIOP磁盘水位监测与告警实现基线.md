## 1. 本批结论

第八批只实现磁盘水位监测与告警。独立 one-shot 每次只读取配置、对显式受管根目录执行 `stat`/`statfs`，并把当前状态和受限事件写入 Admin SQLite。systemd timer 每 5 分钟触发一次并设置 `Persistent=true`。

本批没有清理入口，不调用 Admin、Upgrade、数据包、日志、报告、会话或备份清理器，不删除、移动、压缩或修改业务文件，不修改留存期限，也不阻断业务写入。80% 清理到 70%、90% 应急清理到 80% 和高容量新写入保护均不在本分支。

## 3. 文件系统识别与占用率

1. 对每个登记根目录调用一次 `stat(path, { bigint: true })`，确认它是目录并取得 `stat.dev`。
2. 对同一路径调用一次 `statfs(path, { bigint: true })`。不调用 `readdir`、`opendir`、`find` 或任何目录遍历能力。
3. 对 `stat.dev` 加命名空间后做 SHA-256 截断，生成 `fs-<20位十六进制>` 脱敏标识。同一 `stat.dev` 的多个标签合并为一个文件系统状态，不同设备分别判断。
4. 首次 `stat` 失败、尚不能取得真实设备时，使用由受管标签生成的 `fs-unresolved-*` 稳定脱敏占位标识；后续取得设备或已有可信映射后恢复真实文件系统标识。占位标识不表示已识别出设备。
5. 同一设备的多次 `statfs` 采样如因采样时刻产生细小差异，使用率最高的一次作为该设备当前值。

占用率采用 Linux `df -P` 口径：

```text
used = blocks - bfree
denominator = used + bavail
usage = used / denominator
```

阈值判断使用 BigInt 原始值交叉乘法，不使用展示用小数或四舍五入值：

| 原始占用率 | 状态 |
|---|---|
| `<75%` | `normal` |
| `>=75%` 且 `<80%` | `warning` |
| `>=80%` 且 `<90%` | `cleanup_required` |
| `>=90%` | `emergency` |

`cleanup_required` 和 `emergency` 在本批只是状态名称和告警级别，不会触发清理。

## 4. 状态、事件与单实例

Admin `wizard.db` 增加四张专用表：

| 表 | 内容 |
|---|---|
| `storage_watermark_status` | 每个受管文件系统的当前状态、检查时间、原因码和受管标签 |
| `storage_watermark_targets` | 脱敏目标与最近识别文件系统的映射，用于失败检查和进程重启后的连续性 |
| `storage_watermark_events` | 受限告警事件 |
| `storage_watermark_lock` | 单行 PID/随机令牌租约 |

状态和上次事件时间保存在 SQLite，因此服务进程重启后仍能去重。事件仅在以下情况写入：

- 首次出现异常或检测失败；
- 状态上升；
- 状态下降或恢复为正常；
- 检测失败与检测恢复之间切换；
- 同一异常持续达到提醒周期，默认 360 分钟。

每 5 分钟重复得到相同状态不会重复写事件。事件表和 API 的单条事件严格只含：策略版本、文件系统稳定标识、当前状态、使用率、阈值、UTC 时间、检测成功标志和原因码；不含完整路径、文件列表、业务内容、秘密或任意环境值。本批不清理事件表。

one-shot 通过 SQLite 事务取得单行租约。已有 PID 仍存活时第二实例直接退出；异常退出留下的死 PID 租约可由下一实例接管。释放时必须同时匹配随机令牌，旧实例不能释放新实例的租约。该机制不创建或删除锁文件。

## 5. 检测失败

| 场景 | 原因码 | 行为 |
|---|---|---|
| 根目录不存在 | `managed_root_not_found` | 当前状态 `unknown`，不回退扫描 |
| 权限不足 | `managed_root_permission_denied` | 当前状态 `unknown`，不修改目录权限 |
| 其他 `stat` 失败 | `managed_root_stat_failed` | 当前状态 `unknown` |
| `statfs` 失败或返回非法值 | `managed_root_statfs_failed` | 该文件系统状态 `unknown` |

根目录检查失败不会读取同级或上级目录，也不会把整机最高值代替具体文件系统状态。

| 调用方 | 结果 |
|---|---|

接口返回策略版本、固定阈值、当前状态和最近 20 条受限事件，响应为 `private, no-store`，不返回配置路径或文件信息。系统监视器页面增加一个紧凑提示区，按受管标签展示当前状态和使用率，并提示最近事件时间；没有新建容量看板、历史趋势、预测、模拟清理或操作按钮。

## 7. systemd 边界

- `gaiop-storage-watermark-monitor.service` 为 Node `Type=oneshot`，以 `gaiop` 账户运行。
- `gaiop-storage-watermark-monitor.timer` 使用 `OnCalendar=*-*-* *:0/5:00 UTC`、`Persistent=true`。
- unit 启用 `ProtectSystem=strict`、`NoNewPrivileges=true`、`PrivateTmp=true`、`PrivateDevices=true`、空 capability 集和 `AF_UNIX` 限制。
- unit 不加载包含其他服务秘密的 `admin.env`，只在 unit 内声明 Admin 数据目录、受管根配置位置和提醒周期三个非敏感参数。
- one-shot 要求现有 `wizard.db` 存在，只执行水位专用幂等迁移，不新建空数据库，也不触发其他 Admin 业务表迁移。
- 受管根只读暴露；唯一写路径为 `/var/lib/gaiop/admin`，用于现有 Admin SQLite 状态和事件。
- 配置根不可达时应报告失败。部署人员不得为了消除告警而扩大监测根、开放公网、修改 OpenClaw 核心或增加文件读取权限。
