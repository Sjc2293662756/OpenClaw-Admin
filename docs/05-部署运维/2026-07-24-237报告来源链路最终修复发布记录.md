## 完整根因

真实链路存在两个连续问题：

1. `gaiop-admin.service` 的基础 `EnvironmentFile=/etc/gaiop/admin.env` 覆盖了来源模块 drop-in 中的 `Environment=`。配置文件看似使用同一密钥，但 Admin 与 Gateway 实际进程密钥不同，真实快照无法验签。
2. 密钥对齐后，Gateway 能读取并验签快照，但 `napm-report-export` 把 `buildReportInputForExport()` 的包装结果整体传给报告 Skill，没有传入其中真正的 `reportInput`。报告归一化层因此丢失顶层来源字段。

此前的探针只覆盖“写快照—直接读取—验签”，单元测试只检查构造结果，没有实际执行报告工具并读取最终审计 JSON，因此未发现第二个问题。

## 最终修复

- Admin 使用排序在基础环境文件之后的专用 `/etc/gaiop/admin-report-provenance.env`。
- 发布时保留 Admin 当前实际密钥并同步给 Gateway，不再无条件轮换密钥。
- 发布硬性检查 Admin/Gateway 两个实际进程的密钥相等。
- 发布硬性检查最新真实 Web 快照能被 Gateway 当前进程验签。
- `napm-report-export` 向报告 Skill 传递 `prepared.reportInput`，保留来源渠道、用户、会话和数据源。
- 工具仍通过会话工厂捕获真实 `sessionKey`，不使用“最新快照”或模糊匹配。
