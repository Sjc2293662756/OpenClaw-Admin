# 审计信息接口

| 属性 | 内容 |
|---|---|
| 创建日期 | 2026-07-11 |
| 最后更新 | 2026-07-15 |
| 代码依据 | `server/routes/audit.js` |

## 1. 查询

```http
GET /api/audit-logs?limit=100
Authorization: Bearer <token>
```

权限：`auditor`、`admin`。`limit` 为 1–200，默认 100，超范围自动收敛。

响应：

```json
{
  "ok": true,
  "logs": [
    {
      "id": "...",
      "username": "admin",
      "role": "admin",
      "action": "保存会话设置",
      "target": "系统设置",
      "detail": "不含敏感值的摘要",
      "createdAt": 1780000000000
    }
  ]
}
```

## 2. 权限与错误

未登录返回 401；基础或标准用户返回 `403 PERMISSION_DENIED`。当前接口没有按用户过滤、搜索、时间范围、游标或导出。

## 3. 写入规则

审计写入由服务端业务路由调用 `recordAudit`，浏览器没有通用“新增审计”接口，防止伪造。敏感字段、请求 Token、密码和完整配置不得进入 `detail`。

## 4. 后续契约

若增加筛选和分页，应采用服务端查询并定义稳定游标；若增加导出，应限制管理员/审计角色、记录导出审计并避免导出敏感详情。失败操作审计与请求 ID 尚需统一设计。
