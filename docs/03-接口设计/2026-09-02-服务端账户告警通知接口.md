# 服务端账户告警通知接口

> 状态：隔离工作树已实现并通过本地自动化验证；未提交、未推送、未部署。

所有接口只使用认证上下文中的 `req.user.id`，不接受客户端指定账户。接口统一经过 `alerts.notifications` 最新有效模块权限校验；已清空通知默认不可读。

## 1. 分页查询

`GET /api/alerts/notifications`

查询参数：

| 参数 | 规则 |
|---|---|
| `limit` | 默认 30，范围 1-100 |
| `beforeId` | 可选，正安全整数；读取更早的通知 |
| `readState` | `all` 或 `unread` |
| `severity` | 可选：`轻微/重大/紧急` |
| `offlineAfterId`、`throughId` | 必须成对出现，用于离线汇总事件区间 |

响应包含 `notifications`、全局及筛选后 `counts`，以及 `page.hasMore/nextBeforeId/snapshotThroughId`。通知项包含 `notificationId`、Receiver generation/sequence、`action`、安全 `payload`、`read/readAt`、`createdOffline`、`createdAt/receivedAt`。

## 2. 已读与清空

| 方法与路径 | 语义 |
|---|---|
| `PUT /api/alerts/notifications/:eventId/read` | 当前账户单条已读，幂等 |
| `POST /api/alerts/notifications/read` | 按严重级别、读取状态和可选离线区间批量已读 |
| `DELETE /api/alerts/notifications/:eventId` | 当前账户单条清空 |
| `POST /api/alerts/notifications/clear` | 按同一筛选范围批量清空 |

批量请求体使用 `severity`、`readState`，可选成对的 `offlineAfterId/throughId`。单条 ID 不属于当前账户或已经清空时返回 404，不泄露其他账户是否存在同一共享事件。

成功修改后，BFF 在现有 `/api/events` 上仅向该账户发送：

```json
{ "type": "alertNotificationStateChanged", "action": "read" }
```

或 `action: "clear"`。该事件只是当前页失效提示，不携带其他账户或告警正文。

## 3. 离线汇总

`POST /api/alerts/notifications/offline-summary/claim`

服务端生成领取令牌，客户端不提交账户或水位。存在新离线通知时返回：

```json
{
  "ok": true,
  "summary": {
    "claimToken": "opaque-token",
    "afterId": 0,
    "throughId": 25,
    "total": 4,
    "bySeverity": { "轻微": 2, "重大": 1, "紧急": 1 },
    "expiresAt": 1788321600000
  },
  "claimInProgress": false,
  "retryAfter": null
}
```

其他标签页持有有效租约或没有新离线通知时，`summary` 为 `null`；前者同时返回 `claimInProgress=true`。

`POST /api/alerts/notifications/offline-summary/confirm`

请求体只含 `{ "claimToken": "opaque-token" }`。令牌匹配时推进确认水位并清空租约；不会把任何通知设为已读。令牌已失效或已被其他页面处理时返回 409。

## 4. 现有 SSE 调整

仍只使用 Bearer 认证的 `GET /api/events`：

- `type: alert` 增加 `notificationId` 和 `receiverGeneration`，只发给事件发生时在线且具备权限/设置的收件账户。
- `triggered/recovered` 保持业务动作；不向浏览器发送 compensation 动作。
- `type: alertNotificationStateChanged` 用于同账户跨浏览器刷新已读和清空。
- 线上的 `{type: connected, clientId}` 在浏览器内部映射为 `sseConnected`，与 `gatewayState` 分离，用于领取离线汇总。
- `alertStreamState` 保留现有连接、断档和 Receiver reset 诊断语义。

## 5. 主要错误码

| HTTP | 错误码 | 含义 |
|---:|---|---|
| 400 | `ALERT_NOTIFICATION_FILTER_INVALID` | 严重级别或读取状态无效 |
| 400 | `ALERT_NOTIFICATION_CURSOR_INVALID` | 分页 ID 无效 |
| 400 | `ALERT_NOTIFICATION_RANGE_INVALID` | 离线区间缺失、倒置或无效 |
| 400 | `ALERT_NOTIFICATION_ID_INVALID` | 单条通知 ID 无效 |
| 404 | `ALERT_NOTIFICATION_NOT_FOUND` | 当前账户不可见、已清空或不存在 |
| 409 | `ALERT_NOTIFICATION_SUMMARY_CLAIM_LOST` | 汇总令牌已失效或已处理 |
| 403 | `MODULE_ACCESS_DENIED` | 当前有效模块权限不允许告警通知 |
| 500 | `ALERT_NOTIFICATION_*_FAILED` | 对应持久化或读取失败 |

数据库写入失败时不会推进 Receiver 游标；REST 已读/清空写入成功而 SSE 失效通知发送失败时，以 SQLite 状态为准，下一次读取恢复一致。
