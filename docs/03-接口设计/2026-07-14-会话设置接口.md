## 1. 管理 REST

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/system-settings/sessions` | 登录 | 当前策略、清理状态和脱敏运行时回显 |
| PUT | `/api/system-settings/sessions` | 管理员 | BFF 同步 Gateway 后保存策略与审计 |

请求：

```json
{
  "loginSessionHours": 24,
  "idleTimeoutMinutes": 0,
  "agentContextIdleMinutes": 30,
  "historyRetentionDays": 180
}
```

范围分别为 1–168、0–1440、1–1440、0–3650 的整数。非法返回 `400 SESSION_SETTINGS_INVALID`。响应包含 `settings`、`historyCleanupStatus: "planned"` 和 `runtime`。`runtime` 只返回会话策略的生效/差异/不可达状态及必要数值，不返回完整 Gateway 配置、Token、密码或路径。

## 2. Gateway 上下文配置

管理员保存页面只请求 Admin BFF。BFF 在服务器侧通过 Gateway `config.get`/`config.patch` 写入：

```json
{
  "session": {
    "dmScope": "per-channel-peer",
    "reset": { "mode": "idle", "idleMinutes": 30 },
    "resetByChannel": {
      "webchat": { "mode": "idle", "idleMinutes": 5256000 }
    }
  }
}
```

外部渠道使用用户配置的 `agentContextIdleMinutes`。Web 工作台的 10 年窗口目前仅为待验目标策略，避免在未完成 Gateway 路由适配前误称已生效。浏览器不发送来源路由字段；BFF 先使用当前 Gateway 的 `raw + baseHash` 形式；仅在 Gateway 明确提示旧版只接受 `patches` 时回退兼容形式。

## 3. 一致性和失败处理

Gateway 与 SQLite 不是分布式原子事务。BFF 先 Gateway、后 SQLite：Gateway 同步失败时不会写 SQLite，并返回 `503 GATEWAY_UNAVAILABLE` 或 `502 GATEWAY_SESSION_SYNC_FAILED`；SQLite 写入失败时 Gateway 可能已更新，返回 `500 SESSION_SETTINGS_PERSIST_FAILED` 并提示管理员重试。成功操作写入管理审计。

GAIOP 插件/Skills 当前不直接消费这组 Gateway `session.*` 配置；运行时消费者是 Gateway 本身。GAIOP 后端已完成此边界核对，无需为该设置新增插件代码。

## 4. 生效范围

- 登录会话时长影响新登录。
- 管理端空闲超时按后续受认证请求检查。
- 外部渠道上下文在超过空闲时间后的下一条消息重置，不删除历史记录。
- 历史保留只保存策略，不执行删除。

## 5. 2026-07-15 Web 渠道策略的兼容状态

`resetByChannel.webchat` 可以作为管理员保存的目标策略保留，但当前浏览器对话不会传递 `originatingChannel`。原因是已验证当前 Gateway 拒绝单独的来源字段，并要求完整的来源/目的地路由组合。为确保普通对话可用，Admin 已移除浏览器侧不完整字段。

所以“Web 工作台使用 10 年窗口”目前是**待真实 Gateway 联调验证的策略**，而不是已运行生效的事实；外部渠道的通用空闲策略不受这次修正影响。后续应由 BFF 的 Gateway 参数适配层生成完整路由字段，并同时验证版本兼容、`config.patch` 回显和真实发送结果，再更新本接口文档和系统设置状态。
